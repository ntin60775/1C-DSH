## Контур 1С (dsh-1c-contour)

Владелец секции — плагин `dsh-1c-contour`; правится контуром, не руками.
Гейты и MCP-серверы приходят с хост-плагином контура в cwd проекта (любой пресет сессии).

### Поверхность Unica

Чтение — `unica.search / view / diff / resolve / docs / check`; правка —
`unica.apply` (план → запись); сборка/ИБ — `unica.run {op, args: {…},
dryRun: true|false}` (аргументы операции — ВЛОЖЕННО в `args`; `dryRun`
обязателен явно, платформенные операции возвращают async-задачу — результат
через `unica.task.result`, waitMs ≤ 7000); источник
контракта — словарь `unica.run {}` (вызов без op) и словари узлов (`view`).
Канон правки: `search → view → apply (план) → apply (запись) → check/diff`.
План — вызов `{at, ops}`; ответ несёт `executionToken`, запись — вызов с
одним токеном (`dryRun` и `ifRev` на уровне `apply` не принимаются,
`ifRev` — в аргументах операции `code.replace`).
Локализованные значения (`synonym`, `toolTip`, заголовки форм и СКД) —
одна строка НСтр `ru = '…'; en = '…'`; плейн-строка отвергается. Для
`code.replace` передавай `ifRev` из `rev` узла `Body`: запись по
устаревшему чтению отвергается кодом `conflict`.

Ответы приходят страницами: пока в ответе есть `cursor`, читай следующую
страницу тем же вызовом; коллекции `view` листаются также `from` (префикс
имени) и `offset`. Буквальный `search` без `role` идёт до последнего
совпадения, первая страница несёт `data.totals`. Пакет путей —
`unica.resolve {paths: [...]}`, длинное свойство — `<узел>.Props.<имя>`.
`upload`, `apply`, `reset` как операции `unica.run` недоступны
(#1246): загрузка `.cf`/`.cfe` — через ibcmd, не через раннер: скилл
`1c-ibcmd-delivery` (цикл поставки, глаголы, заимствования).
`source.reexport` переэкспортирует набор в формат линии (2.20/2.21/2.22,
линия платформы должна стоять) и возвращает `warnings` о снятых настройках
выбора; `push delete:<имя>` удаляет расширение
вместе с данными — вопрос человеку.

Часть операций спрашивает человека (перезапись базы, удаление расширения,
снятие с поддержки, запись в базу другой копии). Клиент без elicitation
подтверждения исполняет как прежде, а выбор остаётся отказом с вопросом:
не повторяй такой вызов вслепую, вынеси решение оператору. Аргументы
`humanConfirmation`/`humanReexport` ставит только сервер — вызов модели
с ними отказывается. Исполняемые `pull`/`push`/`make` запирают правки
исходников на время операции: параллельный `apply` получит отказ. Пока
`ibsrv` держит файловую базу, `push`/`extensions` через ibcmd на ней
отказывают: раннер узнаёт `ibsrv` с `--db-path`/`--database-path` и отвечает
`infobase_busy`, а публикацию контура (`--data`/`--config`) не опознаёт —
отказ приходит от ibcmd. Публикацию гасить на время сборки.
Интерактивный `launch` показывает окна лицензии и входа человеку
(`/DisableStartupDialogs` не передаётся).

### Инварианты

1. Исходники 1С (`src/{cf,cfe}`) правятся только через Unica — прямая
   правка блокируется гейтом. Внешние epf/erf: каркас — файлами по
   `epf-init`/`erf-init` (спека внешней обработки юники — источник канона
   разметки), правка узлов — `unica.apply`, сборка/разбор — `epf-load`/
   `epf-dump` (`1c-ibcmd-delivery`).
   Разовый обход: `.dsh/1c/unica-gate-escalations.txt`.
2. Мутации (`unica.apply`, `unica.run {op: push|upload|apply|reset}`) —
   только после непустой сверки с `unica.docs`. Критерий списка —
   авторское решение о платформенной семантике; операции с opaque-данными
   (`infobase.restore/dump/create`) сверки не требуют — их несут замок ИБ
   и подтверждение человека. Пустой ответ не считается;
   источники — `platform-help` и `development-standard`,
   `configuration-documentation` отвечает `unsupported_source`;
   принятая задача (`status: working`) — не сверка, пока не дочитана через
   `unica.task.result`; поиск без совпадений — тоже не сверка.
3. Инварианты пересборки — правила проекта (`.dsh/1c/contour.json` →
   `unica.rebuild_rules`); включаются сверкой на стенде. Ключ `builder`
   в v8project.yaml не используется (per-operation `providers`).
4. Адрес инфобазы и креды — только из `v8project.local.yaml`
   (`infobases.origin.connection`); база читается только из local-слоя,
   поддерживает только `origin`. Ключи `basePath`, `execution_timeout`,
   `partialLoadThreshold` и верхнеуровневый `connection` отвергаются;
   полная загрузка — `push full: true`. Назначение всех полей и регламент
   переезда — навык `1c-project-layout`, `references/v8project.md`.
5. Прод-контур по умолчанию (fail-closed): изменяющие инструменты
   тест-контура блокируются; признак `test` — файл `.dsh/1c/contour` со
   словом test. Ключ `contour:` в `v8project.local.yaml` не писать:
   раннер отвергает незнакомый верхнеуровневый ключ local-слоя.
6. Третий идентичный повтор упавшей команды заблокирован.
7. Артефакты сборки и прогона кладутся только в
   `build/out/{cf,cfe,epf,erf,reports,tmp}`: товарные (`cf`…`erf`) зеркалят
   `src`, отчёты прогонов — в `reports`, служебное сборки — в `tmp` со
   сносом в том же заходе; имя артефакта `<Имя>_<ГГГГ-ММ-ДД>[.<суффикс>].<ext>`
   без перезаписи, вне шести каталогов в `build/out` не создаётся.
   Исключение — junit и артефакты контурного e2e-прогона: они живут в
   `test-results/`, контракт workflow (канон раскладки — навык
   `1c-project-layout`).
8. Носитель состояния инфраструктуры — `.agents/contour-status.md`
   (в git). На старте сессии прочитай его: список пробелов непуст →
   в первом ответе владельцу назови пробелы и предложи план починки
   (ритуал + решение владельца); молча не обходи. Перед починкой сверь
   актуальность `python3 "$DSH_1C_ROOT/scripts/doctor.py" .`; после
   починки обнови носитель (пустой список = инфраструктура чиста).
   Пробел, найденный в работе, запиши в тот же носитель.

### Качество кода

Форма BSL — пак `1c-bsl-code-style` (приоритет над стандартами и
стат-анализом). Любая BSL-правка: guard `bsl-style-gate` при правке;
носитель — guard `bsl-module-gate`: в общих модулях и модулях менеджера
директивы компиляции и переменные модуля на верхнем уровне запрещены
(контекст исполнения задаётся флагами или типом носителя), код из модуля
формы переносится телами, без директив; права ролей на перечисления,
общие картинки и общие макеты не назначаются никогда.
Формальный ревью `1c-bsl-review-standards` (требования пака + стандарты
v8std, конфликт — приоритет пака) — перед отчётом о завершении и перед
push; пропуск любого — отклонение от процедуры. Вызовы БСП — скилл `bsp`
(БСП 3.1.11). Обзор — скилл `1c-contour` (глаголы Unica, приоритеты
качества).

### Тесты и данные

Тесты агент пишет сам, все на pytest: юниты в `tests/unit/`, e2e в
`tests/e2e/`. Юниты покрывают уровень логики 1С (execute_code);
e2e — поведение: write-first, readback, ЖР-сверка (инструмент `workflow`
со скриптами `1c-e2e-author` / `1c-e2e-run` из репозитория контура) на
уровнях API (HTTP) и GUI (testpilot). Данные — MCP `1c-db`; на
второй-третьей базе — инстанс (`.dsh/1c/db-instances.yaml`, MCP
`1c-db-<имя>`, скилл `1c-db-data`).
