# Контракт пака стандартов — API v1

Пак — каталог с манифестом `manifest.json` и необязательными файлами
стандартов и чек-листов ролей; конфиги гейтов живут в манифесте как
данные. Пак — проектный бандл: живёт в `.agents/packs/<имя>/` проекта,
ставится каналом `--pack` установщика ядра. Пак несёт только данные:
стандарты, чек-листы и конфиги гейтов; код, хуки и права на гейты
остаются у ядра, конфиги гейтов исполняет ядро в окружении проекта.

## Раскладка

```text
<имя пака>/
  manifest.json
  standards/<файлы>.md
  roles/<файлы>.md
```

Имя каталога совпадает с `name` манифеста. Файлы стандартов и
чек-листов — markdown; конфиги гейтов живут в манифесте как данные.

## Манифест

JSON-объект, ключи только из таблицы:

| ключ | тип | обязательность | правило |
|---|---|---|---|
| `name` | строка | обязательный | `[a-z0-9]+(-[a-z0-9]+)*`, совпадает с именем каталога |
| `type` | строка | обязательный | `team` (команда) или `stack` (стек) |
| `version` | строка | обязательный | `MAJOR.MINOR.PATCH`, цифры |
| `standards` | список строк | необязательный | относительные пути `.md` внутри пака, файлы существуют |
| `roles` | список объектов | необязательный | роли ревью, см. ниже |
| `gates` | список объектов | необязательный | механические гейты, см. ниже |

Неизвестный ключ — отказ. Пути — только относительные, без `..` и
абсолютных путей, цель внутри пака существует.

### Роль

Объект с ключами `name` и `checklist`, других ключей нет:

- `name` — `reviewer-<kontur>-<aspect>`: минимум два сегмента после
  `reviewer`, сегменты `[a-z0-9]+`, разделитель `-`;
- `checklist` — относительный путь `.md` внутри пака, файл существует.

Чек-лист роли — markdown: область (что читать) и пункты проверки.
Роль регистрируется в реестре ролей проекта бутстрап-вопросом init;
модель роли назначает реестр, не пак.

### Гейт

Объект с ключами `name`, `command` и необязательным `expect_exit`,
других ключей нет:

- `name` — непустая строка, имя гейта в отчётах;
- `command` — непустой список строк: команда и аргументы, исполняется
  ядром в окружении проекта без shell-интерпретации;
- `expect_exit` — целое число, ожидаемый код выхода (по умолчанию 0).

Гейт — декларация команды в манифесте, не исполняемый файл пака;
команду исполняет ядро с правами проекта. Валидатор проверяет схему,
не семантику команды; пак — доверенный источник команды. Доверие паку —
названное решение оператора, не свойство данных.

## Стандарты

Файл стандартов — markdown: правила с носителями. Правило без
носителя и проверки — заявка, не норма; где правило проверяемо,
чек-лист роли или гейт называет проверку. Приоритет норм: канон >
стандарты проекта > пак команды > пак стека > базовый документ;
неразрешимый конфликт — вопрос оператору. Объём уровней: стандарты
проекта — документы проекта, кроме базового документа; паки — отдельный
класс по источнику (команда или стек); базовый документ — нижний
уровень.

## Валидация

Валидатор бандла — [`../validate_pack.py`](../validate_pack.py), только
stdlib:

```sh
python3 <бандл pack>/validate_pack.py <каталог пака>
```

- валиден — exit 0, строка `✓ пак <имя> (<тип>, <версия>) валиден`;
- нарушение — именованный отказ: причина в stderr, exit 2, stdout
  пустой;
- usage-ошибки (нет аргумента, каталог не существует, файл вместо
  каталога) — тот же контур отказа.

Эталонный минимальный пак —
[`manifest.json`](../reference-pack/manifest.json) в `../reference-pack/`:
манифест, один стандарт, одна роль, один гейт; валидатор на нём
проходит. Мутации эталона (убранное поле, чужой тип, неизвестный ключ,
висящая ссылка) обязаны краснеть.

## Исполнение гейтов

Гейты исполняет ядро в окружении проекта: исполнитель бандла —
[`../run_gates.py`](../run_gates.py), только stdlib:

```sh
python3 <бандл pack>/run_gates.py <корень проекта>
```

- паков нет — строка `паков нет: гейтов 0`, exit 0;
- все гейты зелёные — строка на гейт `✓ гейт <пак>/<имя>: exit <код>`,
  вывод команды и итог `✓ гейты паков: N пройдено`, exit 0;
- красный гейт — строка на гейт: расхождение exit —
  `✗ гейт <пак>/<имя>: ожидался exit <ожидаемый>, получен <полученный>`;
  ошибка запуска или таймаут — `✗ гейт <пак>/<имя>: <причина>`;
  вывод команды, итог `гейты паков: K из N красные`, exit 1;
- невалидный манифест или usage-ошибка — именованный отказ: причина в
  stderr, exit 2, stdout пустой.

Манифесты всех паков валидируются до исполнения гейтов: отказ не
смешивается с выводом гейтов и не оставляет побочных эффектов исполненных
команд. Команда гейта исполняется как список аргументов без
shell-интерпретации, рабочий каталог — корень проекта; код выхода
сверяется с `expect_exit` (по умолчанию 0). Ошибка запуска команды
(отсутствие файла, нет права исполнения) — красный гейт с названной
причиной, не краш исполнителя. Вывод команды — недоверенный текст:
управляющие символы заменяются видимым маркером `·`. Гейт дольше таймаута
(600 секунд) — красный с названной причиной. Вывод исполнителя читает
исполнитель шага: зелёная сводка без прочитанного вывода — не
доказательство.
