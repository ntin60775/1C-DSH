# Установка контура 1С на DSH

Процедура ставит контур с нуля: bundle `dsh-1c-contour` в профиль DSH,
пресет `1c`, Юнику на машину, проект на раскладку `.dsh/1c`. Проверка
установки — `scripts/doctor.py`. Устройство гейтов — [dsh-gates.md](dsh-gates.md),
канал Юники — [UNICA.md](UNICA.md).

## Требования

| Что | Версия / место |
|---|---|
| DSH | 0.2.2-rc.2+ — нужен фикс `mcp-client` (ntin60775/deepseek-harness#1): без него MCP-инструменты отдают пустой результат |
| Node.js + pnpm | сборка плагина TS → `lib/` |
| python3 | stdlib, без зависимостей: doctor, мигратор, стартеры, замки |
| Unica | 0.15.0-rc.5, бинарники глобально на машину — [UNICA.md](UNICA.md) |
| Профиль DSH | `$DSH_HOME/profiles/<профиль>` (по умолчанию `~/.dsh`) |

Одна версия контура на машину; пина версии на проект нет. Реестр проектов
фиксирует версию контура на момент перевода, а не пин.

## 1. Сборка

```bash
pnpm install
pnpm build        # tsc → lib/
```

В поставку бандла идут `lib/`, `skills/`, `commands/`, `scripts/`,
`workflows/`, `templates/`, `cordis.patch.yml`, локаль и иконка
(`files` в `package.json`); тесты и процессные скиллы `.agents/` в поставку
не входят.

## 2. Bundle в профиль

Плагин-менеджер DSH (`install_bundle`) ставит пакет двумя путями:

- **локальный path** — абсолютный путь к этому репо (рабочий путь
  разработки: пересборка `lib/` и перезапуск хоста подхватывают правки);
- **git+https** — `git+https://github.com/ntin60775/1C-DSH.git`
  (поставка с тега/ветки).

Патч бандла `cordis.patch.yml` добавляет в профиль две строки:

| Строка | Что |
|---|---|
| `1c-contour` | плагин `dsh-1c-contour`: гейты на событиях хоста |
| `preset-1c` | пресет «Контур 1С» (id `1c`): полная копия `standard` плюс строка доставки `dsh-1c-contour/preset` |

Пресет — копия `standard` из `@deepseek-ai/dsh-web-app` **0.2.2-rc.1**,
а не ссылка: в DSH пресет задаёт полный список детей, наследования нет.
Обновление web-app сверяется с апстримным `presets/standard.patch.yml`:
в rc.2 апстрим добавил `tool-office` — в копии контура его нет (граница
копии; переносить или нет — решение при обновлении).

## 3. Пресет

Выбрать пресет `1c` в ростере сессии. Для новых сессий по умолчанию —
`selectedDefault: 1c` в строке `agent-preset-registry` patch-документа
профиля (home-слой применяется последним); doctor сверяет умолчание.

Доставка контура включается только в сессии 1С-проекта: пресет резолвит
проект от каталога сессии и поднимает скиллы контура, скиллы Юники, команды
`/1c-*` и MCP-записи `unica`, `1c-testpilot`, `1c-db` (+ инстансы), `1c-kd`.
Вне 1С-проекта и без пресета контура не видно; гейты молчат.

## 4. Юника

Бинарники — одна глобальная установка на машину
(`~/.local/share/unica/runtimes`, лаунчер `~/.local/bin/unica`); скиллы
Юники ставит `scripts/install_unica_skills.py`, MCP-запись `unica`
поднимает пресет на уровне проекта. Процедура и версии — [UNICA.md](UNICA.md).
Проверка: `unica --help` печатает `unica 0.15.0-rc.5`.

## 5. Проект

Проектные входы живут в `.dsh/1c/`: `contour.json`, `contour.local.json`,
`db-instances.yaml`, маркер контура `contour`, эскалации гейтов,
`mcp-write-allow.txt`, `testpilot/profiles.yaml`, `standards-exceptions.yaml`,
путь чекера стиля. Порядок чтения: `.dsh/1c` → `.dsh` → `.zcode/1c` →
`.zcode` (одна таблица `LAYOUT_DIRS` в `src/paths.ts`).

Перевод с ZCode-раскладки — мигратор (ручной, по одному проекту; пакетного
нет):

```bash
python3 scripts/migrate_from_zcode.py <проект> --check    # 0/1/2: переведён / не переведён / расхождение
python3 scripts/migrate_from_zcode.py <проект> --dry-run  # план
python3 scripts/migrate_from_zcode.py <проект>            # перенос
```

Мигратор пишет запись в реестр проектов
`${DSH_1C_STATE_DIR:-~/.dsh/state/1c}/projects.json` (путь, раскладка,
версия контура, дата первого перевода). Новый проект — `/1c-bootstrap`
(профили, contour.json, секция AGENTS.md). Нечитаемый вход канона
останавливает поиск (fail-closed): сломанный маркер не превращает прод
в тест, сломанный allowlist не разрешает мутацию.

## 6. Проверка

```bash
python3 scripts/doctor.py <проект>            # семь разделов, exit 0/1
python3 scripts/doctor.py <проект> --json     # машинный verdict по разделам
python3 scripts/doctor.py <проект> --no-ping  # не поднимать MCP
python3 scripts/doctor.py <проект> --profile NAME
```

Разделы: `bundle` (пакет в профиле, строки патча, сборка `lib/`), `preset`
(объявлен и выбран по умолчанию), `skills` (15 контурных, 4 команды, скиллы
Юники, затенения), `mcp` (записи и живость), `layout` (канон и legacy),
`project` (`v8project.yaml`, платформа, топология, `build/out`, движок
стиля, реестр), `state` (корень состояния, замки, журнал гейтов).
Выход 0 — FAIL нет (WARN допустимы); у каждого раздела `--json` несёт
`status` и машинный `code` (`bundle.missing`, `mcp.db-down`, …).

## 7. Перезапуск хоста

Плагин и пресет подхватываются новым поколением модулей: «Остановка» →
«Запуск». «Запуск» при работающем сервере только открывает вкладку;
«Пересборка» пересобирает артефакты без перезапуска. Живая сессия держит
загруженное поколение модуля — правки плагина без перезапуска не видны.

## Контроль установки

Сессия с пресетом `1c` в 1С-проекте: 15 скиллов контура, скиллы Юники,
4 команды, MCP-инструменты `mcp__unica__*`, `mcp__1c-testpilot__*`,
`mcp__1c-db__*`, `mcp__1c-kd__*` (имена нормализованы DSH под контракт
function-name, хвост `<12hex>` гейты отбрасывают). Контроли: сессия без
пресета в том же проекте — инструментов контура нет; пресет `1c` вне
1С-проекта — ни скиллов контура, ни Юники, ни MCP.

## Состояние

Корень состояния — `${DSH_1C_STATE_DIR:-~/.dsh/state/1c}`: замки инфобаз,
состояние гейтов, журнал `logs/rule-audit.jsonl`, реестр `projects.json`.
Legacy `ZCODE_1C_STATE_DIR` ещё читается; снятие legacy-путей — Т10 юнита
`dsh-contour`.
