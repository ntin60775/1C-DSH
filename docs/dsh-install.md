# Установка контура 1С на DSH

Процедура ставит контур с нуля: bundle `dsh-1c-contour` в профиль DSH
(одна хост-строка: гейты и доставка), Юнику на машину, проект на раскладку
`.dsh/1c`. Проверка
установки — `scripts/doctor.py`. Устройство гейтов — [dsh-gates.md](dsh-gates.md),
канал Юники — [UNICA.md](UNICA.md).

## Требования

| Что | Версия / место |
|---|---|
| DSH | 0.2.2-rc.2+ — нужен фикс `mcp-client` (ntin60775/deepseek-harness#1): без него MCP-инструменты отдают пустой результат |
| Node.js + pnpm | сборка плагина TS → `lib/` |
| python3 | stdlib, без зависимостей: doctor, стартеры, замки |
| Unica | версии — `unica.yaml` контура, бинарники глобально на машину — [UNICA.md](UNICA.md) |
| Тест-контур | `1c-testpilot` и прокси `1c-mcp-toolkit` на машину: `scripts/install_testpilot.sh`, `scripts/install_1c_mcp_proxy.sh` (пины в скриптах); профили и инстансы — входы проекта, шаг 5 |
| Профиль DSH | `$DSH_HOME/profiles/<профиль>` (по умолчанию `~/.dsh`) |

Одна версия контура на машину; пина версии на проект нет. Реестр проектов
фиксирует версию контура на момент перевода, а не пин.

## 1. Сборка

```bash
pnpm install
pnpm build        # tsc → lib/
```

В поставку бандла идут `lib/`, `skills/`, `commands/`, `scripts/`,
`workflows/`, `templates/`, `cordis.patch.yml`, `unica.yaml`, локаль и
иконка (`files` в `package.json`); тесты и процессные скиллы `.agents/` в
поставку не входят.

## 2. Bundle в профиль

Плагин-менеджер DSH (`install_bundle`) ставит пакет двумя путями:

- **локальный path** — абсолютный путь к этому репо (рабочий путь
  разработки: пересборка `lib/` и перезапуск хоста подхватывают правки);
- **git+https** — `git+https://github.com/ntin60775/1C-DSH.git`
  (поставка с тега/ветки).

Патч бандла `cordis.patch.yml` добавляет в профиль одну строку:

| Строка | Что |
|---|---|
| `1c-contour` | плагин `dsh-1c-contour`: гейты на событиях хоста И доставка контура в область агента |

Отдельного пресета контура нет. Доставка — аддитив к любому пресету сессии:
копия `standard` не нужна, а значит не дрейфует при обновлении web-app
(пресет `1c` до 0.2.0 был копией `standard` из rc.1 и терял новые
инструменты апстрима — `tool-office`, `tool-cordis`). Умолчание профиля
(`selectedDefault`) контур не трогает.

## 3. Доставка

Правило одно: каталог сессии резолвится в проект 1С → хост-плагин монтирует
в область агента скиллы контура, вендоренные паки проекта
(`.dsh/1c/skills`: стиль, bsp), скиллы Юники, команды `/1c-*` и MCP-записи
`unica`, `1c-testpilot`, `1c-db` (+ инстансы), `1c-kd`. Пресет сессии при
этом не важен: standard, ролевой, любой другой — доставка приходит поверх
его композиции. Вне 1С-проекта контура не видно.

Монтирование — на создании агента и перед первым шагом (`agent/pre-step`,
раньше публикатора каталога скиллов); недоступная станция старт сессии не
держит. Выбор пресета в ростере доставку не включает и не выключает.

Гейты — тот же хост-плагин, от пресета не зависят: в 1С-проекте они
действуют на любую сессию, привязка к роли — позже. Ролевые пресеты
(стековые и любые будущие) получают доставку тем же хостом: строки
доставки и швы `presetIds` в их декларациях не нужны.

## 4. Юника

Бинарники — одна глобальная установка на машину
(`~/.local/share/unica/runtimes`, лаунчер `~/.local/bin/unica`); ставит и
обновляет `scripts/install_unica_runtime.py` (версии — `unica.yaml`),
скиллы Юники ставит `scripts/install_unica_skills.py`, MCP-запись `unica`
поднимает доставка контура на уровне проекта. Процедура — [UNICA.md](UNICA.md).
Проверка: `unica --help` печатает версию из `unica.yaml`.

## 5. Проект

Состояние инфраструктуры для любого агента — `.agents/contour-status.md`
(в git): версия контура, вердикт doctor, именованные пробелы владельца;
правило чтения — инвариант 8 секции 1C CONTOUR AGENTS.md (прочитать на
старте, непустой список вынести владельцу, после починки обновить).
Пишет деплой/бутстрап при приёмке, агент проекта — после починки;
формат и правила — навык `1c-project-bootstrap`, раздел «Носитель
состояния инфраструктуры». Машино-локальный реестр актов и followups
(`.dsh/1c/registry.local.json`) остаётся вне git и носитель не дублирует.

Проектные входы живут в `.dsh/1c/`: `contour.json`, `contour.local.json`,
`db-instances.yaml`, маркер контура `contour`, эскалации гейтов,
`mcp-write-allow.txt`, `testpilot/profiles.yaml`, `standards-exceptions.yaml`,
путь чекера стиля. Вендоренные паки (стиль, bsp) — в `.dsh/1c/skills/`,
порядок вендоринга — навык `1c-project-bootstrap`. Порядок чтения: `.dsh/1c` → `.dsh` (одна таблица
`LAYOUT_DIRS` в `src/paths.ts`); legacy-раскладки ZCode сняты в Т10
после перевода парка.

Перевод проекта с прежнего канала (ZCode/omp) включает уборку legacy-слоя:
`.zcode/` и `.omp/` удаляются, проектные runbook'и, обёртки и `.gitignore`
переводятся на `.dsh/1c` и `$DSH_1C_ROOT/scripts`, проектный
`registry.local.json` получает append-запись о переводе. Порядок — навык `1c-project-bootstrap`,
раздел «Перевод с legacy-каналов»; проверка — doctor, пустой
`git ls-files .zcode .omp` и collect-only набора. Удаление tracked-файлов
уходит в коммит проекта, который делает владелец.

Реестр проектов парка —
`${DSH_1C_STATE_DIR:-~/.dsh/state/1c}/projects.json` (путь, раскладка,
версия контура на момент перевода, дата, результат doctor); запись
создаёт перевод проекта, doctor сверяет её с фактом и дописывает свой
вердикт. Поля пак-шага: `org` — метка конторы (ключ карты `regulations`
машинного конфига деплоя) и акт регламент-пака `regulations_pack`
(имя, версия манифеста,
канал link/copy, дата; для link — коммит чекаута с dirty-маркером);
писатель полей — оркестратор деплоя через `update_registry`
(`scripts/contour_paths.py`, flock на `projects.json.lock`, атомарная
запись). Новый проект — `/1c-bootstrap` (профили, contour.json, секция
AGENTS.md). Нечитаемый вход канона останавливает поиск (fail-closed):
сломанный маркер не превращает прод в тест, сломанный allowlist не
разрешает мутацию.

## 6. Проверка

```bash
python3 scripts/doctor.py <проект>            # семь разделов, exit 0/1
python3 scripts/doctor.py <проект> --json     # машинный verdict по разделам
python3 scripts/doctor.py <проект> --no-ping  # не поднимать MCP
python3 scripts/doctor.py <проект> --profile NAME
```

Разделы: `bundle` (пакет в профиле, строка патча, сборка `lib/`), `delivery`
(пресета-копии в патче нет; умолчание `1c` — миграционный хвост, WARN),
`skills` (15 контурных, 3 команды, скиллы
Юники, затенения), `mcp` (записи и живость), `layout` (раскладка DSH),
`project` (`v8project.yaml`, платформа, топология, `build/out`, движок
стиля, скилл bsp, реестр), `state` (корень состояния, замки, журнал гейтов).
Выход 0 — FAIL нет (WARN допустимы); у каждого раздела `--json` несёт
`status` и машинный `code` (`bundle.missing`, `mcp.db-down`, …).

## 7. Перезапуск хоста

Плагин подхватывается новым поколением модулей: «Остановка» → «Запуск».
«Запуск» при работающем сервере только открывает вкладку; «Пересборка»
пересобирает артефакты без перезапуска. Живая сессия держит загруженное
поколение модуля — правки плагина без перезапуска не видны. Resume сессии
сохраняет записанный пресет: умолчание профиля влияет только на новые
сессии.

## Миграция с 0.1 (пресет `1c` снят)

0.2.0 снимает пресет `1c` и экспорт `dsh-1c-contour/preset`. DSH резолвит
записанный пресет сессии строго (`agent-preset/not-found`), поэтому сессии,
записанные под `1c`, после обновления не собираются. Перевод —
`scripts/migrate_preset_sessions.py`: заголовок и события выбора
`1c` → `standard`, прочие строки логов побайтово целы, оригиналы сохраняются
(`*.bak-pre-1c-migration`), повторный прогон — no-op. Формат лога —
конкатенированные zstd-фреймы (первый фрейм = ровно строка заголовка,
события — фреймы-батчи, checksumFlag=1; инвариант
`session-persistence-jsonl/src/zstd.ts` DSH): скрипт сохраняет границы
фреймов, переупаковывает только изменённые фреймы; лог с нарушенным
контейнером (многострочный первый фрейм, оборванный хвост) — отказ,
починка границ — отдельная процедура из бэкапа. `--scan` — read-only
проверка инварианта по корпусу сессий. Порядок: «Остановка» → скрипт
(при запущенном хосте отказывает) → «Запуск». Доставка в переведённых
сессиях работает хостом по cwd проекта.

Строку `agent-preset-registry` с `selectedDefault: 1c`, оставленную старой
установкой в patch-документе профиля, снять (или вернуть умолчание профиля):
doctor называет её WARN `delivery.stale-default`. Пресет-копия `preset-1c`
в патче установленного бандла — FAIL `delivery.preset-copy` (старая
поставка, обновить бандл).

Возрождение стека `ontoship-team-1c`: ролевые пресеты несут composition
роли + персону, без строки `contour-preset` и шва `presetIds` — доставка
приходит хостом. Старый патч стека со строкой `dsh-1c-contour/preset`
получит громкий warn монтирования (экспорт снят), доставка при этом
работает хостом.

## Контроль установки

Сессия в 1С-проекте под любым пресетом (включая standard): 15 скиллов
контура, скиллы Юники, 3 команды, MCP-инструменты `mcp__unica__*`,
`mcp__1c-testpilot__*`, `mcp__1c-db__*`, `mcp__1c-kd__*` (имена нормализованы
DSH под контракт function-name, хвост `<12hex>` гейты отбрасывают).
Контроль: сессия вне 1С-проекта — ни скиллов контура, ни Юники, ни MCP,
независимо от пресета.

## Состояние

Корень состояния — `${DSH_1C_STATE_DIR:-~/.dsh/state/1c}`: замки инфобаз,
состояние гейтов, журнал `logs/rule-audit.jsonl`, реестр `projects.json`,
архив copy-снимков регламент-паков `pack-archive/` (пак-шаг деплоя;
уборка снимков — решение оператора).
Legacy-переменная состояния ZCode снята в Т10 после перевода парка.
