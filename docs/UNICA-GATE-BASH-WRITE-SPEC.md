# Спека: обнаружение bash-записи в исходники (unica-source-gate)

Инвариант контура: исходники `src/{cf,cfe}` и `tests/epf`
правятся только через Unica MCP. Ветка Bash гейта `unica-source-gate`
(`src/gates/unica-source.ts`) блокирует две машины записи: `sed -i`
(правка на месте) и перенаправление
`>` / `>>`. Спека фиксирует контракт распознавания: блок — только по
цели записи, не по присутствию паттерна в строке команды.

## Принцип

Гейт проверяет цель операции, а не лексику команды. Чтение исходника и
правка копии во временном каталоге — легальны (`cp src/cfe/… /tmp/w.bsl
&& sed -i … /tmp/w.bsl` проходит); правка исходника на месте — блок.
Fail-safe направление: неоднозначность трактуется в сторону блока —
ложный блок стоит агенту одной повторной команды, пропуск записи в
исходники — дыра в инварианте.

## Перенаправление

Каждый операнд `>` / `>>` нормализуется `normalizeSourcePath`
(`src/paths.ts`) отдельно;
блок, если цель легла в исходники (AGENTS.md внутри src — документация,
не исходник).

## Разбор sed

Команда токенизируется как `shlex` с `punctuation_chars=True`
(`tokenize`, `src/gates/unica-source.ts`), режется на сегменты по
шелл-разделителям (`&&`, `||`, `;`, `|`, `&`, `>`, `<`, `(`, `)`);
сегмент считается вызовом sed по basename первого токена. Операнды:

- флаги значений выражений `-e`, `-f`, `--expression`, `--file` (в кластере
  вроде `-ie` и прикреплённой форме `-es/a/b/` — тоже) означают: скрипт
  задан флагом, все свободные токены — цели;
- без флагов выражений первый свободный токен — скрипт, остальные — цели;
- прочие флаги (`-i`, `-n`, `-E`, `-r`, `-s`, `-z`, `--posix`, прикреплённые
  значения `-i.bak`, `-l5`) потребляются без значения.

Каждая цель нормализуется как путь от cwd; цель в исходниках — блок.

Цель-переменная (`"$f"`, подстановки с `$` / `` ` ``) не разрешается в
статике: если в строке команды встречается путь исходников — блок
(fail-closed), нет — проходит.

Токенизация упала (незакрытые кавычки и подобное) — разбор невозможен:
действует прежнее правило «`sed -i` и упоминание пути исходников в строке
команды» → блок.

Не являются находками: упоминание `src/…` в тексте скрипта sed; путь
исходника в аргументе чтения (`sed 's/a/b/' src/cf/файл` без `-i` — это
не запись и гейтом bash-ветки не проверяется вовсе).

## Границы

- Эскалации на bash-ветку не действуют: allowlist
  `.dsh/1c/unica-gate-escalations.txt` открывает только прямые правки
  Write/Edit/ApplyPatch.
- Прочие in-place-инструменты (`perl -pi`, `awk -i inplace`, `ed`, `ex`)
  контрактом не покрываются: обнаружение по sed и перенаправлению; новый
  инструмент — расширение спеки, не тихий обход.
- Селект, чем считать «записью», ограничен статикой: гейт не исполняет
  команду и не видит значения переменных.
