# Спайк обходного semantic-канала 1c-bsl-search

**Итог (решение оператора 24.11): канал не заводить.** Неделя ожидания
по unica#2512 без подвижек; своего обходного канала в разводке нет —
спайк остаётся доказательством осуществимости и границ, semantic-роль
ждёт подключения апстримом. Numbers ниже — не инструкция к развёртыванию.

Доказательство осуществимости своего semantic-поиска, пока роль `semantic`
в `unica.search` заглушена ядром (`ProviderRole::Semantic => None`,
апстримский адаптер — unica#2512). Спайк — эксперимент, не боевой канал
контура; решение о канале принимает оператор.

## Связка

- Прямое MCP-подключение к bsl-analyzer: символы и тела методов конфигурации
  напрямую, минуя глаголы юники.
- Эмбеддинги neuraldeep bge-m3 (free-квота).
- Результат — семантический индекс корпуса методов с самообновляемым кэшем.

Версии анализатора и рантайма в контуре пинует `unica.yaml`; поставка
рантайма — `scripts/install_unica_runtime.py`.

## Числа прогона

- Корпус большой конфигурации: ~712k методов.
- ~11k эмбеддинг-запросов при batch 64.
- Построение индекса: 2–4 ч.

## Границы

- Обоснование выбора прямого MCP-подключения вместо глаголов юники
  в материалах контура не зафиксировано. Известно: у анализатора есть
  собственный эмбеддинг-контур (`bsl-search` embedder, `EMBEDDING_DIM`,
  `EMBEDDING_MAX_REQUEST_BYTES`, docs/architecture/USER2_EMBEDDING_INTEGRATION.md
  апстрима itrous/bsl-analyzer).
- Прямое подключение публикует `syntax_help`/`symbol_info` с `not`
  в inputSchema; шлюз моделей qwen4 отвергает такой список инструментов
  (400 на любой запрос сессии) — bsl-analyzer#891. При принятии канала
  нужен фикс апстрима (убрать `not`; сервер его не проверяет, удаление
  ничего не теряет). Через глаголы юники проблема не возникает: схемы
  анализатора не попадают в список инструментов сессии.
- Регулярная работа контура идёт только через глаголы юники; прямое
  MCP-подключение к анализатору в боевой разводке отсутствует.
