- Published-исполнение `unica.apply` на пилоте требует
  `supportCapability.set` (конфигурация на поддержке вендора) — решение
  оператора, не снималось.
- Окно двух корней состояния: вендоренные стартеры проектов пишут в
  `~/.zcode/state/1c` до Т10; маркер контура в каноне → legacy-копии
  гейтов считают проект продом (fail-closed). Лечение — перевод проекта
  целиком (Т10).
- Станция КД — legacy-путь `~/.local/share/1c-zcode/kd-rules-mcp` до Т10;
  `.zcode/config.json` — legacy-фолбэк url станции (снятие — Т10).
- `wire_config.py` жив (его копию носят проекты: `run_e2e`, `publish_ib`)
  — снос вместе с legacy-скриптами в Т10. Докстринг wire_config всё ещё
  называет шаблон `.zcode/1c/templates/agents-section.md` — legacy-описание,
  уходит вместе со скриптом.
- В `workflows/` (поставляются в бандле) живы литералы `.zcode/…`
  (`1c-e2e-author`, `1c-e2e-run`); критерий Т10 перечисляет носители
  снятия legacy без workflows — при исполнении Т10 включить их в греп
  (находка панели Т9).
- Имя MCP-инструмента в DSH с хеш-хвостом (`mcp__unica__unica_apply_<12hex>`);
  `code.insert` с `selector.anchor` по модулю с BOM+CRLF отклоняется,
  работает селектор уровня метода.
- Стенд 1c-db на пилоте не поднят (граница Т7); `/1c-bootstrap` и
  `/1c-test` smoke-прогоном не гонялись (Т5).

## Стартовый промпт

«Стартуй юнит» — открыть draft-спеку юнита (скилл `grilling`); «исполняй
тикет N» / `/ship` — ship тикета N, один тикет за запуск. Чек-лист
фазовых переходов: вычитка спеки перед план-гейтом — `grilling`; нарезка
и критик — `to-tickets`; ревью-панель перед merge — `ship`. Состояние
брать из этого файла, следующий тикет — отсюда же.
