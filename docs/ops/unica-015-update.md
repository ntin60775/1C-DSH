# Обновление контура на Unica 0.15.0 (финал)

Отчёт изучения релиза, классификация изменений, карта зависимостей контура
и запись выполненного обновления. Канон установки после обновления —
[UNICA.md](../UNICA.md); версии бинарей — `unica.yaml` в корне контура.

## Релиз

Финал `v0.15.0` опубликован 15.11.2026 (коммит `e0324e80a296`). Контур до
обновления стоял на `0.15.0-rc.5` (10.11). Между rc.5 и финалом —
alpha.13/14 и rc.6 (15.11).

Тела релизов GitHub для срезки не годятся: они сгенерированы от разных баз
(rc.5 — 354 PR, rc.6 — 486, финал — 908, наборы пересекаются). Точный
diff — compare API `v0.15.0-rc.5...v0.15.0`: **134 коммита** (133
содержательных + релизный), `behind_by 1` (собственный релизный коммит
rc.5). Классификация ниже — по этим 134 коммитам, не по телам релизов.

Состав поставки (lock тега `plugins/unica/third-party/tools.lock.json`):

| Артефакт | rc.5 | финал | Источник |
|---|---|---|---|
| unica (ядро) | 0.15.0-rc.5 | 0.15.0 | релиз `IngvarConsulting/unica` |
| bsl-analyzer | 0.2.86 | 0.4.6 | `unica-toolchain`, тег `bsl-analyzer-v0.4.6-build.1`, MIT |
| v8-runner | 0.15.3 | 0.17.4 | `IngvarConsulting/v8-runner-rust`, AGPL-3.0 |

`rlm-tools-bsl` в поставке по-прежнему нет. Протоколы MCP те же
(`2025-06-18`, `2025-11-25`, `2026-07-28`), состав инструментов тот же —
11 глаголов.

## Классификация изменений rc.5 → финал

### A. Вопросы человеку (новый класс поведения, ~20 коммитов)

Операции, которые раньше исполнялись или отказывали, теперь спрашивают
человека: подтверждение перезаписи базы (`push force`, #2869), удаление
расширения (#2876), замена данных DT (#2875), пересоздание файловой базы
(#2939), полный pull поверх несохранённых правок (#2886), запись в базу
другой копии (#2951), расхождение базы и набора при push (#2845), снятие
с поддержки (#2889, #2891), смена поставщика в apply (#2871), режим
совместимости ниже 8.3.8 (#2882), перевыгрузка набора (#2920, #2922),
занятая база и сеансы (#2926), цепочка вызовов (#2856). Ответ снимает
свой запрет, остальные цели пакета проверяются (#2931).

Канал — elicitation клиента (`elicitation/create` до протокола
`2026-07-28`, `input_required` с `2026-07-28`). **Клиент DSH объявляет
`capabilities: {}` — elicitation нет**: подтверждения (`proceeds_unasked`)
исполняются как прежде, выборы остаются отказом с вопросом
(`unica.choice`). Аргументы `humanConfirmation`/`humanReexport` ставит
только сервер — вызов модели с ними отказывается до демона. Контур:
правило добавлено в `templates/agents-section.md` и `docs/UNICA.md`;
обходной путь не предусматривается (fail-closed апстрима).

### B. Раннер 0.17 и рабочее пространство

- Переход на v8-runner 0.17.1 → 0.17.4 и его словарь операций (#2910,
  #3046, #3086); контракты инструментов сверены под 0.17 (#3085).
- **Проекция конфига раннера упразднена** (#2909): раннер работает с
  конфигом копии, умолчание `workPath` — корень копии, сквозные отказы
  рабочего пространства (#2911). Старая `.build/unica/runner-project/`
  удаляется при ближайшей записи; неудача — предупреждение
  `former_runner_config_copy_kept`.
- `infobases` в основном файле раннер отвергает — карта только в
  `v8project.local.yaml`; `infobase` принимается один цикл в local-слое.
- Исполняемые `pull`/`push`/`make` запирают правки исходников (#2848,
  правило #2849): параллельный `unica.apply` получает отказ.
- `pull` вызывает раннер напрямую, механизм публикации полной выгрузки
  удалён (#2852, #2854); превью считает несохранённые правки по git
  (#2855); runtime-операции без внутреннего превью раннера (#2850).
- Отмена вызова раннера — прерыванием, ответ раннера вместо убийства
  процесса (#2942); живой агент раннера удерживается (#2925); уборка
  копии начинается с `agent stop` (#3086); слой отказа среды и база
  другой копии — полями раннера 0.17.2 (#2991).
- База от `infobase.create` принимает push без force (#2847); повтор
  полной сборки после частичной загрузки снят (#2933).

Контур: справочник `skills/1c-project-layout/references/v8project.md`,
скилл `1c-unica-worktree` (владелец базы — сама копия), `docs/UNICA.md`.
Гейты не менялись: замок ИБ контура и замок правок юники — разные
пространства, отказ юники гейт видит как обычный отказ вызова.

### C. Линии платформы и форматы наборов

Запись в форматы 2.21/2.22 с сохранением формата набора (#2826); новые
файлы, формы, макеты и СКД в форме Конфигуратора (#2927, #2928); эталоны
XDTO 8.3.27/8.5.1/8.5.4 (#2930); заимствования, режимы совместимости,
виды объектов, свойства корня — по линии набора (#2940, #2950, #2963,
#2972, #2973, #2977, #2989, #3002, #3007, #3008, #3021, #3022); каталог
событий и генератор по линии (#2966, #3027); `event.implement` — области
обработчиков по стандарту 455 (#2881); `form.set` на корне конфигурации
(#3016, #3025), `props.set` пишет свойства описания формы (#3029),
компиляция формы пишет или отвергает каждый ключ (#2975, #3003, #3040);
новая форма списка пишет настройки динсписка как Конфигуратор (#3006);
права очереди в ролях (#3026), события менеджера очереди (#3047).

Контур: знание поверхности — `docs/UNICA.md`, секция агента; правила
пересборки проектов не затрагиваются (линии — контракт юники, не контура).

### D. Надёжность демона и заданий

Срок подъёма по замеру, нехватка времени — не несовместимость (#2981);
задача между реестром и заданием читается, а не пропадает (#3012);
`daemon_idle` без настенных часов (#3019); сохранённый план держит демон
не дольше срока хранения (#3028); приостановленный демон гибнет с
упавшим запускающим (#3039); уборка потомков ждёт смерти процесса
(#3034), живым потомок считается по личности PID (#3050); падение
бэкенда называет улику (#3041); Drop не паникует (#3087); отказ подъёма
по сроку называет причину (#3088).

Контур: `unica.task.result`-ожидания скиллов не меняются; потерь вызовов
стало меньше — трассы сессий чище.

### E. Анализ и чтение

bsl-analyzer 0.4.5 → 0.4.6: MIT, база координат JSONL, references по
запросу (#2846, #3064); находки редактора от резидентного анализатора и
ход подготовки анализа (#2862, #2868); первая страница ветки view без
повторного разбора дескрипторов (#2873); правка по поддержке на каждом
узле view (#2884); статья справки и комментарий метода — полями (#2986,
#3004, #3045); находка поиска легче и называет, что открыть (#3077);
демон без рёбер xdto/xml-format (#2936), кодек XDTO через порт семейства
(#2929).

Контур: `bsl_review_join.py` читает страницы `unica.check` — формат
находок не менялся, джойн не правился. Скилл `1c-unica-artifacts`:
версии движков теперь из yaml.

### F. Готовность перед правкой (pre-ready-check)

Повтор по каждому имени и сбой сборки отдельно (#2938); замок рабочих
копий базы и текст отказа git (#2945); отказ с каталогом сборки другой
копии (#2987); итог только по досчитанному (#3037); сверка с воротами PR
(#3060); авария сборки — «не проверено» (#3072); гейт готовности берёт
весь workspace (#3081).

Контур: новый класс отказов до записи — скиллы правки (`apply`-цикл)
должны читать причину отказа, а не повторять вызов; отражено в секции
агента и `docs/UNICA.md`.

### G. Процесс апстрима (контур не затрагивает)

CLA и реестр участников (#2853), независимое ревью Codex (#2944),
приёмочный корпус и стражи (#2932, #2937, #2949, #2983, #3009, #3036,
#3042, #3044, #3068, #3089 и др.), CI-инвентарь.

## Границы и остатки

- **Выборы без elicitation** — граница канала DSH: отказ с вопросом,
  решение оператора. Обход не делается.
- **Двойной BOM** (`code.replace`/`code.insert`) и **push формы с ручным
  динсписком** (#1877) в diff rc.5→финал не исправлены — границы остаются.
- `bootstrap verify` требует host-манифест (`.codex-plugin/plugin.json`),
  которого в контурной установке нет; контур использует `prefetch`/`run`.
- Парк проектов: секция AGENTS.md обновляется `/1c-bootstrap` по команде
  оператора; живые пробы `push`/`apply` на стенде и admission большого
  репозитория — после обновления (зонтик #1119).
- `~/.unica/provider-state` от rc.5 остался (состояние, не бинарники);
  новое состояние пишется в корень установки.
