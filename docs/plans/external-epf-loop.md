# Спека: цикл внешних epf (ишью #62)

> План-гейт: решения приняты оператором в чате 08.11 (фронтир два
> раунда: маршрут epf, носитель v8-контейнера, правило issue, приёмка,
> сужение гейта); спека — их транскрипция, правки вносятся по находкам
> сверки понимания нарезки до первого ship.

## Цель

Знание о цикле внешних обработок и отчётов — сборка/разбор, открытие в
тест-клиенте, окна платформы, контроль собранного — живёт в носителях
контура, а не в памятях отдельных проектов; гейт исходников согласован
с каноном юники для внешних epf/erf.

## Готово

1. Реестр `skills/1c-testpilot/SKILL.md` дополнен и правлен:
   - открытие внешнего epf в тест-клиенте — `launch_client` с
     `extra_args: ["/Execute", "<путь.epf>"]`; через `e1cib/…` внешние
     не адресуются; файловый диалог — fallback с оговоркой про клавиатуру;
   - каталог окон платформы (раздел «Навигация и окна»): ErrorWindow
     (текст по декорациям; `tc_app get_current_error` — канон чтения,
     **не проверено** живьём), вендорское модальное «Отчет об ошибке»
     (close-only, `unsupported_receiver` на `get_context`),
     «Предупреждение»/вопрос = `form_name="MessageBox"` с заголовком
     окна «1С:Предприятие», гасится `answer_dialog`, оракул — смена
     активного окна;
   - строка «Сочетание клавиш»: граница по среде — при клиенте в
     отдельном Xvfb проба MCP-клавиатуры дала
     `keyboard_window_not_foreground`, подтверждения через
     `answer_dialog`; апстрим заявляет поддержку isolated, расхождение
     не объяснено; живой стенд — не проверено;
   - диалог безопасности на внешний epf/erf: поднимается на пересобранный
     бинарник и после рестарта клиента; execute-каналы до подтверждения
     висят до 180 с; якорь доверия (путь/контент) — носитель 1c-db-data
     (п. 4), в testpilot — указатель.
2. `skills/1c-project-layout/templates/agents/src_epf.md` дополнен
   каноном сборки: секция элементов `<ChildItems>` (порядок

## Рамки

- Знание + сужение гейта; релиз, пин и раскатка — отдельные решения
  оператора вне юнита.
- erf покрывается классом (гейт, инвариант, скрипты, reference);
  новый шаблон src_erf не заводится — существующий приводится к канону
  src_epf.md.
- Живой пробы `get_current_error` нет (решение оператора 08.11): строка
  реестра помечается «не проверено».
- Скрипты `epf-dump`/`epf-load` не трогаются (граница проверенности —
  8.3.27.1859, 1c-ibcmd-delivery).

## Ограничения

- Правило «ловушка → issue до конца сессии» остаётся прозой без
  страховки от обрыва сессии (решение оператора 08.11 — вне рамок).
- Пишущие скрипты через Bash обходят bash-ветку гейта: по коду
  `bash_writes_to_source` ловит только `sed -i` и перенаправления с
  префиксом в строке команды — python-скрипт, пишущий в `src/epf`,
  ветка не видит — отдельный зазор, кандидат в отдельное ишью, в этом
  юните не закрывается.
- Поверхность `unica.apply` на узлах внешних source-set'ов известна по
  тексту epf-init (отсылка на form-edit/form-events), живьём не
  проверена — в носителях формулируется как граница применимости.
