# Поставка 1c-ibcmd-delivery: mapping, тело скилла, указатели, релиз

> План-гейт: утверждена оператором 05.11.

## Цель

Скилл `1c-ibcmd-delivery` доезжает до проектов контура и закрывает
грабли сессии проекта: скилл зрел, но mapping в deploy.json не вносили
ни разу (git -S пуст), в проектах его нет, указатели `1c-contour` и
docs/UNICA.md ведут в пустоту. Агент проекта работал перебором глаголов
и получил два ложных успеха.

### Решения оператора (приняты 05.11)

1. Состав юнита — mapping и тест-инвариант, тело скилла, указатели
   agents-section и README, плюс строка таблицы состава README
   (принял оператор, ответ в чате).
2. Финал юнита — смок + релиз: merge → тег 0.4.92 → пин каталога →
   validate --fetch → дымовой прогон на локальном полигоне по регламенту
   раскатки (AGENTS.md). Версия `.zcode-plugin/plugin.json` — 0.4.92 в
   релизном коммите. Красный смок: пин каталога снимается, тег
   остаётся пометкой негодного выпуска, полигон откатывается предыдущей
   версией. Раскатка боевых — отдельным заказом оператора
   (рекомендация принята ответом на вопрос фронтира).
3. Дистрибокс-знание — рецепт в скилле, без ключа конфига и обёртки
   (рекомендация принята ответом на вопрос фронтира).
4. П4 (живая проба с различением типов исключений) — вне юнита,
   остаётся сессии проекта.

## Готово

1. deploy.json: mapping `skills/1c-ibcmd-delivery →
   .zcode/skills/1c-ibcmd-delivery`; итого 15 скилловых mappings из 19
   (было 14 из 18; прочие — hooks, workflows, scripts, templates).
2. tests/test_deploy_mappings.py: инвариант поставки — каждый
   `skills/*/SKILL.md` замаплен в свой каталог; дубликатов from/to нет;
   источники существуют внутри репо; цели под `.zcode/`. Красный прогон
   показан по рецепту тикета: `git archive` базового дерева + новый
   тест, mapping не добавлен; рабочее дерево не портится.
3. Скилл `skills/1c-ibcmd-delivery/SKILL.md`, три вставки:
   - дистрибокс-рецепт в раздел «Хост Linux»: ibcmd на Linux-хосте может
     жить только в distrobox-контейнере; детект по живым контейнерам,
     вызов `distrobox enter <имя> -- ibcmd …`; имя контейнера — из
     конфигурации машины; каталог базы виден из контейнера;
   - сигнатуры глаголов рядом с циклом поставки: `config load` на
     каталоге даёт `Is a directory`, на Configuration.xml — «Неверный
     формат хранилища данных» (диагноз по аргументу: каталог —
     `config import`, контейнеры .cf/.cfe — `load`); unica `make` —
     поверхность 0.15, на профиле 0.13 (`profiles.yaml`) отказ «tool is
     not in the canonical v0.13 profile», сборка .cfe — `config save`
     из базы;
   - «import упал — apply не звать» у раздела «Доказательство донесённой
     версии»: apply поверх упавшего import применяет старый буфер и
     печатает ложное «Создано поколение».
4. templates/agents-section.md: строка «загрузка `.cf`/`.cfe` — через
   ibcmd» дополнена указателем на скилл.
5. README.md: таблица состава skills/ дополнена
   `1c-ibcmd-delivery`.
6. Проверки: полный прогон `tests/test_*.py`,
   `scripts/lint_skill_frontmatter.py`, forbidden-грепы по чеклисту
   AGENTS.md, грейпы канона (даты, «наблюдение», слитные сокращения,
   имена проектов).
7. Релиз: bump `.zcode-plugin/plugin.json` до 0.4.92 → merge в main →
   тег v0.4.92 → пин в sot-zcode-marketplace → validate --fetch.
8. Дымовой прогон на локальном полигоне по регламенту раскатки
   (AGENTS.md): установка тем же путём, что бой, `/1c-doctor`, скилл на
   месте в развёртке, живой вызов unica.
9. docs/ops/continue.md после merge: запись «юнит отгружен, приёмка за
   оператором» и очередь действий.

## Рамки

- Вставки в тело скилла — минимальный diff над существующим текстом;
  правка канона — два прохода против первоисточников (справка
  `ibcmd help <режим>` 8.3.27, факты сессии проекта).
- Тест stdlib-only, по образцу tests/test_deploy_recon.py (конвенция
  `_lib.check/summary`); README машинно не проверяется — проза.
- Тексты вставок показываются оператору в диффе ship-тикета.

## Ограничения

- Специфик проектов и машины в каноне нет: имя контейнера и путь версии
  платформы из фактуры в тексты не переносятся.
- NBSP нет (grep-гигиена репо); императив без «вы»-форм; канон текстов —
  docs/TEXT-STYLE.md.
- Раскатка боевых проектов вне юнита; П4 вне юнита.

## Контекст

- Скилл создан 21.10 (4301a9c, закрытие #33) с перекрёстными ссылками
  (UNICA.md, `1c-contour`), но без mapping — единственное нарушение
  конвенции «скилл + mapping одним коммитом» среди соседей: kd-rules
  (99c405e) вёз четыре скилла вместе с deploy.json, релиз v0.4.44
  (3709c6f) пишет «маппинг deploy.json» в сообщении.
- Ни одна проверка не связывает `skills/` с mappings: линт скиллов
  проверяет слоты frontmatter, чеклист коммита mapping не упоминает,
  тестов на deploy.json нет; раскатка 02.11 (эра v0.4.73, четыре
  проекта) прошла после создания скилла и промолчала.
- Фактура сессии проекта: ворктри проекта, скрипт заливки в его
  `build/tools` — четыре провала (`load` по каталогу и
  Configuration.xml, unica `make` вне профиля 0.13, зависший пакетный
  1cv8), два ложных «Создано поколение» (apply поверх упавшего load),
  корректный глагол `config import` найден последним; вызов ибкмд —
  `distrobox enter` с полным путём в контейнере.
- Развёртки парка проверены `ls .zcode/skills/` — скилла нет ни в
  одной.
