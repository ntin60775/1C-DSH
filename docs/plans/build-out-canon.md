# Канон build/out: типовые каталоги артефактов

> План-гейт: решения приняты оператором в чате 07.11 (четыре развилки +
> уборка); спека — их транскрипция, правки вносятся по находкам сверки
> понимания нарезки до первого ship.

## Цель

Строгая верхняя раскладка `build/out/` во всех проектах контура: товарные
артефакты по типам (зеркало `src/{cf,cfe,epf,erf}`), отдельный каталог
отчётов прогонов, отдельный каталог служебных артефактов сборки. Правило
живёт в каноне контура (скилл layout, всегда-загружаемая строка,
doctor-WARN), чтобы агенты больше не изобретали каталоги по имени тикета.
В объём юнита входит уборка свалки `build/out` project-bp по этому правилу.

## Решения оператора (07.11)

1. Служебный каталог — `build/out/tmp`: временное по определению, снос
   в том же заходе.
2. Отчёты прогонов — отдельный каталог `build/out/reports` (читаются
   после прогона, не «временные»).
3. Однострочное правило в `templates/agents-section.md`
   (всегда-загружаемый слой): нарушение случилось именно потому, что
   правило жило только в скилле, который агент не открывал.
4. Doctor-WARN на файлы в корне `build/out` вне шести каталогов;
   блокирующий гейт не делается — `.cfe` пишут ibcmd/дистро-бокс,
   PreToolUse видит только строку команды, парсинг путей хрупкий.
5. Уборка свалки `build/out` project-bp — в объём юнита.

## Правило (канон контура)

```
build/out — поставляемые артефакты сборки и прогона. Верхний уровень строгий:
  build/out/cf/      конфигурации .cf
  build/out/cfe/     расширения .cfe
  build/out/epf/     внешние обработки .epf
  build/out/erf/     внешние отчёты .erf
  build/out/reports/ выводы прогонов: allure, cucumber, junit, yaxunit,
                     логи va/yax, скриншоты прогонов
  build/out/tmp/     служебные артефакты сборки: проверочные экспорты,
                     round-trip-каталоги, манифесты, журналы сборки
Таксономия зеркалит src/{cf,cfe,epf,erf}: что в src — то и в out.
Внутри type-каталога создание подкаталогов на усмотрение агента.
Имя артефакта: <Имя>_<ГГГГ-ММ-ДД>[.<суффикс>].<ext>; одно имя = одна
версия, перезапись без смены даты запрещена.
Хеш и размер фиксируются там, где на артефакт ссылаются (факты
поставки / CHANGELOG), не рядом с файлом.
tmp — временное по определению: снос в том же заходе; на файлы из tmp
ничто вне текущей сборки не ссылается.
reports: поколение отчётов прогона сносят при следующем прогоне той же
сцены; доказательства приёмки живут в docs, не в build.
Вне шести каталогов файлы в build/out не создаются.
```

## Тикеты

### Т1 — канон в контуре (1c-zcode)

Все шесть строк таблицы «Посадочные места» + тест doctor. Критерии
(падают на базовом коммите):

- К1 doctor: фикстура проекта со свалкой в `build/out` → WARN с перечнем;
  фикстура с шестью каталогами → WARN нет. Артефакт — вывод doctor на
  фикстурах; на базе WARN-логики нет.
- К2 греп `build/out` в `templates/agents-section.md` → строка правила
  с шестью каталогами; на базе пусто.
- К3 подраздел в `skills/1c-project-layout/SKILL.md` несёт правило
  целиком (шесть каталогов, именование `<Имя>_<дата>`, tmp-снос в заходе,
  хеш-реестр не в `build/`); `lint_skill_frontmatter.py` зелёный.
- К4 грепы в `1c-ibcmd-delivery` (`build/out/cfe`) и `1c-test-contour`
  (`build/out/reports`) непусты; на базе пусты.
- К5 строка `build/` в таблице `docs/PROJECT-LAYOUT-SKILL.md` описывает
  раскладку `out`.
- К6 прогон всех `tests/test_*.py` зелёный (новый тест doctor включён).

### Т2 — уборка build/out project-bp

- К1 sha256 каждого перенесённого `.cfe` до и после переноса совпали;
  фактические хеши зафиксированы в отчёте уборки; сверка с носителем
  фактов тикета 50-1 — по фактическому состоянию того носителя на момент
  исполнения (захардкоженных хешей в тикете нет).
- К2 в корне `build/out` нет файлов и нет каталогов вне шести канонических
  (полный набор из шести не обязателен — каталоги появляются с первыми
  артефактами своего типа).
- К3 `tools/VAParams.template.json` целит `junit`, `screenshots`, `allure`,
  `cucumber` под `build/out/reports/`; живой прогон e2e не требуется —
  артефакт доказательства сами конфиги.
- К4 снос > 7 NORMAL-объектов прошёл авторевью субагентом до сноса
  (вердикт «безопасно» с обоснованием); неуверенные цели не снесены,
  список — оператору в отчёте.

Блокирующие рёбра: Т2 идёт после приёмки Т1 (правило канона — оракул
целевого состояния) и после завершения тикета 50-1 project-bp — артефакты
50-1 ещё пересобираются параллельной сессией (факт критика 07.11:
`.cfe` перезаписаны при том же имени); признак незавершённости — хеши
меняются между инвентаризацией и переносом, тогда стоп.

## Ограничения (точки остановки)

- `build/ib` и сервисные каталоги стенда (`log`, `logs`, `ibsrv-data`,
  `temp`, `hash-storages`, `tools`) не трогаются.
- Снос — по правилам удаления: только абсолютные пути; NORMAL > 7
  объектов — авторевью субагентом; `*.log` не SAFE.
- Сомнительные цели (`06-1-acceptance/`) решает инвентаризация: неуверен —
  список оператору, не снос.
- Корень `build/` вне скоупа; находки-сироты (`va-shot.png`,
  `va-params.launch.json` в корне) — в отчёт уборки, решение оператора.
- vendor-скиллы юники (epf/erf-вывод) не правятся: правило живёт в наших
  скиллах, юника следует канону контура через agents-section.
