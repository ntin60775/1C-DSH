# Спека: набор пресетов доставки контура

Повод — юнит `team-profiles` ntin (`docs/plans/team-profiles.md`, решения
7, 11 и «Готово» 4) и его тикет 05: новое стековое репо
`ontoship-team-1c` поставляет пресеты `1c-architect`, `1c-orchestrator`,
`1c-executor` и переиспользует доставку/гейты `dsh-1c-contour`. Шов
минимальный и аддитивный: фильтр доставки из точного id `1c` становится
конфигурируемым набором id. Форма шва задана утверждённой спекой ntin;
отдельного план-гейта 1C-DSH не было — решение о переносе принадлежит
приёмке этого тикета оператором.

## Цель

Сессия под стековым пресетом (`1c-*`) в 1С-проекте получает тот же
контур, что и пресет `1c`: скиллы, команды, MCP контура. Пресет `1c`
и конфиг без ключа не меняются; пресеты team-бандла (`architect` и др.)
доставку не получают.

## Решения

| # | решение | источник |
|---|---|---|
| 1 | Носитель набора — конфиг строки пресета `contour-preset`: ключ `presetIds` (массив id) | форма шва ntin, «Готово» 4 |
| 2 | Дефолт без ключа — ровно `['1c']`; невалидный/пустой набор не отключает доставку, а пишет громкий лог и откатывается к дефолту | аддитивность шва, безопасность контура |
| 3 | Обе точки фильтра (`deliver`, `agent-preset/selected`) читают один набор; стековые пресеты передают три id | тикет 05 ntin |
| 4 | Гейты не привязываются к пресету: плагин гейтов остаётся хост-уровня, в 1С-проекте действует на любую сессию | граница объёма; дифференциация позже |
| 5 | Доставка не копируется стеком: стек монтирует `dsh-1c-contour/preset` | «Готово» 4 ntin |

## Готово

1. **Набор из конфига.** `apply(ctx, config)` принимает `presetIds`;
   каждое из трёх id получает скиллы и MCP проекта; `1c` работает без
   ключа; `architect` (team) с тем же конфигом доставку не получает.
   — носители: `src/preset/index.ts`, `src/preset/config.ts`, тесты
   `preset-mount.spec.ts`, `preset.spec.ts`.
2. **Дефолт цел.** Без ключа доставка ровно у `1c`; пустой, нестроковый
   или не-массивный набор откатывается к дефолту с предупреждением.
   — носители: `presetIdSet`, unit-тесты, красная проба на базе
   (фильтр захардкожен — новые id не получают доставку).
3. **Документация шва.** `docs/dsh-install.md` и комментарий строки
   `contour-preset` называют ключ и дефолт; стек-бандл ссылается на шов.
   — носители: док, патч, тикет T1.

## Рамки

- Только 1C-DSH: код, тест, док. Стек-бандл, реестр и живая проба ролей —
  в ntin (тикет 05) и в тикете T1 этого репозитория.
- Per-role дифференциация доставки, скиллов и гейтов не вводится.
- Формат `<profile>/ontoship/executors.json` не меняется.

## Ограничения

- Правка аддитивна: удаление ключа, изменение `PRESET_ID` и поведение
  пресета `1c` не входят в объём; регрессия — существующие тесты.
- Модульного HMR у профиля нет: новая ревизия плагина в живом хосте
  видна только новому поколению модулей (перезапуск). Живая проба в
  живом GUI — после перезапуска оператора; без него — стоп и отчёт.
- Стек-бандл требует team-бандл и реестр; порядок установки называет
  README стека.
