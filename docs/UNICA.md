# Unica: установка, версии, скиллы и MCP

Контур 1С — мягкая зависимость Unica: без неё гейт исходников отрезает
единственный путь правки 1С. Бинарники ставятся один раз на машину, скиллы
Юники и MCP-запись `unica` поднимаются в сессии 1С-проекта. Два канала
одновременно не держать: имя MCP-сервера `unica` одно.

## Канал и версия

Текущая версия — `0.15.0-rc.5` (тег `v0.15.0-rc.5`, коммит
`537e4b513c80`). Версия и состав артефактов — `runtime-manifest.json`
schema 2 в каталоге установки; проверка — `/1c-doctor`.

## Глобальная установка

| Что | Где |
|---|---|
| Бинарники (ядро, `bsl-analyzer`, `v8-runner`) | `~/.local/share/unica/runtimes/<имя>/<версия>--<sha256>/<платформа>/` |
| Манифест установки | `~/.local/share/unica/<версия>/runtime-manifest.json` |
| Bootstrap | `~/.local/share/unica/<версия>/bootstrap/bin/<платформа>/unica-bootstrap` |
| Лаунчер | `~/.local/bin/unica` |
| Скиллы | `~/.local/share/unica/skills` |
| Кэш артефактов | `UNICA_RUNTIME_CACHE_DIR`, по умолчанию `~/.local/share/unica/runtimes` |

В манифесте rc.5 три артефакта: `unica 0.15.0-rc.5`,
`bsl-analyzer 0.2.86`, `v8-runner 0.15.3`. `rlm-tools-bsl` в rc.5 нет —
не требовать и не искать. Маркер завершённости артефакта — `.ready.json`
рядом с каталогом платформы; оборванная закачка оставляет `.partial`
в корне кэша.

Лаунчер берёт версию из `UNICA_GLOBAL_VERSION` или последнюю в
`runtimes/unica`, корень — `UNICA_GLOBAL_ROOT`, и экспортирует
`UNICA_RUNTIME_CACHE_DIR` перед запуском ядра. Проверка установки —
`unica --help` (печатает `unica 0.15.0-rc.5`).

## Скиллы Юники

Скиллы — собственность проекта, не профиля: они видны только в сессии
1С-проекта. Ставит их `scripts/install_unica_skills.py`: разреженный клон
тега, каталог `plugins/unica/skills`, атомарная подмена
`~/.local/share/unica/skills`. Рядом ставятся `LICENSE` и `SOURCE.json`
(версия, тег, коммит, число скиллов) — проверка установки:

```bash
python3 scripts/install_unica_skills.py --check
```

Прежняя установка скиллов не нужна: подмена каталога целиком, половины
скиллов не бывает. Источник — LGPL-3.0, текст лицензии едет с каталогом.

Провайдер скиллов пресета `1c` поднимается в области агента и видит три
корня: `skills/` контура, `commands/` контура и `~/.local/share/unica/skills`.
Вне 1С-проекта и без пресета скиллов Юники в каталоге нет.

## MCP-запись `unica`

Запись ставит пресет `1c`, а не проект. Stdio-команда записи — `unica mcp`
(лаунчер `~/.local/bin/unica`, подмена — `UNICA_LAUNCHER`) с `cwd` корня
проекта. Юника отвечает только `structuredContent`; клиент MCP DSH
проецирует его в текст модели начиная с 0.2.2-rc.2 (фикс `mcp-client`,
ntin60775/deepseek-harness#1). Воркспейс Юники фиксируется при старте;
вызов инструмента `cwd` не переключает: для второй копии — своя сессия,
а не второй вызов.

- `UNICA_RUNTIME_CACHE_DIR` указывает на глобальный кэш; проект своего
  кэша не держит.
- Handshake — протокол `2025-11-25`, `serverInfo 0.15.0-rc.5`, 11
  инструментов: `view`, `apply`, `resolve`, `search`, `check`, `diff`,
  `run`, `docs`, `task.get/result/cancel`.
- Соседние записи пресета: `1c-testpilot`, `1c-db` (с инстансами
  мультистенда), `1c-kd`.
- Пресет требует DSH с фиксом `mcp-client` (0.2.2-rc.2 и новее): на
  стоковом 0.2.2-rc.1 ответы Юники приходят в сессию пустыми.

## Поверхность 0.15

- **Страницы.** `view`, `check`, `diff`, `docs`, `search` отдают длинные
  ответы страницами по `limit` (1–50) и `cursor`. Пока `cursor` непустой,
  ответ неполон. `check {}` без `at` отдаёт вердикт workspace и группы
  диагностик страницами; `check {at}` — находки узла.
- **Поиск.** Буквальный `search` без `role` идёт до последнего совпадения,
  первая страница несёт `data.totals` (точный объём). Роли — `symbol` и
  `semantic`; роли `lexical` нет. `symbol`/`semantic` могут остановиться
  после первого окна и пометить неполноту.
- **Пакетный `resolve`.** `resolve {paths: ["…:4", …]}` переводит много
  путей/строк в логические адреса одним вызовом; ошибка одного элемента
  не роняет остальные.
- **Длинное свойство.** `<узел>.Props.<имя>` читает свойство целиком,
  когда обычный `view` упирается в предел; `<узел>.Can.<op>` — контракт
  операции.
- **Новые операции `apply`.** `panels.set`, `homePage.set`, `attribute.copy`,
  `dimension.set`, `property.rename`, `props.set` на корне конфигурации и
  форме. Состав для узла — из `can`.
- **Словарь операций.** Поле `implemented` убрано; недоступной операции в
  словаре нет. Контракт вызова — `argsSchema` из `unica.run {}`; при
  `support.state: limited` допустимо только `support.supportedArgs`.
- **`unica.docs`.** Источники — `platform-help` и `development-standard`;
  `configuration-documentation` отвечает `unsupported_source` (#939).
  Длинная страница — страницами, ответ может прийти задачей
  (`status: working`): ждать `task.result`, принятие задачи не ответ.
- **Секреты и EOL.** Секрет подключения не попадает в сохранённые задания;
  правки XML не портят переводы строк в нетронутом тексте.

## v8project 0.15 и v8-runner

Полный справочник полей и регламент переезда —
`skills/1c-project-layout/references/v8project.md`. Коротко:

- `infobases` живут в `v8project.local.yaml`, поддерживается только `origin`.
  Несколько именованных баз, верхнеуровневый `connection`, смесь
  `infobase` + `infobases` отвергаются; 0.15 переносит базу в приватную
  копию `.build/unica/runner-project/`.
- `builder`, `basePath`, `execution_timeout`, `push.partialLoadThreshold`
  отвергаются. Полная загрузка — `push full: true`.
- `build` — прежнее имя `push`; `infobase` — прежнее имя `infobases.origin`;
  принимается один цикл.
- Исполнители `providers`: `designer`, `agent`, `ibcmd`, `ibcmd-rs`,
  `webinst`; прежние имена `build`/`dump`/`init`/`load`/
  `infobase.configuration.export` переименовываются в
  `push`/`pull`/`infobase.create`/`upload`/`download`.
- `upload`, `apply`, `reset` как операции `unica.run` недоступны (#1246).
  Загрузка `.cf`/`.cfe` — ibcmd, не раннер. `unica.apply` (MCP) — другое,
  он правит исходники. Сборка `.cfe` — два пути: `unica make` (из
  исходников, расширение должно стоять в ИБ) и `ibcmd config save
  --extension=<имя>` (из базы) — скилл `1c-ibcmd-delivery`. Успех apply не
  равен донесённой версии: критерий — поколение расширения, не строка
  «успешно» и не `generation-id` основной конфигурации.
- Файловая база принадлежит копии: запись из второй копии даёт
  `infobase_of_another_copy`. Каждой копии — своя база
  (`infobase.create`); владелец и проекция — скилл `1c-unica-worktree`.

## Известные границы 0.15

- **Публикации нет.** `unica.run` не публикует базу; `panels.set` и
  `homePage.set` — интерфейс, не веб-публикация. Контур закрывает это
  скиллом `1c-ibsrv-publish` через `publish_ib.sh`.
- **Дети HTTP-сервиса** (шаблоны URL, методы) по-прежнему не выражаются
  контрактом `object.create` целиком; апстрим — #529. Дети и права
  дописываются XML по разовой эскалации.
- **Размер вызова.** Предел ~16 КиБ снят (#1309), ресурсные лимиты сведены
  в реестр (#1312), отказ по размеру результата называет размер и предел.
- **`push` формы с ручным динсписком** падает `ConfigFilesError`
  (unica#1877); доставка — ibcmd, скилл `1c-ibcmd-delivery`.
- **Большие деревья.** 0.15 убирает отказы по размеру ответов страницами и
  снимками на диске; зонтик #1119 (нагрузка больших конфигураций) открыт,
  admission-порог большого репозитория проверять живьём.
- **`extensions.list`/`pull`** — открытые #1797/#1798; серверной базе для
  IBCMD нужен `infobases.origin.dbms` (диагностика — #1103). Подсистемы
  основной конфигурации на файловой базе смотреть `execute_code` через 1c-db.
- **Запись тела с BOM даёт двойной BOM.** `code.replace`/`code.insert`
  дописывают свой BOM поверх уже стоящего в теле: файл получает
  `EF BB BF ×2`, модуль перестаёт компилироваться, любой вызов в такой
  модуль вешает канал до отстрела по таймауту. `unica.check` при
  несобранных диагностиках может отчитаться зелёным — компиляцию
  доказывать живой загрузкой. Лечение: повторный `unica.apply` с телом без
  ведущего BOM.

## Траблшутинг

**Сервер не стартует.** `unica --help` отвечает не `0.15.0-rc.5` — смотреть
лаунчер и `runtimes/unica`: пустой каталог означает, что артефакт не
докачан; прогрев — `unica-bootstrap prefetch --plugin-root <каталог
установки>`. `.partial` в `runtimes` — след оборванной закачки.

**Сервер жив, первый вызов провайдера — `provider_unavailable`.**
Разошлись артефакты, не handshake: скилл `1c-unica-artifacts`, `/1c-doctor`
назовёт недостающий артефакт и версию.

**Handshake без хоста:**

```bash
printf '%s\n' \
  '{"jsonrpc":"2.0","id":1,"method":"initialize","params":{"protocolVersion":"2025-11-25","capabilities":{},"clientInfo":{"name":"probe","version":"0"}}}' \
  '{"jsonrpc":"2.0","id":2,"method":"tools/list","params":{}}' | unica mcp
```

Ожидание — `serverInfo 0.15.0-rc.5` и 11 инструментов.

## Работа в git-ворктри

Воркспейс фиксируется при старте MCP: `cwd` сервера — корень проекта,
`cwd` вызова его не переключает. Второй копии — своя сессия и своя база;
владелец файловой базы и проекция конфига — скилл `1c-unica-worktree`.
Гейты контура — host-плагин `dsh-1c-contour`, отдельной разводки в проекте
нет.
