# Артефакты рантайма Unica: манифест, кэш, provider_unavailable

Симптом: после обновления юники диагностика BSL отвечает `provider_unavailable`,
пока в глобальном кэше нет требуемого артефакта. Лечение — прогрев штатной
командой или перенос из копии кэша на той же машине. Разовый чек рассинхрона —
`/1c-doctor` (сверка манифеста с кэшем артефактов).

Контракт 0.15 (0.15.0-rc.5, манифест schema 2): `unica 0.15.0-rc.5`,
`v8-runner 0.15.3`, `bsl-analyzer 0.2.86`. `rlm-tools-bsl` в манифесте rc.5
нет — не требовать и не искать.

Установка одна на машину: каталог плагина — `~/.local/share/unica/<версия>/`
(например `~/.local/share/unica/0.15.0-rc.5/`), кэш артефактов —
`~/.local/share/unica/runtimes`, лаунчер — `~/.local/bin/unica`
(`UNICA_GLOBAL_ROOT`, `UNICA_GLOBAL_VERSION`). Корень кэша переопределяет
`UNICA_RUNTIME_CACHE_DIR`.

## Как Unica резолвит артефакты (0.15)

- Контракт — `runtime-manifest.json` в каталоге установленной версии
  плагина (`~/.local/share/unica/<версия>/`): `artifacts` → имя → `version`
  и `targets.<платформа>` → `asset.sha256` + `files[]` (относительный путь
  и sha256 каждого файла).
- Кэш —
  `~/.local/share/unica/runtimes/<имя>/<версия>--<sha256>/<платформа>/`;
  маркер завершённости — `.ready.json` (artifact, version, target,
  assetSha256). Суффикс каталога — ровно `asset.sha256` из манифеста.
- Резолв строгий по версии из манифеста: артефакт другой версии означает
  «артефакта нет».
  Провайдер сам не докачивает, не откатывается и из чужих кэшей не берёт.
- Сервер при этом жив: handshake, tools/list, ping — всё зелёное. Провал
  всплывает только на первом вызове провайдера, поэтому после обновления
  юники его не видно до первой диагностики.

## Симптомы

- `bsl_diagnostics`/`bsl_index` в статусе вечно `stale`, файлов под ними
  не появляется.
- Вызов провайдера отвечает `provider_unavailable`, «BSL analysis did not
  complete, so the module is unproven».
- В логах демона: «bsl-analyzer is not bundled in this workspace» и
  «could not locate Unica plugin root for bsl-analyzer MCP adapter
  lookup».

## Диагноз по шагам

1. Версия установки — `~/.local/bin/unica --help` (первая строка вида
   `unica 0.15.0-rc.5`); каталог плагина — `ls ~/.local/share/unica/`.
2. Что требует манифест — `~/.local/share/unica/<версия>/runtime-manifest.json`:
   `artifacts.<имя>.version` и `targets.<платформа>.asset.sha256`.
3. Что лежит в кэше — `ls ~/.local/share/unica/runtimes/<имя>/`.
   Каталога `<версия>--<sha256>` нет — диагноз подтверждён.
4. `.partial` в корне кэша (`~/.local/share/unica/runtimes/.partial/<имя>`) —
   след начавшейся и оборванной закачки; на закрытых стендах типичная
   причина — недоступность github releases (повторные попытки юники молча
   падают так же).

## Лечение: prefetch или перенос из копии кэша

Первый ход — прогрев штатной командой бутстрапа: она сверяет манифест с
кэшем и докачивает недостающее.

```bash
PLUGIN_ROOT="${UNICA_GLOBAL_ROOT:-$HOME/.local/share/unica}/0.15.0-rc.5"
"$PLUGIN_ROOT/bootstrap/bin/linux-x64/unica-bootstrap" prefetch --plugin-root "$PLUGIN_ROOT"
```

Каталог `bootstrap/bin/<платформа>/` — по хосту: `linux-x64`, `darwin-arm64`,
`win-x64` (на Windows бинарь `unica-bootstrap.exe`).

Артефакт требуемой версии часто уже на машине — в копии кэша той же версии
(архив, вторая учётная запись, прежняя установка). Перенос легален после
сверки с манифестом. **Главное: `asset.sha256` манифеста — хеш исходного
артефакта с github (tar.gz или бинарь), НЕ распакованного файла.** Для
raw-бинарей работает `sha256sum`; для unpack-артефактов (tar.gz —
v8-runner) сверка распакованного файла всегда даст «расхождение» — это не
повод отбраковать копию. Критерий легальности копии — поля `.ready.json`
каталога: `artifact`, `version`, `target`, `assetSha256` — обязаны совпасть
с манифестом.

```bash
VER=0.2.86                        # version из манифеста
SHA=<asset.sha256 целиком>        # из targets своей платформы (напр. linux-x64)
SRC="<копия кэша>/bsl-analyzer/${VER}--${SHA}"
#  raw-бинарь (bsl-analyzer): байт-сверка с манифестом возможна
sha256sum "$SRC/linux-x64/bsl-analyzer"
#  unpack-артефакт (v8-runner): sha манифеста — хеш tar.gz,
#  бинарь сверять бессмысленно; сверить .ready.json:
cat "$SRC/linux-x64/.ready.json"
DST="${UNICA_RUNTIME_CACHE_DIR:-$HOME/.local/share/unica/runtimes}/bsl-analyzer"
cp -r "$SRC" "$DST/"
test -x "$DST/${VER}--${SHA}/linux-x64/bsl-analyzer"
```

`.ready.json` приезжает вместе с каталогом; его поля обязаны совпадать с
манифестом — по ним unica признаёт артефакт завершённым. Рестарт сервера
не нужен: резолв происходит на очередной вызов провайдера. Старые версии в
кэше не мешают — не трогать. Повторный `prefetch` на машине с доступной
сетью — равноправный путь: появившийся каталог сверь с манифестом тем же
`sha256sum`.

## Грабли

- Пустой ответ провайдера ≠ «чисто»: `provider_unavailable` значит «анализ
  не выполнялся» (дух скилла `unica:code-diagnostics` — чистый ответ и
  неотработавший провайдер различимы). Не переписывай код по находкам,
  которых не было.
- `.partial` может остаться и после починки остальных артефактов — сам по
  себе не мешает (пересоздаётся при каждой неуспешной закачке), но это
  маркер того, что закачка на машине не работает: рассчитывай на перенос
  из копии кэша.
- После копии проверить `test -x` (и для unpack-артефактов — целостность
  файлов по `files[]` манифеста, маркер завершённости — совпадение полей
  `.ready.json`): без исполняемого бита провайдер падает уже на запуске
  бинаря. Напоминание: «расхождение» `sha256sum` распакованного файла с
  `asset.sha256` для tar.gz-артефактов — норма, не отбраковка (см. выше).
- При удалении прежней версии плагина демон НЕ умирает сам: перед сносом
  каталогов проверять `ps`/`lsof`.
- Артефакт-версии меняются вместе с плагином: после каждого обновления
  unica рассинхрон ожидаем. `/1c-doctor` назовёт недостающий артефакт и
  версию до первого `provider_unavailable`.
