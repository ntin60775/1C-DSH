# 1c-project-layout — топология каталогов 1С-проекта

Принцип: **каталог = source-set юники**. Топология и каркас `v8project.yaml`
создаются одним шагом, а не двумя рассинхронизирующимися. Дизайн и разводка
владельцев файлов — docs/PROJECT-LAYOUT-SKILL.md репо контура.

## Что делает скрипт

```bash
SKILL_DIR=.zcode/skills/1c-project-layout   # каталог скилла при вызове
python3 "$SKILL_DIR/scripts/scaffold.py" all \
  --dir <проект> --name <slug> \
  --kinds cf,cfe,epf,erf \
  --components tests-e2e,tools-mcp,docs \
  --remote git@github.com:<owner>/<repo>.git
```

Субкоманды (используй по отдельности для дооснащения):

- `structure` — обязательная топология: `src/{cf,cfe,epf,erf}`,
  `tests/e2e`, `tools` (служебные скрипты проекта), `vendor` (вендоренный
  внешний код); компоненты сверх неё (`tools/mcp` — когда нужен MCP
  `1c-db`, `docs` — по запросу, `kd2-rules` — файлы правил обмена КД 2,
  git-tracked), каталожные `AGENTS.md` в каждый каталог,
  корневой `AGENTS.md` с таблицей структуры, пустой `packagedef` в корне
  (маркер проекта для 1C Platform Tools в VS Code — без него расширение
  не распознаёт проект; в новых проектах пустой, существующий не трогать:
  бывает живым OneScript-дескриптором);
- `v8project` — каркас `v8project.yaml` (общая часть) + `v8project.local.yaml`
  с привязкой ИБ (`--ib-connection`; относительный `File=` в дефолте
  `File=build/ib` делается абсолютным от корня — гард onec_db под
  абсолютный путь) и закреплёнными
  знаниями деплоя (ibcmd для файловой базы из-за GTK, путь платформы
  каталогом без strict-пина). Полный контракт 0.15, назначение всех полей и
  регламент переезда со старого конфига — [references/v8project.md](references/v8project.md);
  разбор бинарного контейнера `.epf`/`.erf` и проверка собранного
  (маркеры элементов формы в бинарнике) —
  [references/epf-binary.md](references/epf-binary.md);
- `git` — `git init`, `.gitignore` (только дозапись недостающих строк),
  `.gitattributes` (политика CRLF/binary — без неё `unica.check` роняет
  `repositoryReady` первым коммитом), `--remote`;
- `e2e-baseline` — базовый e2e-набор приёмки контура в `tests/e2e`:
  самодостаточный test_contour_basics.py (фикстура с самоподъёмом канала
  `1c-db` в режиме анонимизации; живость, прогрев с токенами, число без
  токена, метаданные, валидатор ссылок; только чтение; без импортов из
  conftest — встаёт и в проект со своим conftest). Прогон —
  `run_e2e.sh [профиль] tests/e2e`; существующие файлы набора не трогаются
  без `--force`. Жизненный цикл: ставится на время приёмки контура и
  снимается `scaffold.py e2e-baseline --remove` — снимаются только файлы,
  совпадающие с шаблоном, правленый файл остаётся с WARN (`--force`
  снимает и его), свои тесты проекта не трогаются. Свои тесты проекта
  кладутся рядом.

Скрипт идемпотентен: существующее не перезаписывается без `--force`
(`.gitignore` — всегда только дозапись). `--dry-run` — показать план.
Корневой `AGENTS.md` не перезаписывается: если существует — таблица
структуры печатается в stdout для вставки агентом.

## Обязательный минимум и полный ритуал

Скилл регламентирует минимально допустимую топологию проекта контура.
Состав утверждён владельцем по эмпирике живых проектов контура
(детектор — `scaffold.py check --dir <проект>`, exit 1 = не
выполнен; doctor ретранслирует тем же детектором):

- `src/cf/`, `src/cfe/`, `src/epf/`, `src/erf/` — исходники всех видов;
- `tests/e2e/` — e2e-тесты контура (pytest): поведение, API, GUI;
- `tests/unit/` — юниты pytest (уровень логики, `execute_code`); канонное
  место юнитов, в минимум не входит — заводится с первыми юнитами;
- `tools/` — служебные скрипты и конфигурации проекта (вопрос «где хранить
  узкие скрипты» решён здесь; вендоренная поставка контура — не тут,
  она в `.zcode/1c/scripts`);
- `vendor/` — вендоренный внешний код (паки, тулкиты);
- `kd2-rules/` — файлы правил обмена «Конвертации данных» 2 (XML правил,
  zip-комплекты БСП); канонное место хранения, в минимум не входит —
  предлагается при бутстрапе и заводится, когда проект работает с
  правилами; git-tracked (каталожный AGENTS.md), путь идёт в `rules_dir`
  станции kd — `kd_register_project.py` подхватывает каталог сам;
- `v8project.yaml` — общий контракт юники; `v8project.local.yaml` — машинная
  привязка ИБ, платформа и исполнители (в git не попадает);
- `.gitignore` + `.gitattributes` — гигиена git (атрибуты закрывают
  `repositoryReady` первого коммита);
- `packagedef` — маркер 1C Platform Tools в VS Code;
- корневой `AGENTS.md` — входная точка агентов.

**Минимум отсутствует — навык срабатывает полноценно**: блок вопросов
оператору целиком (имя проекта, kinds, components, remote, ib-connection,
провайдер сборки),
потом `--dry-run` → план → запуск. Не дооснащать молча дефолтами и не
чинить отдельные файлы мимо ритуала: выбор структуры — это решение
владельца, а не угадывание агента. Минимум на месте — дооснащение
адресное по факту недостающего. Исключение — юнит-наследие omp-эпохи
(`tests/cfe`/`tests/epf` вместо `tests/e2e`): `check` опознаёт его
отдельной подсказкой, лечение — перенос покрытия и демонтаж
(`scripts/migrate_from_omp.py`, см. MIGRATION-FROM-OMP.md), не ритуал.

## build/out — артефакты сборки и прогона

`build/` вне git, но раскладка `build/out/` канонична. Верхний уровень
строгий, таксономия зеркалит `src/`; каталоги появляются с первыми
артефактами своего типа — пустой набор не заводится заранее:

- `cf/`, `cfe/`, `epf/`, `erf/` — поставляемые артефакты: конфигурация
  `.cf`, расширения `.cfe`, внешние обработки `.epf`, внешние отчёты
  `.erf`;
- `reports/` — выводы прогонов проектных раннеров: allure, cucumber, junit
  va/yax, yaxunit, логи va/yax, скриншоты прогонов; отчёты предыдущего
  прогона той же сцены сносить при следующем прогоне, доказательства
  приёмки живут в `docs`. Исключение — junit и артефакты контурного
  e2e-прогона (`run_e2e.sh`): они пишутся в корневой `test-results/`,
  оттуда их читают workflow — контракт, не переносится;
- `tmp/` — служебные артефакты сборки (проверочные экспорты,
  round-trip-каталоги, манифесты, журналы сборки): снос в том же заходе,
  на файлы из `tmp` ничто вне текущей сборки не ссылается.

Правила:

1. Имя артефакта — `<Имя>_<ГГГГ-ММ-ДД>[.<суффикс>].<ext>`; одно имя —
   одна версия, перезапись без смены даты запрещена.
2. Реестр хешей и размеров — вне `build/`: там, где на артефакт
   ссылаются (факты поставки, CHANGELOG).
3. Внутри type-каталога подкаталоги — на усмотрение агента.
4. Вне шести каталогов записи в `build/out/` не создаются; свалку в корне
   ловит doctor (WARN с перечнем), канонное имя обязан носить каталог —
   файл с именем `cf` тоже чужое.
5. Сборка `.cfe` пишет в `cfe/`, выгрузки прогонов — в `reports/`,
   проверочные каталоги — в `tmp/`; складывать артефакты в каталог по
   имени тикета — нарушение раскладки.

## Порядок

1. Определи вход: проект с нуля / ИБ есть, исходников нет (тогда выгрузка
   unica создаст `src/cf` — скелет докинет остальное) / дооснащение
   существующего. Идемпотентность покрывает все три.
2. Один блок вопросов оператору с дефолтами: имя проекта, kinds,
   components, remote. Доставка и сборка — ibcmd: блок `providers` в
   `v8project.yaml` вставляет агент сам — внешний контракт, scaffold его
   не пишет. На серверной ИБ — каркас `infobases.origin.dbms` в
   `v8project.local.yaml` (`kind`, `server`, `name`, `user`, `password`
   СУБД); файловой базе `dbms` не нужен.
3. `--dry-run` → покажи план → запуск.
4. Первый коммит атомарен: скелет + `v8project.yaml` + `v8project.local.yaml`
   вне git + `.gitignore` + `.gitattributes`.

## Что дальше (не этот навык)

- Контурные конфиги (`.zcode/1c/contour.json`, профили testpilot, разводка
  hooks+MCP, секция AGENTS.md между маркерами) — навык `1c-project-bootstrap`.
- Первый источник правды: ИБ есть → выгрузка в `src/cf` (`unica.run`,
  канон в `1c-contour`); с нуля → `build`. Расширения объявляются
  EXTENSION-source-set'ами по мере появления (скиллы юники `cfe-init`).
- Миграция omp-наследия (features/VAParams) — `scripts/migrate_from_omp.py`.

## Инварианты

1. Каталог = source-set: `path: .` у source-set — ошибка; каждое расширение
   — свой подкаталог `src/cfe/<Имя>` и свой source-set.
2. Каталожные `AGENTS.md` вместо `.gitkeep`: пустые каталоги трекаются в git
   и несут правила.
3. Корневой `AGENTS.md` принадлежит проекту: не перезаписывать, секцию
   контура не трогать.
4. `.gitignore` append-only у всех владельцев: layout — 1С-артефакты,
   `1c-project-bootstrap` — `.zcode`-строки.
5. Секреты (креды ИБ) — только в `v8project.local.yaml`; общий
   `v8project.yaml` кредов не содержит. Каркас пишет строку подключения в
   local-слой; `user`/`password` — отдельными полями там же. Креды инстансов
   1c-db — только в `.zcode/1c/db-instances.yaml`; оба файла вне git.
