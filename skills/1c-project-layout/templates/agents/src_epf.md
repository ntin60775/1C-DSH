# Каталог src/epf — исходники внешних обработок

XML-выгрузки внешних обработок. На каждую обработку — отдельный подкаталог.
Маршрут и канон разметки общие для класса внешних артефактов: внешние
отчёты (`.erf`, каталог `src/erf`) живут по тем же правилам.

## Правила
- Имя подкаталога = имя обработки.

## Маршрут работы
- Каркас новой обработки — файлами по скиллам юники `epf-init`/`erf-init`,
  раздел «Формат файлов»; источник канона разметки — спека внешней
  обработки юники.
- Правка существующих узлов — `unica.apply`; поверхность на внешних
  source-set'ах — по тексту `epf-init` (form-edit/form-events), живьём
  не проверена.
- Сборка и разбор — `$DSH_1C_ROOT/scripts/epf-load.sh` и `epf-dump.sh`
  (скилл `1c-ibcmd-delivery`); `unica.run op=make` — альтернатива той же
  сборки через раннер.

## Канон разметки формы
- Секция элементов формы — `<ChildItems>`; порядок верхнего уровня:
  AutoCommandBar → ChildItems → Attributes → Commands. `<Items>`
  конфигуратор грузит «мягко»: дерево молча отбрасывается, форма
  открывается пустым окном.
- UUID корневого XML и `Forms/Форма.xml` — разные; дубликат даёт молча
  неполный контейнер (диагноз — в `epf-binary.md`).
- Колонки ValueTable-реквизита формы — только примитивные типы;
  `cfg:CatalogRef.*` не резолвятся. Ссылочную колонку заменяй строкой-ключом;
  представление ссылки — `ПРЕДСТАВЛЕНИЕ()` в запросе.

## Проверка собранного
- «Собралось» не значит «дерево попало в бинарник»: наличие имён элементов
  формы проверяй разбором v8-контейнера — рецепт и диагноз дубликата UUID
  в скилле `1c-project-layout` — `references/epf-binary.md`.
