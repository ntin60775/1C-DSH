# Бинарный контейнер v8 (.epf/.erf): разбор и проверка собранного

Собранный внешний артефакт «формально собрался», но форма открывается
пустым окном: разметка элементов могла не попасть в бинарник. Рецепт
разбирает контейнер до блоков и ищет имена элементов формы в разжатом
содержимом — доказательство «дерево попало в бинарник» без запуска
клиента. Без зависимостей: python stdlib (`struct`, `re`, `zlib`).

## Формат контейнера

- Шапка 16 байт: поле 0 — смещение страницы `commit`
  (`0x7fffffff` — страницы нет); поле 4 — версия формата; поле 8 —
  служебный размер, числу записей TOC не равен на всех сборках — на
  него не опираться.
- TOC-страница стоит на смещении 16: ASCII-шапка
  `\r\n<size:08x> <alloc:08x> <next:08x> \r\n` — это шапка самой
  страницы, не запись. Число записей на странице — `size / 12`; записи
  — бинарные little-endian hex8-триплеты по 12 байт (start, end, next)
  сразу после шапки и указывают на блоки-дескрипторы. Многостраничный
  TOC связан полем `next` (страницы `cf`/`erf` с большим числом
  объектов); для внешних артефактов демо-пути страница одна.
- Блок — ASCII-шапка `\r\n<size:08x> <alloc:08x> <next:08x> \r\n`
  (31 байт) + данные. Следующая шапка стоит на `смещение + 31 + alloc`
  (`alloc` — размер страницы с добивкой, у дескрипторов обычно 512);
  поле `next` отлично от `0x7fffffff` только у страниц TOC.
- Свободная страница узнаётся по первому полю шапки `0x7fffffff`: в ней
  лежат устаревшие данные прежних сборок — маркеры там ложные, страницу
  пропускать.
- Данные блока двух сортов: несжатые (`size` = длина данных; блоки
  дескрипторов — метки времени, нули и utf-16 имя файла) и сжатые сырым
  deflate (`zlib.decompressobj(-15)`; `size` = длина сжатого потока).
  Содержимое сжатых блоков — сериализованный текст 1С в UTF-8 с BOM
  (разметка форм, модули); UTF-16 в контейнере — только имена файлов в
  дескрипторах. Литеральных XML-тегов в бинарнике нет.

## Рецепт: имена элементов формы в бинарнике

```python
import struct, re, zlib

PATH = "<путь-к-файлу.epf>"
MARKERS = ["<имя элемента>", "<имя обработчика>"]  # из исходника разметки формы

raw = open(PATH, "rb").read()
HEAD = re.compile(rb"\r\n([0-9a-f]{8}) ([0-9a-f]{8}) ([0-9a-f]{8}) \r\n")

toc = HEAD.match(raw, 16)
if not toc:
    raise SystemExit("TOC-шапка на смещении 16 не найдена — не контейнер v8 или оборван")
toc_size, toc_alloc, toc_next = (int(x, 16) for x in toc.groups())
records = []
page, n = 16, toc_size // 12
while n > 0:                                         # страницы TOC по полю next
    if page + 31 + n * 12 > len(raw):
        raise SystemExit("TOC-страница оборвана")
    body = raw[page + 31: page + 31 + n * 12]
    for i in range(n):
        records.append(struct.unpack("<III", body[12 * i: 12 * i + 12]))
    if toc_next >= 0x7fffffff:
        break
    nxt = HEAD.match(raw, toc_next)
    if not nxt:
        raise SystemExit("следующая страница TOC не найдена — контейнер оборван")
    page = toc_next
    toc_size, toc_alloc, toc_next = (int(x, 16) for x in nxt.groups())
    n = toc_size // 12

found = dict.fromkeys(MARKERS, False)
walked = deflated = plain = 0
pos = 16
while pos + 31 <= len(raw):
    head = HEAD.match(raw, pos)
    if not head:
        break                                        # хвост без шапки — стоп
    size, alloc, nxt = (int(x, 16) for x in head.groups())
    pos += 31 + alloc
    if size >= 0x7fffffff:
        continue                                     # свободная страница — старые данные
    blob = raw[pos - alloc: pos - alloc + size]      # данные с old+31 до old+31+size
    d = zlib.decompressobj(-15)
    try:
        data = d.decompress(blob)
        if not d.eof:
            print("deflate без eof — блок оборван, маркеры по нему ненадёжны")
        deflated += 1
    except zlib.error:
        data = blob
        plain += 1
    for w in MARKERS:
        if w.encode("utf-8") in data or w.encode("utf-16-le") in data:
            found[w] = True
    walked += 1

print(f"TOC: {len(records)} записей; блоков пройдено: {walked} (deflate {deflated}, plain {plain})")
print("имена элементов:", {w: ("есть" if ok else "нет") for w, ok in found.items()})
```

Чтение результата: имя элемента «нет» при живом маркере в исходнике
разметки — дерево в бинарник не попало, форма откроется пустым окном.
Поиск ведётся по несжатым и разжатым блокам; попадание имени в
дескрипторе (utf-16 имя файла) — не доказательство дерева, сравнивай с
набором имён из исходника. Проверка маркера по свободным страницам
отключена (устаревшие данные прежних сборок дают ложное «есть»).

## Диагноз дубликата UUID

UUID корневого XML обработки и `Forms/Форма.xml` различаются; дубликат
даёт молча неполный контейнер: TOC короче ожидаемого (7 файлов вместо
8+), в дескрипторе отсутствует блок данных `ObjectId.1`; рантайм —
«Ошибка подключения внешних метаданных: Ошибка формата потока» на
`ВнешниеОбработки.Создать`; обратный dump обрывается на строке «Формат:
Иерархический» без «Выгрузка завершена». Разбор битого контейнера —
тем же рецептом; собрать битый образец — `epf-load.sh` из копии
выгрузки с продублированным UUID.

## Границы проверенности

- Рецепт и формат сверены на образцах контейнеров сборки 8.3.27 и на
  корпусе парковых контейнеров (`cf`/`cfe`/`epf`/`erf`): модель
  «записи = размер TOC-страницы / 12», шаг цепочки `+ 31 + alloc`,
  кодировка контента UTF-8 BOM подтверждены на всех проверенных
  образцах.
- Разбор битого контейнера (дубликат UUID) выполнен на реальном
  артефакте при диагнозе; битый образец рецептом при отгрузке не
  воспроизводился.
- Сверка списка файлов с валидным контейнером другой сборки —
  контрольный приём, не ритуал; рецепт список имён файлов не печатает.
- Связка с каноном сборки и маршрутом работы — шаблоны AGENTS каталогов
  `src/epf` и `src/erf` (скэфолд 1c-project-layout); сборка/разбор —
  `epf-load.sh`/`epf-dump.sh` (скилл `1c-ibcmd-delivery`).
