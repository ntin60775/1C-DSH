# Бинарный контейнер v8 (.epf/.erf): разбор и проверка собранного

Собранный внешний артефакт «формально собрался», но форма открывается
пустым окном: разметка элементов могла не попасть в бинарник. Рецепт
разбирает контейнер до блоков и ищет маркеры имён элементов формы в
разжатом содержимом — доказательство «дерево попало в бинарник» без
запуска клиента. Без зависимостей: python stdlib (`struct`, `re`,
`zlib`).

## Формат контейнера

- Шапка 16 байт: `ff ff ff 7f | 00 02 00 00 | int32 LE — счётчик записей
  TOC (смещение 8) | 00 00 00 00`.
- Верхний TOC сразу после шапки: первая запись — ASCII-триплет hex8
  `\r\n%08x %08x %08x \r\n` (start, end, next), остальные `счётчик − 1`
  записей — бинарные little-endian hex8-триплеты по 12 байт (start, end,
  next). Верхний TOC описывает TOC-блок и блоки-дескрипторы объектов;
  полный состав блоков им не ограничен.
- Каждый блок — ASCII-шапка `\r\n<size:08x> <alloc:08x> 7fffffff \r\n`
  (ровно 31 байт) + данные длиной `size`; шапки идут цепочкой по всему
  файлу.
- Данные блока двух сортов: несжатые (`size` = длина данных; блоки
  дескрипторов — хеш-ID и utf-16 строки вида «version») и сжатые сырым
  deflate (`zlib.decompressobj(-15)`; `size` = длина сжатого потока;
  разжатое — вложенный контейнер с теми же ASCII-шапками, в нём —
  тексты модулей и разметка форм в utf-16). Другие форматы сжатия в
  образцах не встречались; при первом отказе разжатия проверить wbits
  (`15`, `47`), отличия от апстримных сборок — «не проверено».

## Рецепт: маркеры формы в бинарнике

```python
import struct, re, zlib

PATH = "<файл.epf|.erf>"
MARKERS = ["<имя элемента>", "<имя обработчика>"]  # из исходника разметки формы; литеральных XML-тегов в бинарнике нет

raw = open(PATH, "rb").read()
count = struct.unpack("<I", raw[8:12])[0]            # счётчик TOC, смещение 8
toc = re.match(rb"\r\n([0-9a-f]{8}) ([0-9a-f]{8}) ([0-9a-f]{8}) \r\n", raw[16:])
entries = [tuple(int(x, 16) for x in toc.groups())]
off = 16 + toc.end()
for i in range(count - 1):                           # остальные записи — бинарные LE-триплеты
    entries.append(struct.unpack("<III", raw[off + 12 * i: off + 12 * i + 12]))
if len(entries) != count:
    print(f"TOC неполный: {len(entries)} записей против счётчика {count}")

HEAD = re.compile(rb"\r\n([0-9a-f]{8}) ([0-9a-f]{8}) ([0-9a-f]{8}) \r\n")
found = dict.fromkeys(MARKERS, False)
blocks = 0
for m in HEAD.finditer(raw):                         # блоки верхнего уровня; сжатые разжимаются и обыскиваются
    size = int(m.group(1), 16)
    data = raw[m.end(): m.end() + size]
    try:                                             # сжатый блок — сырой deflate
        data = zlib.decompressobj(-15).decompress(data)
    except zlib.error:
        pass                                         # несжатый — данные как есть
    for w in MARKERS:
        if w.encode("utf-16-le") in data or w.encode("utf-8") in data:
            found[w] = True
    blocks += 1

print(f"TOC: {count} записей; блоков пройдено: {blocks}")
print("маркеры формы:", {w: ("есть" if ok else "НЕТ") for w, ok in found.items()})
```

Чтение результата: «маркеры: НЕТ» при непустом исходнике разметки —
дерево в бинарник не попало, форма откроется пустым окном; пересборка
до прогона бессмысленна. «TOC неполный» при здоровом счётчике — признак
обрыва контейнера (см. диагноз ниже).

## Диагноз дубликата UUID

Корневой XML обработки и `Forms/Форма.xml` обязаны иметь разные UUID.
Дубликат даёт молча неполный контейнер: TOC короче ожидаемого (7 файлов
вместо 8+), в дескрипторе отсутствует блок данных `ObjectId.1`; runtime
— «Ошибка подключения внешних метаданных: Ошибка формата потока» на
`ВнешниеОбработки.Создать`; обратный dump обрывается на строке «Формат:
Иерархический» без «Выгрузка завершена». Разбор битого контейнера — тем
же рецептом.

## Границы проверенности

- Рецепт прогнан на двух образцах: несжатый контейнер (TOC 7 записей ==
  счётчик, блоки без сжатия) и контейнер сборки 8.3.27 (TOC 8 == счётчик,
  контент-блоки deflate — разжатое содержимое несёт маркеры имён
  элементов формы).
- Разбор битого контейнера (дубликат UUID) выполнен на реальном
  артефакте при диагнозе; воспроизведение битого образца при отгрузке
  рецепта не проводилось.
- Связка с каноном сборки и маршрутом работы — шаблон AGENTS каталога
  `src/epf` (скэфолд 1c-project-layout); сборка/разбор — `epf-load.sh`/
  `epf-dump.sh` (скилл 1c-ibcmd-delivery).
