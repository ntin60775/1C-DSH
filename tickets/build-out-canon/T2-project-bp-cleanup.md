# Т2 «Уборка build/out project-bp»

Оценка: ~60 мин. Блокеры: приёмка Т1 (правило канона — оракул целевого
состояния); завершённость тикета 50-1 project-bp — артефакты 50-1 ещё
пересобираются параллельной сессией (критик 07.11: `СС_РаспознованиеPDF`
перезаписан при том же имени), признак незавершённости — хеши меняются
между инвентаризацией и переносом, тогда стоп.

## Зачем

Корень `build/out` project-bp — свалка: 17 `va*.log`, 8 `yax*.log`,
`va-data`, `verification`, `screenshots`, `allure`, `cucumber`, `yaxunit`,
`junit`, `06-1-acceptance`, `pilot-50`, `probe_t30.py`, `va-shot.png` —
вперемешку с товарными `.cfe` в `cfe/` (`va-shot.png` и прочие сироты —
в корне `build/`, вне скоупа). Пилотные артефакты 50-1 лежат мимо
типового каталога, вывод прогонов целит мимо правила
(`tools/VAParams.template.json`: `junit`/`screenshots`/`allure`/`cucumber`
→ корень `build/out/*`). После приёмки Т1 правило канона даёт целевое
состояние. Спека: [docs/plans/build-out-canon.md](../../docs/plans/build-out-canon.md).

## Что делается

Работа в дереве project-bp (`/home/prog7/home/dev/work/project-bp`), всё —
абсолютными путями:

1. Инвентаризация: полный список целей сноса с классификацией (логи —
   NORMAL, `*.log` не SAFE; каталоги отчётов прогонов — NORMAL) плюс
   снятие sha256 артефактов `pilot-50/` — стартовое значение для сверки
   стабильности (см. Блокеры).
2. Перенос артефактов: `build/out/pilot-50/*.cfe` → `build/out/cfe/`;
   sha256 каждого файла до и после переноса совпадают; фактические хеши
   фиксируются в отчёте уборки; сверка с носителем фактов 50-1 — по его
   фактическому состоянию на момент исполнения, захардкоженных хешей нет.
3. Авторевью субагентом (read-only): полный список целей + команда сноса +
   счётчик (NORMAL > 7) — вопрос «безопасно ли это удаление». Вердикт
   «безопасно» с обоснованием → снос; «рискованно»/«не уверен» → стоп,
   список оператору.
4. Снос подтверждённых целей; сомнительные (`06-1-acceptance/`) не сносятся
   без проверки, куда дублируются их доказательства (факты приёмки живут
   в docs — сверить, иначе список оператору).
5. Перенацеливание `tools/VAParams.template.json`: `junit`, `screenshots`,
   `allure`, `cucumber` → под `build/out/reports/`; живой прогон e2e не
   требуется, артефакт доказательства — сами конфиги.
6. Контрольная раскладка: в корне `build/out` нет файлов и нет каталогов
   вне шести канонических (полный набор из шести не обязателен — каталоги
   появляются с первыми артефактами своего типа).
7. Не трогается: `build/ib` и сервисные каталоги стенда (`log`, `logs`,
   `ibsrv-data`, `temp`, `hash-storages`, `tools`); корень `build/` вне
   скоупа — находки-сироты (`va-shot.png`, `va-params.launch.json`) в отчёт
   уборки, решение оператора.

## Демо-путь

`find build/out -maxdepth 1` не показывает ни одного файла или чужого
каталога в корне; sha256 перенесённых `.cfe` до и после совпали и
зафиксированы в отчёте; конфиги прогонов указывают в `reports/`.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: `sha256sum` до и после переноса. Ожидание: значения попарно
   равны, зафиксированы в отчёте уборки. На базе артефакты лежат в
   `pilot-50/` — критерий падает.
2. Артефакт: `find build/out -maxdepth 1`. Ожидание: в корне нет файлов
   и нет каталогов вне `cf`, `cfe`, `epf`, `erf`, `reports`, `tmp`. На
   базе — свалка.
3. Артефакт: `tools/VAParams.template.json`. Ожидание: пути вывода под
   `build/out/reports/`. На базе — корень `build/out/*`.
4. Артефакт: вердикт авторевью-субагента до сноса. Ожидание: «безопасно»
   с обоснованием либо эскалация оператору; неуверенные цели не снесены.
