# Т1 «Канон build/out в контуре»

Оценка: ~90 мин. Блокеры: нет.

## Зачем

`build/out` не регулируется никем в каноне: `1c-project-layout` закрепляет
только `src/{cf,cfe,epf,erf}` (обязательный минимум: scaffold check,
doctor), `build/ib` — канон тест-контура, весь `build/` gitignored. Агенты
изобретают каталоги по имени тикета: сессия sess_c902e02d (50-1 project-bp)
сложила пилотные `.cfe` в `build/out/pilot-50/` при живом прецеденте
`build/out/cfe/<Имя>_<дата>.cfe` в том же проекте. Правило живёт только в
скилле — агент его не открывает, поэтому нужна и всегда-загружаемая строка,
и doctor-WARN. Спека: [docs/plans/build-out-canon.md](../../docs/plans/build-out-canon.md).

## Что делается

Правило канона — раздел «Правило» спеки: шесть каталогов
`cf/cfe/epf/erf/reports/tmp` (зеркало `src/{cf,cfe,epf,erf}` + отчёты
прогонов + служебное), именование `<Имя>_<ГГГГ-ММ-ДД>[.<суффикс>].<ext>`,
одно имя = одна версия, tmp сносится в том же заходе, хеш-реестр не в
`build/`. Посадка:

- `skills/1c-project-layout/SKILL.md` — новый подраздел «build/out:
  артефакты сборки и прогона», правило целиком; текст по нормам канона
  (happy path, без истории сессии, имена каталожных констант из конфигов);
- `docs/PROJECT-LAYOUT-SKILL.md` — строка таблицы `build/` дополняется
  раскладкой `out` (сейчас: только `build/ib`, дампы `*.dt`, `build/tools/`);
- `templates/agents-section.md` — одна строка-правило (шесть каталогов +
  именование + tmp-снос), между маркерами BEGIN/END 1C CONTOUR;
- `scripts/doctor.py` — проверка: существующий `build/out` содержит
  в корне файлы/каталоги вне шести каталогов → WARN с перечнем (длинный
  перечень усечь), `build/out` отсутствует или чист — молчание; FAIL
  не делать (каталог опционален);
- тест doctor в `tests/` — фикстура проекта со свалкой и фикстура с шестью
  каталогами, прогон хуком-процессом по канону проверок репо;
- `skills/1c-ibcmd-delivery/SKILL.md` — раздел «Сборка `.cfe` из базы —
  `config save`» называет цель `build/out/cfe/`;
- `skills/1c-test-contour/SKILL.md` — раздел о прогонах va/yax: логи,
  отчёты, скриншоты → `build/out/reports/`.

vendor-скиллы юники не правятся — юника следует канону через
agents-section. После правки доков — сопровождение KB: `gitmark.py index`,
`gitmark.py lint --strict`.

## Демо-путь

doctor на проекте со свалкой в `build/out` печатает WARN с перечнем
чужих файлов; на чистом дереве — молчит. Греп «build/out» по пяти
посадочным местам возвращает правило, на базовом коммите — пусто.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тест doctor (фикстуры «свалка» / «чистое `build/out`»).
   Ожидание: свалка → WARN с перечнем, чистое → молчание. На базе
   WARN-логики нет — падает.
2. Артефакт: греп `build/out` в `templates/agents-section.md`.
   Ожидание: строка правила с шестью каталогами. На базе пусто — падает.
3. Артефакт: подраздел в `skills/1c-project-layout/SKILL.md`.
   Ожидание: правило целиком (шесть каталогов, именование с датой,
   tmp-снос в заходе, хеш-реестр не в `build/`);
   `lint_skill_frontmatter.py` зелёный. На базе подраздела нет — падает.
4. Артефакт: грепы в `1c-ibcmd-delivery` (`build/out/cfe`) и
   `1c-test-contour` (`build/out/reports`). Ожидание: непусты. На базе
   пусты — падает.
5. Артефакт: строка `build/` в таблице `docs/PROJECT-LAYOUT-SKILL.md`.
   Ожидание: описывает раскладку `out`. На базе — только `ib`/дампы/`tools`.
6. Артефакт: прогон всех `tests/test_*.py`. Ожидание: зелёный, новый
   тест doctor включён.

## Блокирующие рёбра

Нет: тикет ведётся от базового коммита репо контура.
