# Т2 «Канон: границы execute-фрагмента в 1c-test-contour»

Оценка: ~40 мин. Блокеры: Т1.

## Зачем

Зазор P1 ишью 58: границ синтаксиса фрагмента в каноне нет —
`skills/1c-test-contour/SKILL.md` документирует только границы
канала-токенизации; читатель ожидает «фрагмент = обычный BSL» без
оснований. Секция закрывает зазор по матрице Т1: что проверено, что
запрещено, как обнаружить молчаливое частичное исполнение.

## Что делается

- Секция «Границы execute-фрагмента» в `skills/1c-test-contour/SKILL.md`
  рядом с существующими границами окружения Выполнить в «Канон юнита»
  (там живёт правило резолва имён в контексте формы) — один кусок знания
  об одном окружении, со связкой к разделу оракулов:
  - матрица проверенного из Т1 (работает / падает / падает молча — по
    каждой конструкции, две среды);
  - правила — от матрицы, не пре-матричные: запрещаются только классы,
    которые матрица показала падающими или молчащими; работающее не
    запрещается. Живой пример фрагмента в скилле (многострочный Если с
    ВызватьИсключением) сверяется с новыми правилами: противоречие —
    пример правится или правило уточняется по матрице;
  - правило счётчика: фрагмент с ветвлением возвращает число исполненных
    веток (связка с числовым протоколом) — молчаливое частичное
    исполнение обнаруживается сверкой суммы, а не зелёным статусом;
  - граница применимости из Т1, без имён сред: «воспроизводится на обеих
    средах» либо «воспроизводится на одной из двух сред»;
    неподтверждённые наблюдения — с пометкой «не проверено», без даты
    и автора (канон текстов: скилл — знание без хроники).
- Ссылка на границу из докстрингов onec_db не дублируется: скилл —
  единственный носитель матрицы.
- Формулировки — императив, без имён проектов и сред (гигиена имён;
  формальная проверка `.forbidden-names.txt` имена стендов не ловит —
  обезличивание руками, не грепом).

## Демо-путь

Читатель скилла по секции пишет фрагмент под матрицу: запрещённые классы
не использует, ветвление с оракулом-счётчиком; попытка конструкции из
запрещённого класса объясняется секцией до прогона.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: grep «Границы execute-фрагмента» по
   `skills/1c-test-contour/SKILL.md`. Ожидание: секция есть. На базовом
   дереве — падает.
2. Артефакт: grep правила счётчика в секции. Ожидание: правило названо
   классом явления, связано с числовым протоколом. На базовом дереве —
   падает.
3. Артефакт: `python3 scripts/lint_skill_frontmatter.py`. Ожидание:
   15/15.
4. Артефакт: проверка имён из `.forbidden-names.txt` по рецепту AGENTS.md.
   Ожидание: чисто.
5. Артефакт: сверка формулировок с матрицей Т1. Ожидание: каждая граница
   секции подтверждена строкой вывода прогона Т1; запрещён только класс,
   показанный падающим или молчащим; живой пример фрагмента скилла
   согласован с правилами; непроверенное помечено «не проверено».

## Границы

- Носители сверх 1c-test-contour (1c-db-data, agents-section, workflows)
  в тикет не входят — слой канала и анонимайзера не про синтаксис
  (решение спеки).
- Правило счётчика дополняет числовой протокол, не заменяет его;
  раздел оракулов пересматривается только в точке связи с секцией.
- СтрДублировать в границы execute не входит — функции нет в языке;
  красная проба остаётся контролем диагностики, в матрицу секции не
  записывается.
