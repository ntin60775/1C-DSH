# Т4 «Кандидат апстрим-репорта в mcp-toolkit»

Оценка: ~30 мин. Блокеры: Т1.

## Зачем

P2 ишью 58 («либо исполнять в полном BSL, либо fail-loud диагностика»)
исполняется только в апстриме: epf и прокси — GPL, правки вендора
запрещены, канал — репорт в mcp-toolkit. Дисциплина апстримов: отправляет
владелец, основная сессия по подтверждению. Юнит готовит черновик с
числовым протоколом — репорт, который апстрим воспроизводит без нашего
окружения.

## Что делается

- `tickets/execute-fragment-limits/upstream-report-draft.md` (пуля снята
  по «Границам» — см. «Решение» в конце файла):
  - минимальный reproduction из матрицы Т1 (наименьший фрагмент,
    повторяющий отказ, — не владельческий тест целиком; проба
    СтрДублировать в reproduction не входит — функции нет в языке,
    апстрим закроет как невалид);
  - числовой оракул: ожидание против факта по каждой пробе (число,
    текст ошибки, номер строки epf);
  - окружение: версия тулкита (1.10.0 ca14a98), платформа 8.3.27.1859,
    режим совместимости, вердикт носителя по двум средам; имена сред
    обезличены (внутренние имена стендов наружу не идут —
    `.forbidden-names.txt` их не ловит, обезличивание руками);
  - сверка с исходником: указание, что `ВыполнитьКод` исполняет через
    `Выполнить(Код)`, и требование P2 в терминах апстрима (fail-loud на
    неподдержанную конструкцию либо исполнение в полном BSL).
- Язык черновика — как договаривается владелец (русский черновик, перевод
  — на отправке).

## Демо-путь

Черновик читается отдельно от контура: reproduction + оракул + версии
достаточны для открытия ишью в mcp-toolkit без доступа к нашим базам.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: файл черновика существует, содержит reproduction, оракул и
   версии. Ожидание: три раздела на месте. На базовом дереве файла нет —
   падает.
2. Артефакт: сверка reproduction с матрицей Т1. Ожидание: каждый факт
   черновика подтверждён строкой вывода прогона; ничего сверх матрицы;
   СтрДублировать в reproduction нет.
3. Артефакт: grep имён из `.forbidden-names.txt` по черновику + осмотр
   имён сред. Ожидание: чисто; имена стендов обезличены — репорт уходит
   наружу.

## Границы

- Отправка репорта, диалог с апстримом, закрытие ишью 58 — вне юнита,
  слово оператора.
- Репорт не заводится, если матрица Т1 не воспроизвела отказ: вместо
  репорта — наблюдение владельца остаётся с пометкой «не проверено»
  (решение в Т2); условие отражено в пункте «Готово» 4 спеки.

## Решение — репорт не заведён (06.11)

Условие из «Границ» сработало: матрица Т1 не воспроизвела ни один отказ
владельца (пробы — синтетические аналоги, фрагменты владельца не
исполнялись). Оба варианта отступа цикла `Пока` (таб, пробелы) и
`Для`-цикл зелёные на обеих средах; ступени вложенного `Если` 3 уровня
отдали счётчик 1; на синтетических ступенях молчаливого `-1` не было;
`СтрДублировать` остаётся ожидаемо-красным контролем диагностики — не
граница execute, в reproduction не входит. Факты — в
[T1-probe-matrix.md](T1-probe-matrix.md), «Выводы чистых прогонов (К2)»
и «Следствие для Т2–Т4». Файл черновика `upstream-report-draft.md` не
создан; критерии приёмки (пункты 1–3 тикета) сняты по условию «Границ»,
не провалены — их носителя нет; разрешение условного исхода — «Границы»
тикета и пункт «Готово» 4 спеки. Приёмка тикета — слово оператора.

Наблюдения владельца в каноне помечены «не проверено»: в секции
«Границы execute-фрагмента» скилла 1c-test-contour они записаны без даты
и автора, с формулировкой «на двух средах не воспроизведены; условия их
проб неизвестны (версия epf, канал)».

Тема для апстрима возвращается в работу только при появлении
воспроизводимого отказа: тогда заводится новый заход по этому тикету с
собственным протоколом проб — формат оракула и версии окружения
(тулкит 1.10.0 ca14a98, платформа, compat) берутся из матрицы Т1.
Отправка, диалог с апстримом и закрытие ишью 58 — вне юнита, см.
«Границы».
