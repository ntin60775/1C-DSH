# Т1 «Диагностическая матрица проб execute_code»

Оценка: ~60 мин. Блокеры: нет.

## Зачем

Причина из ишью 58 (ВычислитьВыражение) противоречит исходникам тулкита:
execute_code идёт через `Выполнить(Код)` (клон
`~/home/dev/contrib/clones/1c-mcp-toolkit`, тег 1.10.0, строка 3969 модуля
формы — совпадает с номером строки в ошибке из ишью), платдок 8.3.27.1859
операторных ограничений Выполнить не содержит, СтрДублировать в языке нет
(красная проба владельца — корректное поведение платформы), СтрШаблон
(8.3.6) работает живьём. Два отказа владельца (цикл, молчаливый −1 во
вложенных Если) статикой не объясняются — механику даёт только живая
матрица. Матрица — носитель формулировок Т2–Т4.

## Что делается

- Скрипт проб `tickets/execute-fragment-limits/probe_execute_limits.py`
  (клиент onec_db stdlib к живому 1c-db, url из contour-конфига проекта;
  каждая проба — отдельный вызов execute, число или текст ошибки в выводе).
- Состав проб (на каждой среде):
  1. владельческие: цикл Пока с таб-отступом, тот же с пробелами,
     `Результат = СтрДублировать("а", 5);` — ожидаемо-красный контроль
     (функции нет в языке: проба ловит не границу execute, а корректную
     диагностику платформы; отклонение = дефект диагностики канала),
     контроль `Результат = СтрДлина("ааа");`;
  2. дискриминаторы: однострочный `Если Истина Тогда Результат = 2; КонецЕсли;`;
     многострочный Если 3 уровня со счётчиком в двух ступенях — ступень А
     с тривиальными условиями (`Если Истина Тогда …`), ступень Б с
     условиями-вызовами глобальных функций (`Если СтрДлина("а") = 1
     Тогда …`; конструкция `Свойство(…)` из ранней редакции не пробуется:
     глобальной функции Свойство в языке нет — падала бы компиляцией
     целиком, как контроль СтрДублировать; контекст формы на серверной
     ветке недоступен — ВыполнитьКод объявлена &НаСервереБезКонтекста,
     клон 1.10.0, Module.bsl:3963); переменные — с уникальным префиксом
     проб (`Е2ЕМ1`…), при молчании обеих ступеней — отдельная проба с
     «естественными» именами владельца (`Е2ЕОчки`); Для-цикл со счётчиком (ожидание 3);
     СтрШаблон-контроль глобальных функций (ожидание «3|3»); заведомая
     синтаксическая ошибка (`Результат = (();`) — сверка номера строки
     epf в тексте ошибки с клоном;
  3. базовые: `Результат = 1;`.
- Прогон на тест-ИБ project-bp (стенд поднять `start_1c_db.sh`) и
  контроль — на демо erp-demo. Фрагменты вычислительные, без записей
  данных; анонимайзер не отключается.
- Стенды погасить тем же заходом (правило «сервисы на время работы»).

## Демо-путь

Матрица в выводе прогона: два столбца сред, по каждой пробе число или
текст ошибки; видно, воспроизводится ли отказ владельца и на какой
среде.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: скрипт проб существует и исполняется против живого 1c-db.
   Ожидание: вывод содержит по каждой пробе число либо текст ошибки.
   На базовом дереве скрипта нет — падает.
2. Артефакт: вывод прогона на project-bp и на демо приложен в тикете.
   Ожидание: две среды, различимый ответ по дискриминаторам (число либо
   текст ошибки с номером строки epf).
3. Артефакт: проба заведомой синтаксической ошибки в выводе прогона.
   Ожидание: номер строки epf в тексте ошибки указывает на
   `Выполнить(Код)` модуля формы (сверка с клоном) — подтверждение пути
   исполнения.
4. Артефакт: вывод прогона (тот же артефакт, что в К1–К3). Ожидание:
   проба СтрДублировать красная с «не определена» на обеих средах —
   контроль диагностики сработал как ожидалось; отклонение — дефект,
   фиксируется в матрице.
5. Артефакт: проба стендов после гашения в приложенном протоколе
   (ss/nc по портам из contour-конфига, выполнена в том же заходе).
   Ожидание: порты не слушают — стенды погашены.
6. Артефакт: вывод прогона без `Usr=`/`Pwd=` и без записей в базы
   (фрагменты вычислительные). Ожидание: чисто.

## Границы

- Скрипт — диагностический артефакт юнита в tickets/, не поставка:
  в скиллы и deploy.json не входит.
- Бисект версии epf (1.9.0 против 1.10.0) в тикет не входит: заказывается
  отдельно, если матрица воспроизведёт отказ и потребуется локализация
  версии.
- Записи данных в базы, работа с ЖР, GUI — вне тикета.

Помеха: прокси project-bp, поднятый до захода, погас между прогонами

Отказы владельца из ишью 58 НЕ воспроизвелись:

  компиляции … {<Неизвестный модуль>(1,15)}: Ошибка в выражении` —

Диагностика ошибки из двух звеньев: внешняя — строка epf
(`Форма(3969)`), внутренняя фигурная — позиция во фрагменте
(`{<Неизвестный модуль>(строка, колонка)}`). Для набора матрицы
(однострочные ошибочные фрагменты) проверена позиция (1,13) и (1,15);
поведение на многострочном ошибочном фрагменте не проверено.

### Расхождение пробы СтрШаблон (черновой прогон)

Первая редакция пробы (`СтрШаблон("№|№", …)`) упала с ошибкой «Слишком
много фактических параметров». Доработка живыми пробами установила
механику самой функции — это не граница execute, в границы фрагмента не
заносится: маркеры этой версии — `%1`, `%2`, … по номерам (платдок:
`Значение1–Значение10`); «№» маркером не считается; ошибка «Слишком
много фактических параметров» возникает, когда переданных значений
больше, чем распознанных маркеров шаблона. Повтор маркера допустим:
`СтрШаблон("%1|%1", x)` → «3|3» зелёная. Проба переписана на
`СтрШаблон("%1|%2", …)`; чистые прогоны — без отклонений.

### Следствие для Т2–Т4

Условие отказа владельца не воспроизведено ни на одной из двух сред —
третий исход вердикта о носителе (спека знает «на обеих» и «на одной из
двух»): пробел «условия проб 05.11 неизвестны» остаётся границей
применимости; наблюдение владельца идёт в канон с пометкой «не проверено»,
без даты и автора. По решению спеки апстрим-репорт не заводится —
условие из «Границ» Т4 сработало, Т4 фиксирует этот статус, черновик
репорта не создаётся.

Проверенные классы (границы Т2 формулировать только по ним): циклы
`Пока` (отступ табом и пробелами) и `Для`; вложенный `Если` 3 уровня с
условиями-литералами и условиями-вызовами глобальных функций; глобальные
функции `СтрДлина`, `СтрШаблон`; базовое присваивание `Результат = число`.
Границ синтаксиса матрица не установила; диагностика ошибок точная
(строка epf + позиция во фрагменте).

Границы применимости, помеченные «не проверено»: клиентская ветка
execute_code (`execution_context=client`, ВыполнитьКодНаКлиенте — тоже
чистый `Выполнить`) не пробовалась; многострочный ошибочный фрагмент
(позиция во фрагменте) не пробовался; условия проб владельца 05.11
(версия epf, канал) неизвестны.
