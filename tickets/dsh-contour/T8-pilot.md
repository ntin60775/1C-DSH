## Границы и расхождения

- **Конфигурация erp-demo на поддержке вендора, правки запрещены.**
  `unica.apply` план проходит гейты, но Юника отвергает исполнение:
  «enable editing with `supportCapability.set`». Published-исполнение на
  пилоте не снималось: `supportCapability.set` сбрасывает правила вендорских
  объектов — решение о включении правок за оператором. Гейт-критерий
  «unica.apply — allow» снят по факту пропуска вызова гейтами (журнал
  advisory, блокировок нет). Отчёт модульных правил снят через штатный
  механизм разовых эскалаций (`unica-gate-escalations.txt`), без изменения
  поддержки.
- **Формат эскалаций**: строка «путь: причина» гейт отвергает с подсказкой
  (канон — голый путь, причина в `#`-комментарии выше). Первая правка
  модуль-пробы была заблокирована из-за формата строки, добавленной
  исполнителем; модель прочитала подсказку гейта, исправила формат и
  повторила — механизм эскалаций отработал штатно.
- **MCP гонится с первым ходом**: в одноразовой сессии первый запрос
  уходит до подключения MCP (0 инструментов), ко второму ходу каталог
  полон (90 `mcp__*`). Пробы снимались с прогревочным ходом. В
  интерактивной сессии GUI разрыв не виден (каталог собирается до ввода).
  Модель в повторном ответе назвала инструменты отсутствующими, хотя
  запрос нёс 90 `mcp__*` — видимость сверялась по событиям
  `request/header` и `skills/list`, не по словам модели.
- **`tc_execute_code` не экспонируется**: пресет ставит
  `TC1C_CODE_EXECUTION=false`; прод/тест-пробы mcp-гейта сняты на
  bash-REST ветке (`execute_code` в команде с `:6003`) — живой сервер для
  решения гейта не нужен.
- **Стенд 1c-db не поднимался**: запись объявлена, инструменты появятся
  со стендом (готовность e2e, не установки — граница Т7). Станция kd
  после проб работает (поднята гейтом, ветка «станции нет»).

  миграции (наследие ZCode); миграция и вендоринг пака — файловые

  `--check` 0). Пробный ворктри `/tmp/t8-wt` и ветка `t8-probe` удалены.
- **Флейки набора под нагрузкой**: `test_stale_lock_orphans` (первый
