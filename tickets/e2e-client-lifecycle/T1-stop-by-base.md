# Т1 «Стоп по базе (--stop --base)»

Оценка: ~40 мин. Блокеры: нет.

## Зачем

Гашение клиента сегодня знает только «свои» процессы (pid-файл, kill-маркер
инстанса): testpilot-клиент, поднятый мимо скрипта, скриптом не гасится.
Соло-фикстура (Т2) и финализация сеанса (Т3) держатся на общем правиле
гашения по признаку базы — носителем становится новая ветка остановки.
Отдельная ветка сохраняет семантику текущих стопов (Т7 мультистенда):
инстансный стоп не начинает гасить чужих.

## Что делается

- `scripts/start_1c_db.sh`: ветка `--stop --base <строка соединения>` —
  гасит все процессы с `File=<строка>` в cmdline (и поднятые скриптом,
  и testpilot-клиенты); cmdline читается из `/proc`, правило гашения
  не зависит от pgrep.
- Правило гашения прежнее: короткие одиночные kill + перепроверка свежей
  пробы `/proc/<pid>/stat`, добивание по pid; Usr/Pwd в выводе нет
  (инвариант Т2 мультистенда).
- Совместимость: mono-`--stop` и `--stop --instance` работают как сегодня.
- Тесты процессами с фейковыми процессами — паттерн `tests/test_multistand.py`.

## Демо-путь

«Чужой» клиент базы поднят мимо скрипта (фейковый процесс с `File=` в
cmdline); `--stop --base` гасит его одним вызовом; клиенты соседней базы
живы.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тест — фейковый процесс с `File=<строка>` в cmdline, поднятый
   вне скрипта, гасится `--stop --base`; живость по `/proc`, не pgrep.
   Ожидание: процесс мёртв, процессы соседней базы живы. На базовом
   дереве ветки `--base` нет — падает.
2. Артефакт: тест с безпарольной базой — `File=` без `Pwd=` (находка
   живой приёмки Т8 мультистенда: пустой пароль валиден). Ожидание:
   гашение ловит строку соединения без пароля. На базовом дереве —
   падает.
3. Артефакт: инвариант-тест вывода ветки — ни `Usr=`, ни `Pwd=` в
   stdout. Ожидание: чисто. Падает вместе с веткой (нет ветки — нет и
   проверяемого вывода).
4. Артефакт: регресс mono-`--stop` и `--stop --instance`. Ожидание:
   поведение прежнее (инвариант, зелёный до и после).

## Границы

- `--base` самодостаточен: гашение адресуется строкой соединения,
  комбинация с `--instance` не определяется (находка критика P3-1);
  `--instance` участвует только в восстановлении клиента (Т2).
- Прокси веткой `--stop --base` не гасится: у процесса прокси нет `File=`
  в cmdline — гасятся только клиенты, что и нужно соло-фикстуре.
- Инстансный стоп не гасит общий прокси, mono-стоп гасит прокси и называет
  живых инстансов — семантика Т7 мультистенда не пересматривается.
