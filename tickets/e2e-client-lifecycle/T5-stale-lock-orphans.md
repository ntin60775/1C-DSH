# Т5 «Мёртвый лок и сироты на старте»

Оценка: ~50 мин. Блокеры: нет.

## Расхождения (ship 08.11)

- Класс гашения шире слова «сирота»: гасится всякий живой маркированный
  клиент этой базы — в том числе клиент параллельного старта в окне между
  запуском и готовностью канала (замок не различает «прогревается» от
  «висит в диалоге», различителя нет). «Уже полностью поднят» выше по
  скрипту выводит здоровый стенд из-под гашения. Сериализация стартов
  остаётся на stand-замок take — гигиена работает раньше замка (панель
  Т5, P2; решение исполнителя — гашение по тикету, 40-3 требует погасить
  клиента с диалогом; решение оператора может вернуть отказ по живому
  замку).
- «Живых процессов на базе нет» для решения о локе — надмножество
  строгого File=-класса: сессии без File= (1cv8 CONFIG /F<путь> — путь
  базы самостоятельным значением аргумента) и процессы с нечитаемым
  cmdline. Сессия /IBName пути не несёт — невидима (граница: не проверено;
  канон контура — File=). Подстрочный матч пути не годится: префикс
  соседней базы (…/ib/A против …/ib/AB) давал ложное «живой» (панель Т5,
  P2).
- Статья «сирота погашен (pid N)» — факт после подтверждённой смерти;
  перед сигналом — «гашение сироты: pid N» (панель Т5, P3: статья
  опережала факт при отказе kill).
- Тест: критерий 4 составной (статья «сирота погашен» присутствует И
  Usr/Pwd/значений в выводе нет) — иначе на дереве без ветки вакуумно
  зелёный; pid клиента — из контракта вывода «• клиент запущен (pid N)»,
  не из формулы pid-файла; cleanup гасит поднятых стартом клиентов и
  снимает их pid-файлы и логи. Краснота на базовом 2d5e289: 8 провалов из
  15 (критерии 1, 2, 4, добивание; инвариант Т3 и границы зелёные).

## Зачем

Лок 1Cv8.1CL переживал kill клиента и блокировал рестарт (лечился ручным
`rm`); после аварийного прогона оставался 1cv8c с открытым диалогом —
следующий launch_client падал «Test-client startup deadline expired».
Ритуал «stop → pkill по маркеру → снять лок → старт» в 40-3 выполнялся
руками на каждой итерации.

## Что делается

- `scripts/start_1c_db.sh` перед подъёмом клиента: файл лока `1Cv8.1CL`
  существует и живых процессов на базе нет — лок снимается автоматически
  со статьёй в выводе.
- Клиенты-сироты с kill-маркером контура на этой базе гасятся стартом —
  маскированно (Usr/Pwd в выводе нет); маркеры per-instance из Т7
  мультистенда, паттерн маркера — литерал с экранированием ERE.
- Живой немаркированный клиент — отказ stand-гарда Т3 мультистенда с pid,
  как сегодня (гард не ослабляется).
- Тесты процессами.

## Демо-путь

После «аварии» (фейковый сирота с маркером + файл лока без живых
процессов) один старт чистит всё и поднимает стенд; статьи «лок снят»,
«сирота погашен» в выводе.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тест — файл лока есть, живых процессов на базе нет; старт
   снимает лок и поднимает стенд, статья в выводе. Ожидание: рестарт без
   ручных команд. На базовом дереве старт упирается в лок — падает.
2. Артефакт: тест — фейковый сирота с kill-маркером контура в cmdline
   гасится стартом этой базы; клиент соседней базы жив. Ожидание:
   гашение по базе, без чужих. На базовом дереве гард отказывает, сирота
   не гасится — падает.
3. Артефакт: тест — живой немаркированный клиент: старт отказывает с pid
   (stand-гард). Ожидание: инвариант Т3 — зелёный до и после.
4. Артефакт: инвариант-тест вывода ветки автогашения — без Usr/Pwd.
   Падает вместе с веткой.

## Границы

- Лок живого клиента не трогается: автоснятие только при отсутствии
  живых процессов на базе.
- Сироты без маркера контура не гасятся — живой немаркированный клиент
  остаётся решением гарда (отказ с pid), автогашение только «своих».
