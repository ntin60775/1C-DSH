# Т10 «Живая приёмка юнита»

Оценка: ~90 мин. Блокеры: Т1–Т9.

## Зачем

Слой жизненного цикла клиентов доказывается живой базой: процессные тесты
проверяют механику, но не «рестарт — секунды», не автопочинку после
преднамеренного убийства и не диагностику таймаута на живом стенде.
Канон «живая база — сессия проекта»: приёмка исполняется в сессии
проекта, не в контурной.

## Что делается

- Сессия проекта: стенд на файловой базе, venv по обновлённому пину (Т9).
- Сценарий приёмки:
  1. смешанный прогон (сессионные наборы + GUI-соло) одной командой
     через Т8 — зелёный, сводка одна;
  2. преднамеренно убитый прогон — kill -9 pytest-сеанса и клиента
     стенда (с маркером): остаются зомби-прокси, мёртвый лок `1Cv8.1CL`
     и, если соло-сеанс оставил testpilot-клиента, немаркированная
     сирота; перед стартом `--stop --base` гасит сироту (Т1), затем
     старт чинит сам (Т4, Т5): статьи «прокси пересоздан», «лок снят»,
     стенд рабочий;
  3. гигиена pgrep после падшего прогона — 0 зомби (Т3);
  4. смоделированный таймаут — диагностика с полным набором сущностей,
     без `Pwd=` (Т6);
  5. замер рестарта между итерациями — секунды, не минуты (Т7);
- Протокол пробы — в #56 (коммент по слову оператора), факт — в тикете
  и continue.md.

## Демо-путь

Весь сценарий прогона — артефакты: вывод run_e2e с одной сводкой,
статьи старта, pgrep-срезы «до/после», текст диагностики таймаута,
замеры времени; всё — в протоколе #56.

## Критерии приёмки (падают на базовом коммите)

Каждый пункт сценария на базовом дереве (до юнита) не выполняется:
смешанный прогон одной командой не собирается (TESTS — один путь), убитый
прогон оставляет зомби без автопочинки, таймаут приходит без диагностики,
рестарт занимает минуты. Приёмка исполняется на дереве после Т1–Т9.

1. Артефакт: вывод run_e2e смешанного прогона. Ожидание: одна команда,
   два сеанса, зелёная сводка. На базовом дереве — падает.
2. Артефакт: pgrep-срезы после падения, после `--stop --base` и после
   старта; вывод старта со статьями. Ожидание: немаркированная сирота
   гасится `--stop --base`, после старта 0 зомби, execute отвечает.
   На базовом дереве — падает.
3. Артефакт: текст диагностики таймаута. Ожидание: процессы, порт, лок,
   stand-замок; ни одного `Pwd=`. На базовом дереве — падает.
4. Артефакт: замер рестарта (число в протоколе). Ожидание: секунды,
   не минуты. На базовом дереве — минуты (5–7).
5. Артефакт: коммент-протокол в #56. Ожидание: опубликован, находки и
   решения зафиксированы.

## Границы

- Лимит видеопамяти из приёмки Т8 мультистенда: не более трёх стендов
  одновременно; сценарий приёмки идёт на одном стенде.
- Красная живая проба на чистой системе — стоп до разбора (ограничение
  спеки).
- Публикация протокола в #56 и пуш — по слову оператора (прецедент Т8
  мультистенда).
