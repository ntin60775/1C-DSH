# Т8 «run_e2e: автосведение сеансов и TESTS-список»

Оценка: ~60 мин. Блокеры: Т2.

## Зачем

`run_e2e.sh` принимает ровно один путь TESTS: выборку «юниты + 5
сессионных файлов» одним сеансом не собрать — финальный гейт 40-3
собирался обходным прямым pytest с ручным e2e_sweep и без junit-сводки.
Смешанный сеанс «GUI-соло + сессионные onec_db» ломает сессионную
фикстуру: 25 failed / 11 passed / 8 errors на 44 тестах.

## Что делается

- `scripts/run_e2e.sh`: TESTS принимает список путей/глобов.
- Обвязка делит выборку по файлам: сессионные наборы — один pytest-сеанс;
  файлы с маркером `e2e_solo` (Т2) — отдельный сеанс.
- junit-файлы всех сеансов сводятся в один `E2E_SUMMARY_JSON`; post-свип
  `e2e_sweep.py` выполняется один раз по итогу.
- Тест обвязки на фейковых наборах (фейковые файлы тестов и маркеров,
  без запуска стендов).

## Демо-путь

Выборка «два сессионных файла + один GUI-соло файл» одной командой:
два pytest-сеанса, одна сводка; в сводке — все тесты обеих сессий.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тест обвязки — TESTS = «сессионный файл + соло-файл»;
   лог вызовов pytest — ровно два сеанса, состав каждого соответствует
   маркерам. Ожидание: соло-файлы в отдельном сеансе. На базовом дереве
   TESTS — один путь — падает.
2. Артефакт: тест — `E2E_SUMMARY_JSON` собирается из двух junit-файлов;
   все тесты обеих сессий в сводке. Ожидание: одна сводка на прогон.
   На базовом дереве — падает.
3. Артефакт: тест — post-свип вызывается ровно один раз независимо от
   числа сеансов. Ожидание: один вызов `e2e_sweep.py`. На базовом дереве
   автосведения нет, свойство не выражено — тест падает.
4. Артефакт: тест — глоб `tests/e2e/*.py` разворачивается в выборку;
   деление по маркерам сохраняется. На базовом дереве — падает.

## Границы

- `run_e2e` меняется только в части TESTS и сведения сеансов (Рамки
  спеки): instance-механика из хвостов #37 (флаг > env `E2E_INSTANCE` >
  поле профиля, исполнена 06.11) не пересматривается, publish и прочие
  хвосты #37 — вне юнита.
- Маркер `e2e_solo` вешается плагином автоматически по использованию
  `solo_base` — литерала в файле теста может не быть; деление выборки —
  по collect-only (сбор через venv проекта), не статическим грепом
  (находка критика P3-4). Файл без маркера идёт в сессионный сеанс —
  поведение по умолчанию не меняет существующие наборы.
