# Т3 «Финализация сеанса (pytest_sessionfinish)»

Оценка: ~40 мин. Блокеры: Т1, Т2.

## Зачем

К финалу доводки e2e в 40-2 висели четыре 1cv8c на двух базах: падший
прогон оставляет клиентов сеанса без уборки. Уборка на уровне плагина
закрывает это для всех проектов поставки, а не копипастой в conftest.

## Что делается

- `src/onec_db/plugin.py`: `pytest_sessionfinish` гасит клиентов
  тест-сеанса по признаку базы — правило гашения то же (короткие
  одиночные kill + перепроверка, добивание по pid); перечень клиентов
  сеанса — те, кого поднимали фикстуры плагина (канал, соло-восстановление).
- Прокси финализация не гасит никогда (решение владельца #37 — один
  прокси на проект); зомби-прокси чинит следующий старт (Т4).
- Граница kill -9 pytest: финализация не выполнится — остатки чинит
  старт (Т4: прокси, Т5: сироты с маркером).
- Тесты плагина процессами.

## Демо-путь

Прогон с падшим тестом (ассерт) — после сеанса ни одного клиента сеанса
в `/proc`; прокси жив.

## Критерии приёмки (падают на базовом коммите)

Базовое дерево — субрепо `../1c-onec-db` на wheel 0.1.6.

1. Артефакт: тест плагина — сеанс с падшим тестом, после sessionfinish
   pgrep-эквивалент (обход `/proc`) по базе пуст. Ожидание: клиентов
   сеанса нет. На базовом дереве финализации нет — падает.
2. Артефакт: тест — прокси жив после финализации. Ожидание: процесс
   прокси не тронут (инвариант). Падает вместе с финализацией.
3. Артефакт: тест — соло-модуль (клиент поднят фикстурой в finally) +
   финализация: поднятый фикстурой клиент гасится в конце сеанса,
   «чужой» клиент той же базы жив. Ожидание: гасится только поднятые
   сеансом. На базовом дереве — падает.

## Границы

- Перечень «клиентов сеанса» — развилка носителя (список фикстур плагина
  против cmdline-матча по базе с маркером сеанса); решает ship, критерий
  3 ограждает чужих клиентов.
- Запрет на Usr/Pwd в выводе — инвариант контура (Т2 мультистенда),
  проверяется инвариант-тестом вывода.
