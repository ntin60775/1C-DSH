# Т1 «Доставка: политика реконнекта HTTP-строк»

Оценка: ~40 мин. Блокеров нет.

## Зачем

Сессия, открытая при погашенном прокси `:6003` или станции КД `:8060`,
навсегда остаётся без их тулов: дефолт `mcp-client` — 10 попыток по
0.5–30 с (≈2,5 мин), затем `gave-up` и снятие тулов; повторного маунта нет.
Прокси встаёт за 1–3 с и без клиента 1С, поэтому часа ожидания хватает на
любой штатный подъём стенда.

## Что делается

- `src/delivery/config.ts`, тип `McpServerConfig`: поле `reconnect`
  (рукописная копия формы пакета — `enabled`, `initialDelayMs`, `maxDelayMs`,
  `maxAttempts`; импорт типа из `@deepseek-ai/dsh-mcp-client` не тянем, пакета
  нет в зависимостях).
- `mcpRows`: единая константа политики `{ maxAttempts: 120, maxDelayMs:
  30_000 }` на `1c-db`, `1c-kd` и строки инстансов `1c-db-<имя>`. Строки
  `unica` и `1c-testpilot` (stdio) политику не получают — дефолт пакета.
- `tests/unit/delivery.spec.ts`: точная форма политики по каждой http-строке
  и её отсутствие на stdio.
- `tests/unit/delivery-mount.spec.ts`: конфиг, реально уходящий в
  `agent.ctx.plugin`, несёт политику и `failOnStartupError: false`.

## Демо-путь

`pnpm vitest run tests/unit/delivery.spec.ts tests/unit/delivery-mount.spec.ts`
— новые ассерты печатают конфиг строк с `reconnect`; на дереве без правки
прогон красный (поля нет).

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: `pnpm vitest run tests/unit/delivery.spec.ts` — для `1c-db`,
   `1c-kd` и строки инстанса `config.reconnect` равен `{ maxAttempts: 120,
   maxDelayMs: 30_000 }`; на базовом коммите тест падает (поля нет).
2. Артефакт: `tests/unit/delivery-mount.spec.ts` — конфиг, переданный в
   `agent.ctx.plugin` для строк `1c-db`/`1c-kd`, содержит ту же политику и
   `failOnStartupError: false`; на базовом коммите тест падает.
3. Артефакт: тот же тест — stdio-строки `unica` и `1c-testpilot` приходят без
   `reconnect`. Ожидание-инвариант: зелёный до и после.
4. Артефакт: `pnpm typecheck` — зелёный. Сигнал к чтению, не доказательство.

## Границы

- Харнесс не правится; значения политики — константа доставки, не вход
  `contour.json`.
- doctor, `--status` и тексты канона — тикеты Т2–Т4.
- Мультистенд не меняется: инстансы получают только политику.
