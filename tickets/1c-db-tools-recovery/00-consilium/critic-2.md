## Находки

### F1. P2 — окружение: спецификация «установленный харнесс 0.2.2-rc.5» не совпадает с фактически исполняемым билдом
- Проекция: окружение (+время ссылок).
- Место: Контекст, строка 91-93.
- Утверждение: живой хост работает не из установленного пакета rc.5, а из чекаута форка через tsx, поэтому заявленный в спеке якорь окружения и ссылка на «установленный харнесс» описывают не тот билд, на котором поедут живые пробы; line-ссылки спеки верны для чекаута, а не для rc.5-сборки.
- Доказательство: `~/.local/bin/dsh-web → …/forks/deepseek-harness/scripts/web-launcher/dsh-web-launcher.py`; `REPO = HERE.parents[1]`; запуск `[node, "--import", "tsx/esm", "apps/cli/src/bin.ts", "web"]` (`cwd=REPO`, :378-380); чекаут = `dsh-v0.2.2-rc.5-1875-g129a68f443`; сам спайк это признаёт: `05-proof.md:4` «Источник кода — чекаут DSH 1e9748a831 (его же крутит живой хост через tsx)», а спека эту оговорку сняла.
- Что править: в Контексте назвать фактический билд живых проб (чекаут форка, `dsh-web` через tsx) и отдельно зафиксировать (проверено) равенство семантики rc.5-пакета: дефолты 500/30000/10, throw по неизвестному ключу, gave-up+clearTools присутствуют в `~/.dsh/profiles/node_modules/@deepseek-ai/dsh-mcp-client/lib` (0.2.2-rc.5). Иначе приёмка на упакованной установке (парк) повисает без якоря.

### F2. P2 — демо-путь пункта 6 противоречит собственному «Ограничению» (окружение пробы)
- Проекция: демо-путь (чек-лист) × окружение.
