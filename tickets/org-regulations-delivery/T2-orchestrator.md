# Т2 «Оркестратор: пак-шаг, поверхность, реестр»

Оценка: ~60 мин. Блокеры: Т1 (скилл pack-deploy доставлен). Спека:
Готово 2, 3; решения 3; находки T1, T2, T5, T6, T15, T18, T27.

## Зачем

Пак-шаг должен жить в оркестраторе легально: поверхность установки
1c-contour-deploy — закрытый список без паков, всё вне поверхности —
пробел владельцу. Парковый резолв и запись реестра — на оркестраторе
(исполнитель-субагент ask не поднимает); без этого батч-вопрос
вырождается в N серийных вопросов, а реестр получает конкурентных
писателей.

## Что делается

- `contour-deploy/skills/1c-contour-deploy/SKILL.md`: шаг исполнителя
  «паки регламентов» (читает pack-deploy, исполняет); `.agents/packs`
  в поверхность установки; приёмка шага = акт в реестр парка, без
  коммита и вне автоприёмки контур-слоя (паки в gitignore); промпт
  исполнителя несёт путь чекаута contour-deploy; строка невалидного
  пака в выводе core `--check` = аномалия пака → пак-шаг, не дефект
  ядра; парковый резолв до fan-out: поле `org` целей → ключ
  `regulations` конфига, один батч-вопрос при отсутствии поля/ключа,
  пустой реестр = стоп (нет целей); писатель реестра — оркестратор
  последовательно под `projects.json.lock` (контракт замка — как у
  doctor, `scripts/contour_paths.py`); смена конторы проектом — поле
  `org` правит оператор + переустановка, автосверки нет.
- `docs/dsh-install.md` (1C-DSH): схема записи реестра парка
  дополняется полем `org` и актом пака (name/version/channel/date,
  link-коммит).
- README contour-deploy + Предусловия оркестраторов: документация
  ключа `regulations`.

## Демо-путь

Temp-парк в /tmp (temp-конфиг и temp-реестр через параметры, два
орг-чекаута, четыре git-проекта): отсутствие поля org → один
батч-вопрос → запись → пак-шаг ставит паки → акты в temp-реестре →
повторный прогон молчит. Репетиция одного исполнителя-субагента на
одном temp-проекте (холодный агент, только текст протокола). Краснота
на базовом коммите: пак-шага и поверхности нет — temp-парк не
резолвится, акт не пишется; канон схемы без поля org — ожидание
схемы падает.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: вывод паркового резолва на temp-парке без поля org.
   Ожидание: один батч-вопрос на четыре проекта, запись полей,
   второй прогон без вопросов. На базовом дереве резолва нет —
   критерий неисполним.
2. Артефакт: temp-реестр после прогона. Ожидание: записи org и актов
   (name/version/channel/date), путь через ключ `fleet`, запись под
   замком. На базовом дереве схемы и писателя нет — красный.
3. Артефакт: текст поверхности установки 1c-contour-deploy.
   Ожидание: `.agents/packs` в списке, приёмка шага = акт без
   коммита. На базовом дереве паков в поверхности нет — ожидание
   падает.
4. Артефакт: доклад холодного исполнителя-субагента на temp-проекте.
   Ожидание: пак поставлен по тексту протокола, шаг «из головы»
   отсутствует. На базовом дереве протокола и шага нет — красный.
5. Артефакт: канон схемы `docs/dsh-install.md`. Ожидание: поле org и
   акт пака описаны. На базовом дереве описания нет — ожидание
   падает.
