# Т7 «Kill-маркер + интеграционный юнит»

Оценка: ~50 мин. Блокеры: Т5, Т6.

## Зачем

Гашение матчит клиентов по признаку, одинаковому у всех баз, — стоп одного
стенда убьёт соседний. Канал в startup-строке есть только у фазы 1; фаза 2
(autostart;ts;params) его не несёт — канал не годится маркером.

## Что делается

- Per-instance autostart-каталог `build/.1c-db-autostart-<имя>` в cmdline
  обеих фаз — путь заменяет канал как различительный признак.
- `scripts/start_1c_db.sh`: `kill_client` матчит путь каталога.
- Интеграционный юнит «два инстанса, разные операции» на фейковых процессах
  и портах — `tests/test_start_1c_db.py` или отдельный
  `tests/test_multistand.py`.

## Демо-путь

Два фейковых клиента подняты; гасится один — процесс другого жив (свежая
pgrep); обратный порядок — тот же результат.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тест kill обеих фаз — cmdline содержит
   `.1c-db-autostart-<имя>` в фазе 1 и фазе 2; гашение убивает только свой
   процесс. На базовом дереве маркер общий на корень — падает.
2. Артефакт: интеграционный юнит «два инстанса, разные операции».
   Ожидание: операции не перепутались, гашения независимы. На базовом
   дереве `--instance` нет — падает.
3. Артефакт: регресс kill моно-режима. Ожидание: прежний маркер для main
   (инвариант).

## Границы

Правило гашения не меняется: короткие одиночные kill + перепроверка свежей
pgrep; скрипт не переходит на групповые kill.

## Расхождения (разбор прогона)

Панель: reviewer-spec — merge нельзя (P1 метасимволы маркера, P2 mono-стоп,
жизненный цикл копии, доверие к новому пути); reviewer-tests — merge нельзя
(P1 вакуумная проверка прокси, P2 «операции не перепутались», однофазность,
зомби-/proc, сироты cleanup); reviewer-code — merge нельзя (P1 маркер как
ERE, P2 молчаливое «остановлен», сверка копии, «погасить всё», навык);
reviewer-kb — merge после правки тикета (P1 однофазность, P1 матч по
каталогу против файла; разбор сюда). Все P1/P2 правлены в том же заходе;
P3 — в хвостах.

1. **«Обеих фаз» — формулировка от двухфазной фактуры.** Старт однофазный
   с v0.4.73 (danger-флаги в startup-строке, `CONTOUR_AUTOSTART` упразднён;
   шапка скрипта, коммит 3889612): фазы 2 с `autostart;ts;params` нет,
   канал в startup-строке единственного запуска. Критерий 1 закрыт по
   смыслу: различительный путь копии в cmdline клиента — одного; тест
   проверяет его. Посылка «Зачем» про канал тоже снята: маркером канал
   не годится по другой причине — embedded его не несёт, а подстрока
   `channel=base2` ловит `base20`. Спека («Kill-маркер обеих фаз», Готово 2)
   правится словом оператора — вне этого тикета.
2. **Маркер — путь файла, не каталога** (тикет: «kill_client матчит путь
   каталога»). Путь каталога входит подстрокой в путь соседнего:
   `.1c-db-autostart-base2` — префикс `.1c-db-autostart-base20`, гашение
   base2 погасило бы base20. Маркер — путь копии обработки внутри каталога
   (`…-base2/Mock.epf`); тест ловит префиксную ловушку двумя фейками.
3. **Маркер в pgrep/pkill — литерал, не регулярка.** Паттерн экранируется
   для ERE (`sed`): точка в имени каталога проекта (`proj.v1` матчит
   `projXv1` — предсуществующая беда пути) и метасимволы имени инстанса
   (`base.2` против `base12`, `base(2` — regex error) не становятся
   wildcard; тест закрывает точку в имени фейками base.2/base12.
4. **Семантика общего прокси при stop** — назначенная Т7 панелью Т5
   (предупреждение «гасит всех и общий прокси — Т7»): инстансный стоп
   прокси не гасит («прокси не гашу…»), mono-стоп гасит и называет живых
   инстансов. Клиент, промахнувшийся мимо маркера (поднят до Т7 или при
   сменившемся `epf_path`), добивается по pid из pid-файла — без этого
   стоп рапортовал бы «остановлен» при живом клиенте.
5. **Валидация имени инстанса** (локальная защита пути маркера: нельзя
   «/», «\», начало с «.»; гарда имени раньше гарда канала). Полный
   charset имён — прежний хвост Т4 для сервера этапа 2, слово оператора;
   локальная защита его не предрешает.
6. **Копия обработки**: запись атомарная (.part+mv, stand-замок берётся
   позже), не перезаписывается (доверие платформы к пути), расхождение
   с мастером — предупреждение; обновление и уборка каталогов — руками
   (скилл 1c-db-data, ритуал epf). Живой вопрос первого старта инстанса —
   диалог доверия к новому пути — не проверен живым, проверка Т8.
7. **«Операции не перепутались» — сужение доказательства.** На фейковых
   клиентах интеграционный юнит доказывает независимость гашений, точку
   и канал в cmdline; изоляция execute_code двух инстансов на одном
   прокси — критерий живой приёмки Т8 (спека, Готово 5). Формулировка
   теста приведена к доказанному.
8. **Тесты**: секция Т7 вынесена в `tests/test_multistand.py`
   (самодостаточная, вариант тикета); Т3-кейс «--stop при живом клиенте
   замок не снимает» адаптирован к добиванию по pid (инвариант Т3
   «замок не снимается, пока клиент жив» сохранён в release-ветке —
   проверка прямой `release` при живом pid; полный стоп теперь убивает
   клиента и выпускает замок фактом смерти). Красность на базовом
   дереве: 14 FAIL в test_multistand + 3 каскадных в Т3-кейсе
   test_start_1c_db; инварианты (mono-маркер, mono-стоп, `--proxy-only`,
   старт до клиента, канал в cmdline) зелёные на обоих деревьях.
9. **Хвосты (P3) без правки**: shim-сценарий и «свежая pgrep» демо-пути
   покрыты формой теста частично (маркер — часть cmdline процесса);
   `instance_pidfile` переписывает формулу IHASH — смена формулы честно
   уронит тест; хрупкость подстроки «kill-маркера» в отказе —
   трассирована комментарием. Правка continue.md Т5 («--stop --instance
   гасит всех») — снята записью Т7.
