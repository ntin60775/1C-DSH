# Т5 «Рантайм --instance»

Оценка: ~60 мин (верхняя граница лимита). Блокеры: Т4.

## Зачем

Два стенда на одной машине делят pid-файлы, логи и Xvfb :97 и берут связь
из одного источника — параллельная работа невозможна.

## Что делается

`scripts/start_1c_db.sh` при `--instance X`:

- рантайм-ключи клиента, Xvfb и WM от `sha1(корень + X)`; pid-файл и лог
  прокси — от `sha1(корень)`, общие (один прокси на проект);
- дисплей — поле `display` инстанса; не задан — свободный из пула 97/98/99
  по порядку объявления (занятый пропускается); исчерпание → exit 2 с
  подсказкой задать `display` явно (решение оператора);
- связь, user, password — из записи инстанса; main наследует из
  `v8project.local.yaml`;
- канал — поле `channel` или имя инстанса; пробы, autostart, прогрев — с
  `?channel=<канал>`;
- `--print-config` учитывает инстанс.

## Демо-путь

Два старта разных инстансов в тестовом режиме — разные pid-файлы и логи
клиента, разные дисплеи, прокси общий; заполненный пул → exit 2 с
подсказкой.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тест инстанс-ключей — пути pidfile/лога клиента, Xvfb и WM.
   Ожидание: различаются по инстансу; пути pid-файла и лога прокси общие.
   На базовом дереве HASH один на корень — падает.
2. Артефакт: тест выбора дисплея: поле → пул → пропуск занятого → исчерпание.
   Ожидание: 97/98/99 по порядку, исчерпание exit 2 с подсказкой. На базовом
   дереве дисплей жёстко :97 — падает.
3. Артефакт: тест связи: инстанс X берёт connection/user из записи, main —
   из local. Ожидание: строки подключения соответствуют источникам. На
   базовом дереве записи нет — падает.
4. Артефакт: регресс моно-режима. Ожидание: прежний путь (инвариант).

## Границы

Порт-логика — Т6; kill-маркер — Т7; пароль в лог не печатается, pgrep-выводы
по клиентам маскируются.

## Расхождения (разбор прогона)

- Валидация канала — панель P1: имя инстанса/поле channel становятся живым
  каналом изоляции прокси; недопустимый канал тулкит молча уводит в
  `default` (channel_registry.validate_channel_id) — два инстанса
  схлопываются в один канал, чужая проба отвечает «жив», danger-запись
  уходит не в ту базу; «;» в имени инжектит параметры в startup-строку.
  Правка: instances_py отказывает на канал вне
  `[A-Za-z0-9_-]{1,64}` (канон тулкита). Это закрывает и хвост Т4
  «charset имени» в рантайм-части; имя→сервер этапа 2 остаётся за
  оператором (matcher гейта).
- Mono-режим получил пул дисплеев — панель P2: против «Рамок» спеки
  («моно — поведение сегодняшнего дня»); правка: mono-дисплей жёсткий
  :97 (stale-сокет чинит прежняя ветка), пул — только инстансам.
- Пул считал занятым любой сокет — stale-слоты терялись навсегда
  (панель P2). Правка: занят = живой Xvfb (pgrep), stale-сокет чинится
  существующей веткой очистки при старте.
- `--stop --instance` гасит клиентов всех инстансов (маркер обработки
  общий) и общий прокси — панель P2: предупреждение в выводе и шапке;
  per-instance гашение — Т7. Владелец семантики «погашение одного не
  трогает второй» (критерий Т8) — Т7/Т8, в тикетах не назван — доложено
  оператору.
- Гонка выбора дисплея («двое разом взяли один») — панель P2: названа
  в комментарии pick_display границей; арбитраж ресурсов — Т6 (порт);
  арбитраж дисплея нигде не назван — доложено оператору.
- `PROBE_URL` с `?channel=` только в proxy-режиме (embedded-клиент канал
  не несёт); разделитель query безопасен при url с уже имеющимся `?`;
  сообщения ожидания/готовности показывают канальный url.
- Поле display валидируется (номер без двоеточия) — `:98` раньше давал
  `Xvfb ::98`; образец фиксирует «номер без двоеточия» и «пока не
  читается» для publish_port (публикация берёт порт из contour.json).
- Доки по панели: образец переведён на факт рантайма (было «применяется
  Т5»); README «двухфазный подъём» → однофазный + `--instance`; навык
  1c-db-data: дисплей стенда из вывода старта/записи вместо жёсткого
  `:97`, строка «несколько баз — каналы одного прокси» дополнена
  инстанс-путём.
- Тесты по панели: проводка дисплея (pick_display+CHILD_ENV) и
  mono-`:97` текстом; mono-связь процессно (тело mono-блока CONN против
  фикс-текста local); ключ зависит от корня (одинаковое имя в другом
  проекте); логи Xvfb/WM в пер-инстансном различии; полная строка связи
  base3 и точный пустой display; знание системных Xvfb'ов машины
  (занятость — внешний факт, ожидание из pgrep-списка, фейки закрывают
  свободные слоты).
- Краевой случай из панели: встроенные креды в connection с кавычками
  (`File=…;Usr="u"`) — абсолютизатор срезает кавычку значения; в
  инстанс-ветке связь собирается по сегментам до `;`, в mono-ветке
  поведение прежнее (предсуществующее, регрессом не является). Полный
  разбор строки подключения — носитель будущий, вне Т5.
- Остаточные хвосты за оператором: charset имени для сервера этапа 2
  (matcher гейта); арбитраж дисплея между параллельными стендами
  (Т6/Т8); владелец семантики общего прокси при stop — Т7/Т8.
