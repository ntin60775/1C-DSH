# Т5 «Рантайм --instance»

Оценка: ~60 мин (верхняя граница лимита). Блокеры: Т4.

## Зачем

Два стенда на одной машине делят pid-файлы, логи и Xvfb :97 и берут связь
из одного источника — параллельная работа невозможна.

## Что делается

`scripts/start_1c_db.sh` при `--instance X`:

- рантайм-ключи клиента, Xvfb и WM от `sha1(корень + X)`; pid-файл и лог
  прокси — от `sha1(корень)`, общие (один прокси на проект);
- дисплей — поле `display` инстанса; не задан — свободный из пула 97/98/99
  по порядку объявления (занятый пропускается); исчерпание → exit 2 с
  подсказкой задать `display` явно (решение оператора);
- связь, user, password — из записи инстанса; main наследует из
  `v8project.local.yaml`;
- канал — поле `channel` или имя инстанса; пробы, autostart, прогрев — с
  `?channel=<канал>`;
- `--print-config` учитывает инстанс.

## Демо-путь

Два старта разных инстансов в тестовом режиме — разные pid-файлы и логи
клиента, разные дисплеи, прокси общий; заполненный пул → exit 2 с
подсказкой.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тест инстанс-ключей — пути pidfile/лога клиента, Xvfb и WM.
   Ожидание: различаются по инстансу; пути pid-файла и лога прокси общие.
   На базовом дереве HASH один на корень — падает.
2. Артефакт: тест выбора дисплея: поле → пул → пропуск занятого → исчерпание.
   Ожидание: 97/98/99 по порядку, исчерпание exit 2 с подсказкой. На базовом
   дереве дисплей жёстко :97 — падает.
3. Артефакт: тест связи: инстанс X берёт connection/user из записи, main —
   из local. Ожидание: строки подключения соответствуют источникам. На
   базовом дереве записи нет — падает.
4. Артефакт: регресс моно-режима. Ожидание: прежний путь (инвариант).

## Границы

Порт-логика — Т6; kill-маркер — Т7; пароль в лог не печатается, pgrep-выводы
по клиентам маскируются.
