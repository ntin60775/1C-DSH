# Т4 «Конфиг инстансов + fail-loud»

Оценка: ~45 мин. Блокеры: нет.

## Зачем

Вторая база описывается машино-локальным файлом; ленивый инит означает, что
файла штатно нет, и отсутствие — не ошибка.

## Что делается

- `templates/db-instances.example.yaml` — образец: `channel`, `connection`,
  `user`, `password`, `display`, `publish_port` (порт публикации хранится
  конфигом, обрабатывается следующим юнитом).
- `skills/1c-project-layout/templates/gitignore.template`: +
  `db-instances.yaml` и `.zcode/1c/contour.local.json` — правило гигиены
  рядом с появлением ресурса.
- `scripts/start_1c_db.sh`: чтение `.zcode/1c/db-instances.yaml`; fail-loud
  при `--instance X`: нет файла / нет инстанса X / битый YAML / неполные
  поля (`connection`, `user`, `password`) → exit 2 с перечнем недостающего
  и путём к образцу. Фолбэк на main запрещён.

## Демо-путь

`start_1c_db.sh . --instance base2` без конфига → exit 2 с перечнем, чего не
хватает, и путём к образцу; без `--instance` и без файла — поведение как
сегодня.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тесты четырёх веток fail-loud в `tests/test_start_1c_db.py`.
   Ожидание: exit 2 + перечень недостающего в тексте. На базовом дереве
   `--instance` не существует — падают.
2. Артефакт: греп `skills/1c-project-layout/templates/gitignore.template` на
   две строки. Ожидание: строки есть. На базовом дереве отсутствуют.
3. Артефакт: регресс моно-режима (файла нет, `--instance` нет). Ожидание:
   прежний путь до подъёма клиента (инвариант; зелёный до и после).

## Границы

Doctor валидацию файла не делает (следующий юнит, этап 3); файл в проекте
никто не создаёт автоматически; пароль в лог и чат не печатается. Строки
в gitignore-шаблон наследует только новый скэфолд — в существующих
проектах линии добавляются вручную (шаг 6 ритуала
1c-project-bootstrap дополнен двумя строками по панели Т4).

## Расхождения (разбор прогона)

- Годный конфиг при `--instance` молча продолжал main-путь (панель, 4/4
  роли — P1): связь из `v8project.local.yaml`, канал из contour.json —
  это ровно «фолбэк на main», запрещённый спекой, под видом инстанса.
  Правка: годная запись останавливается громко — exit 2 «рантайм
  инстанса — Т5»; шапка скрипта и образец приведены к правде. Окна
  «тихо поднял main вместо инстанса» нет.
- Парсер построчный, не полный YAML; по панели закрыты: inline-комментарий
  вне кавычек (пароль с «#» законен — режется только « #» вне кавычек),
  незакрытая кавычка, белый список полей (опечатка `chanel` ловится, не
  тихий пропуск), повторное поле/имя, BOM (utf-8-sig), OSError прав,
  каталог вместо файла, маркер `---`, кавычный ключ. Попутный баг,
  пойманный тестом образца: срез комментария съедал закрывающую кавычку —
  `user: ""` читался как незакрытый.
- Разбор аргументов по панели: пустое имя, повторный `--instance`,
  форма `--instance=X`, значение-флаг `--instance --print-config` —
  всё отказывает, ничего не глотается молча.
- Тесты по панели: пароль в фикстуре неполной записи (проверка «не
  печатается» больше не вакуумная), main-связь в фикс-проекте (отказ —
  прямое доказательство запрета фолбэка), греп gitignore-строк
  автотестом (критерий 2 раньше закрывался ручным грепом), кейс
  «образец как есть → exit 2 с перечнем user, password», ветки парсера
  (пустой файл, чужой верхний ключ, скаляр у инстанса, повторное имя,
  ключ без двоеточия, не-UTF-8).
- KB по панели: образец внесён в строку `templates/` README; инвариант 5
  скилла 1c-project-layout дополнен кредами инстансов; шаг 6 ритуала
  1c-project-bootstrap дополнен строками `db-instances.yaml` и
  `contour.local.json`; «фактический порт» → «фактический url» (Т6);
  `(:97…)` → `:97–:99`; подсказка различает обязательные три поля и
  опциональные.
- Charset имени инстанса `[a-z0-9_-]+` — за оператором (кандидат из
  панели Т1, повторён панелью Т4): `Base2`/`База2` пройдут валидацию, на
  Т5 такое имя даст сервер вне matcher гейта — тихий обход. По правилу
  «спека после план-гейта меняется словом оператора» в Т4 не вносится;
  носители решения: правка спеки/Т5 словом оператора или добавление
  проверки словом оператора в Т4.
- Тест «валидная запись не блокируется» из прогона до панели закреплял
  тихий main-путь — заменён на проверку громкой остановки «рантайм — Т5».
- Образец называет `File=build/ib/base2` относительным; абсолютизация
  для записи инстанса — обязанность Т5 (риск расхождения ключа замка и
  строки клиента из досье Т3 касается Т5, не Т4).

## Дополнение 06.11 (решение оператора после приёмки Т8)

Гвард «неполные поля» трактовал пустой `password` как незаполненный —
гвард блокировал безпарольные базы (демо-учётка из local без пароля
остановила старт inst2 на живой приёмке). Решение оператора «безпарольное
тоже должно работать» (574471e): поля обязаны присутствовать, пустое
ЗНАЧЕНИЕ валидно только у `password` (база без пароля); пустые
connection/user — отказ. Красность на базе: 3 FAIL (пустой password
валиден, пустой connection с подсказкой, mono с «'' # комментарий»).
Образец согласован (`password: ""` валиден — расходился с гвардом с Т4).
