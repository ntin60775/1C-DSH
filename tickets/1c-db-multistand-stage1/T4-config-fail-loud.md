# Т4 «Конфиг инстансов + fail-loud»

Оценка: ~45 мин. Блокеры: нет.

## Зачем

Вторая база описывается машино-локальным файлом; ленивый инит означает, что
файла штатно нет, и отсутствие — не ошибка.

## Что делается

- `templates/db-instances.example.yaml` — образец: `channel`, `connection`,
  `user`, `password`, `display`, `publish_port` (порт публикации хранится
  конфигом, обрабатывается следующим юнитом).
- `skills/1c-project-layout/templates/gitignore.template`: +
  `db-instances.yaml` и `.zcode/1c/contour.local.json` — правило гигиены
  рядом с появлением ресурса.
- `scripts/start_1c_db.sh`: чтение `.zcode/1c/db-instances.yaml`; fail-loud
  при `--instance X`: нет файла / нет инстанса X / битый YAML / неполные
  поля (`connection`, `user`, `password`) → exit 2 с перечнем недостающего
  и путём к образцу. Фолбэк на main запрещён.

## Демо-путь

`start_1c_db.sh . --instance base2` без конфига → exit 2 с перечнем, чего не
хватает, и путём к образцу; без `--instance` и без файла — поведение как
сегодня.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: тесты четырёх веток fail-loud в `tests/test_start_1c_db.py`.
   Ожидание: exit 2 + перечень недостающего в тексте. На базовом дереве
   `--instance` не существует — падают.
2. Артефакт: греп `skills/1c-project-layout/templates/gitignore.template` на
   две строки. Ожидание: строки есть. На базовом дереве отсутствуют.
3. Артефакт: регресс моно-режима (файла нет, `--instance` нет). Ожидание:
   прежний путь до подъёма клиента (инвариант; зелёный до и после).

## Границы

Doctor валидацию файла не делает (следующий юнит, этап 3); файл в проекте
никто не создаёт автоматически; пароль в лог и чат не печатается. Строки
в gitignore-шаблон наследует только новый скэфолд — в существующих
проектах линии добавляются вручную.
