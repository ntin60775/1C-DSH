# Т1 «Реестр 1c-testpilot: внешние epf и окна платформы»

Оценка: ~45 мин. Блокеры: нет.

## Зачем

Сессия 08.11 (project-bp, sess_8386e97e) около двух часов выводила с нуля
открытие внешнего epf в тест-клиенте и работу с окнами платформы. Реестр
операций `1c-testpilot` не знает ни внешних epf (через `e1cib/…` они не
адресуются), ни каталога окон: ErrorWindow, вендорское модальное
«Отчет об ошибке», предупреждение платформы с `form_name="MessageBox"`;
`tc_app get_current_error` (TOOLS.md апстрима) не упомянут. Строка про
сочетания клавиш держит «на живом стенде не проверено» — проба через
MCP-сервер при клиенте в отдельном Xvfb дала отказ
`keyboard_window_not_foreground` (фокус остался за root; апстрим
заявляет поддержку isolated — расхождение не объяснено). Спека:
[docs/plans/external-epf-loop.md](../../docs/plans/external-epf-loop.md).

## Что делается

Правка `skills/1c-testpilot/SKILL.md`, таблица «Навигация и окна» реестра
— новые строки:

- «Открыть внешнюю обработку/отчёт (.epf/.erf)»: запуск раннером с
  ключом — `launch_client` с `extra_args: ["/Execute", "<путь>"]`, форма
  открывается на старте клиента; при epf, заданном в профиле, — отказ
  `conflicting_execute_argument`; через `e1cib/...` внешние не
  адресуются; файловый диалог (`set_file_dialog_result` + Ctrl+O) —
  fallback только там, где клавиатура достаёт окно;
- «Окно ошибки платформы (ErrorWindow)»: заголовок окна «1С:Предприятие»,
  текст читается по декорации `ErrorInfo`; `tc_app get_current_error` —
  канон чтения, **не проверено** живьём;
- «Вендорское „Отчет об ошибке“ (ErrorReportWindow)»: не читать
  (`tc_form get_context` на ref окна отвечает `unsupported_receiver`),
  только закрывать — `tc_window close_window` с readback; стек ошибки —
  `get_current_error` (строка выше), не кликом по гиперссылке «Сформировать
  отчет об ошибке»;
- «Предупреждение/вопрос платформы»: ManagedForm с
  `form_name="MessageBox"`, заголовок окна «1С:Предприятие» (не
  «Предупреждение»); гасить `answer_dialog` на ref окна; оракул успеха —
  смена активного окна;
- «Диалог безопасности на внешний epf/erf»: поднимается на пересобранный
  бинарник и после рестарта клиента; якорь доверия (путь/контент) —
  носитель 1c-db-data (Т4), факт в testpilot не пересказывать;
  признак подтверждения — execute-канал оживает; до подтверждения
  execute-каналы висят до 180 с — выглядит как флап стенда;
  подтверждение — оператором на дисплее владельца или кликом по
  `Button0` тест-клиентом.

Правка строки «Сочетание клавиш»: вместо «на живом стенде не проверено»
— граница по среде: при клиенте в отдельном Xvfb (MCP-сервер на чужом
DISPLAY) проба дала `keyboard_window_not_foreground` — подтверждения
форм через `answer_dialog` на ref окна; апстрим (TOOLS.md пина)
заявляет поддержку `desktop: isolated`, расхождение не объяснено; на
живом стенде не проверено. Литерал отказа — с префиксом `keyboard_`,
как соседние коды строки.

## Расхождения (панель 08.11, правлены)

- Литерал отказа — `keyboard_window_not_foreground`, не
  `window_not_foreground` (P1: код `_keyboard_linux.py` апстрима и
  живой вызов транскрипта; прежний критерий с укороченным литералом
  пропустил бы находку — переведён на полный литерал).
- Отказ клавиатуры — факт среды (фокус за root при клиенте в отдельном
  Xvfb), не свойство isolated: апстрим заявляет поддержку (TOOLS.md
  пина), расхождение не объяснено, граница формулируется по среде.
- `/Execute` — способ запуска, не подтверждения: из строки клавиатуры
  убран.
- Семантика доверия — хозяин `1c-db-data` (Т4): в testpilot указатель,
  факт не пересказывается (рассинхрон двух скиллов снят).
- В строку открытия добавлен отказ `conflicting_execute_argument`
  (epf в профиле).

Тексты по нормам канона (happy path, без истории сессии и имён проектов).
Факты вычитать против транскрипта sess_8386e97e (база
`~/.zcode/cli/db/db.sqlite`) и TOOLS.md апстрима 1c-testpilot
(`contrib/clones/1c-testpilot`) до коммита; тег клона сверить с пином
скилла (1.9.2) — при расхождении вычитка идёт по diff TOOLS.md между
тегом клона и пином.

## Демо-путь

Агент, читающий реестр перед GUI-действием, получает рецепт открытия
внешнего epf и каталог окон без разведки; греп `/Execute` по SKILL.md
возвращает строку.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: греп `/Execute` в `skills/1c-testpilot/SKILL.md`.
   Ожидание: строка открытия внешнего epf с `extra_args` и оговоркой про
   клавиатуру. На базовом дереве — пусто, падает.
2. Артефакт: греп `get_current_error` в том же файле. Ожидание: строка
   ErrorWindow с пометкой «не проверено». На базе пусто, падает.
3. Артефакт: греп `keyboard_window_not_foreground` (полный литерал,
   с префиксом `keyboard_`, как в коде апстрима). Ожидание:
   переписанное примечание строки сочетаний клавиш. На базе пусто,
   падает.
4. Артефакт: греп `MessageBox` в разделе про окна. Ожидание: строка
   про предупреждение/вопрос с заголовком «1С:Предприятие». На базе
   пусто, падает.
5. Инвариант: `lint_skill_frontmatter` 15/15 — frontmatter скилла не
   трогается.
