# Т5 «Гейт и инвариант 1: согласование с каноном epf»

Оценка: ~60 мин. Блокеры: нет.

## Зачем

Гейт исходников `unica_source_gate` блокирует прямые Write/Edit в
`src/epf/` и `src/erf/` (список `SOURCE_PREFIXES` в
`hooks/contour_common.py`), а канон юники (`epf-init`/`erf-init`)
предписывает создавать каркас внешних обработок и отчётов «файловыми
средствами… прямо в path» source-set'а — канонической операции создания
внешнего объекта на поверхности unica нет, `unica.apply` правит только
существующие узлы. Противоречие живёт эскалациями и обходами (пишущие
скрипты через Bash ветку гейта не видят). Решение оператора 08.11:
src/epf и src/erf выпадают из гейта; контроль качества epf-правок —
roundtrip скриптов и разбор v8-контейнера (Т3). Спека:
[docs/plans/external-epf-loop.md](../../docs/plans/external-epf-loop.md).

## Что делается

- `hooks/contour_common.py`: `SOURCE_PREFIXES` теряет `src/epf/` и
  `src/erf/`; остаток — `src/cf/`, `src/cfe/`, `tests/epf/` (tests/epf
  остаётся блокируемым — решение оператора касалось только src).
  Комментарий к списку называет решение (файловый канон
  epf-init/erf-init, сужение словом оператора 08.11). Bash-ветка
  (`sed -i`/перенаправления) читает тот же список — сужается
  автоматически.
- Тесты гейта (процессы stdin → exit): кейсы Write/Edit и bash-ветки
  для src/epf и src/erf добавляются новыми с ожиданием «пропуск»
  (exit 0) — в `tests/test_unica_source_gate.py` их нет (проверено
  грепом); кейсы src/cf и src/cfe остаются инвариантом «блок» (exit 2);
  кейс эскалации остаётся на cf/cfe.
- Краснота: базовое дерево (git archive базовых hooks в пустой каталог +
  правленые тесты) — epf/erf-кейсы падают (базовый гейт блокирует, тест
  ждёт пропуск), cf/cfe-инварианты зелёные до и после; лог красноты в
  /tmp.
- `templates/agents-section.md`, инвариант 1: «src/{cf,cfe} правятся
  только через Unica — прямая правка блокируется гейтом. Внешние
  epf/erf: каркас — файлами по epf-init/erf-init (спека внешней
  обработки юники — источник канона разметки), правка узлов —
  unica.apply, сборка/разбор — epf-load/epf-dump (1c-ibcmd-delivery).
  Разовый обход для остальных — .zcode/unica-gate-escalations.txt».
- Носители-описания гейта согласуются с сужением: docstring
  `unica_source_gate.py` (перечень блокируемых деревьев), правило про
  гейт в скилле `1c-contour` («Исходники 1С правятся только через
  Unica… блокируется гейтом»), строка «только через Unica» в шаблоне
  `templates/agents/src.md`. Подсказка маршрутизации
  (`suggest_unica_tool`) epf/erf-специфики не содержит — проверено,
  правки не требует.

Тексты по нормам канона.

## Демо-путь

Тест-процесс гейта: Write в `src/epf/<имя>/Ext/…` — exit 0 на новом
дереве, exit 2 на базовом; Write в `src/cf/…` — exit 2 на обоих.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: новый тест гейта «Write в src/epf проходит» (процесс
   stdin → exit). Ожидание: exit 0 на новом дереве; на базовом дереве —
   exit 2, тест падает. Лог красноты в /tmp.
2. Артефакт: новый тест гейта «Edit в src/erf проходит». Ожидание:
   exit 0 новое / падение на базе.
3. Артефакт: инвариантный тест «Write в src/cfe блокируется» — зелёный
   до и после (защита cf/cfe и tests/epf не ослаблена).
4. Артефакт: греп `src/epf/` в `hooks/contour_common.py` — на новом
   дереве пусто (критерий доказывается полным набором тестов).
5. Артефакт: греп `epf-init` в `templates/agents-section.md`. Ожидание:
   переформулированный инвариант 1 с маршрутом epf/erf. На базе пусто,
   падает.
6. Артефакт: греп «epf» (как блокируемого дерева) в docstring
   `unica_source_gate.py` и правленые строки `1c-contour`/`src.md` —
   перечень носителей соответствует списку `SOURCE_PREFIXES`.
7. Инвариант: полный набор тестов хуков зелёный на worktree и на
   слитом main.
