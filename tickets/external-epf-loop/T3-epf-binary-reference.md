# Т3 «Reference разбора v8-контейнера epf»

Оценка: ~40 мин. Блокеры: нет.

## Зачем

E2e-регрессия «форма без элементов» не имеет носителя в контуре: рецепт
побитового разбора v8-контейнера (python, zlib, TOC) выведен в сессии
08.11 при диагнозе пустой формы и живёт только в памяти project-bp
(`1c-ibcmd-config-export.md`). Без reference каждый проект копирует
рецепт из ничего. Спека:
[docs/plans/external-epf-loop.md](../../docs/plans/external-epf-loop.md).

## Что делается

Новый файл `skills/1c-project-layout/references/epf-binary.md`:

- структура контейнера: шапка 16 байт, int32 счётчик блоков на смещении
  8, TOC-страница `\r\n` + hex8-триплеты `start end next`, имена файлов
  utf-16 внутри zlib-блоков; паттерн блока данных
  `\r\n([0-9a-f]{8}) ([0-9a-f]{8}) 7fffffff \r\n` (машинные литералы
  as-is);
- проверка собранного: маркеры имён элементов формы (групп, кнопок,
  таблиц) ищутся в дефлейт-блоках — маркеры есть = дерево попало в
  бинарник; маркеров нет при непустом исходнике = форма соберётся
  пустым окном;
- диагноз дубликата UUID: корневой XML процессора и `Forms/Форма.xml`
  обязаны иметь разные UUID; дубликат даёт молча неполный контейнер
  (TOC 7 файлов вместо 8+, нет блока данных ObjectId.1), runtime
  «Ошибка подключения внешних метаданных: Ошибка формата потока» на
  `ВнешниеОбработки.Создать`, dump обрывается на «Формат:
  Иерархический» без «Выгрузка завершена»;
- «не проверено»: сверка списка файлов с валидным epf другой сборки —
  как контрольный приём, не как ритуал.

Рецепт — python stdlib (zlib + regex), без зависимостей. Формат выгрузки
— иерархический (тот же, что ждёт source-set юники). Тексты по нормам
канона: класс явления (любой epf/erf), без истории сессии.

## Демо-путь

Источники бинарников для прогона рецепта:

- валидный — `onec/Testpilot/Testpilot.epf` из клона апстрима
  1c-testpilot (`contrib/clones/1c-testpilot`) или артефакт
  `build/out/epf/` любого проекта парка;
- битый (дубликат UUID) — собирается `epf-load.sh` из копии выгрузки с
  продублированным UUID корня и `Forms/Форма.xml` (платформа — по
  канону 1c-ibcmd-delivery; машинные пути проектов в репо не
  переносятся).

Рецепт, запущенный на валидном `.epf`, печатает TOC и находит маркеры
имён элементов; на битом — показывает короткий TOC.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: файл `skills/1c-project-layout/references/epf-binary.md`
   существует; греп «Ошибка формата потока» и «hex8-триплеты» находит
   разделы. На базовом дереве файла нет — падает.
2. Артефакт: рецепт (скопированный из reference как есть) на валидном
   `.epf` (Testpilot.epf из клона апстрима или артефакт build/out)
   возвращает читаемый TOC — счётчик блоков сходится с числом
   триплетов. На базовом дереве копировать нечего — падает.
3. Инвариант: `lint_skill_frontmatter` 15/15 (reference без
   frontmatter-правок скиллов).
