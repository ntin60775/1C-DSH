# Т3 «Reference разбора v8-контейнера epf»

Оценка: ~40 мин. Блокеры: нет.

## Зачем

E2e-регрессия «форма без элементов» не имеет носителя в контуре: рецепт
побитового разбора v8-контейнера (python, zlib, TOC) выведен в сессии
08.11 при диагнозе пустой формы и живёт только в памяти project-bp
(`1c-ibcmd-config-export.md`). Без reference каждый проект копирует
рецепт из ничего. Спека:
[docs/plans/external-epf-loop.md](../../docs/plans/external-epf-loop.md).

## Что делается

Новый файл `skills/1c-project-layout/references/epf-binary.md`:

- структура контейнера (модель верифицирована на корпусе контейнеров
  парка после правок панели): шапка 16 байт (поле 0 — смещение страницы
  `commit`, `0x7fffffff` — нет); TOC-страница на смещении 16, её
  ASCII-шапка — шапка самой страницы, число записей = размер страницы /
  12; записи — бинарные little-endian hex8-триплеты (start, end, next) на
  блоки-дескрипторы; многостраничный TOC связан полем next; блок —
  ASCII-шапка 31 байт (size, alloc, next), следующая шапка на
  смещение + 31 + alloc; свободные страницы (первое поле `0x7fffffff`)
  несут устаревшие данные — пропускать; данные блоков двух сортов —
  несжатые (дескрипторы: метки времени, нули, utf-16 имя файла) и сжатые
  сырым deflate (контент: сериализованный текст 1С в UTF-8 с BOM —
  разметка форм, модули; литеральных XML-тегов в бинарнике нет);
- проверка собранного: имена элементов и обработчиков формы из исходника
  разметки ищутся в разжатом содержимом deflate-блоков (обе кодировки);
  поиск по свободным страницам отключён; deflate без eof — диагностика
  обрыва; имя «нет» при живом маркере в исходнике = дерево не попало в
  бинарник;
- диагноз дубликата UUID: корневой XML процессора и `Forms/Форма.xml`
  обязаны иметь разные UUID; дубликат даёт молча неполный контейнер
  (TOC 7 файлов вместо 8+, нет блока данных ObjectId.1), рантайм
  «Ошибка подключения внешних метаданных: Ошибка формата потока» на
  `ВнешниеОбработки.Создать`, dump обрывается на «Формат:
  Иерархический» без «Выгрузка завершена»;
- «не проверено»: сверка списка файлов с валидным epf другой сборки —
  контрольный приём, не ритуал (рецепт список имён файлов не печатает);
- ссылка на reference из `skills/1c-project-layout/SKILL.md` (конвенция
  каталога references/, находка панели P2: без неё reference — единственный
  сирота репо; плановая ссылка из Т2 идёт в шаблоны проектов, где
  относительный путь к references/ ломается).

Рецепт — python stdlib (zlib + regex), без зависимостей. Формат выгрузки
— иерархический (тот же, что ждёт source-set юники). Тексты по нормам
канона: класс явления (любой epf/erf), без истории сессии.

## Демо-путь

Источники бинарников для прогона рецепта:

- валидный — `onec/Testpilot/Testpilot.epf` из клона апстрима
  1c-testpilot (`contrib/clones/1c-testpilot`) или артефакт
  `build/out/epf/` любого проекта парка;
- битый (дубликат UUID) — собирается `epf-load.sh` из копии выгрузки с
  продублированным UUID корня и `Forms/Форма.xml` (платформа — по
  канону 1c-ibcmd-delivery; машинные пути проектов в репо не
  переносятся).

Рецепт, запущенный на валидном `.epf`, печатает TOC (записи = размер
TOC-страницы / 12) и находит имена элементов; на обрезанном контейнере
даёт диагностику вместо мусора.

## Расхождения (панель 08.11, правлены)

- P1: поле на смещении 8 — не счётчик записей TOC (на контрпримере
  парка: значение 20 при 8 записях); ASCII-строка на смещении 16 —
  шапка самой TOC-страницы, а не первая запись; записи = размер
  страницы / 12. Первая версия рецепта печатала «TOC: 20 записей» и
  теряла запись.
- P1: перечисление блоков регуляркой по всему файлу ловило шапки
  свободных страниц (size = `0x7fffffff`) и искало маркеры до конца
  файла — по устаревшим данным прежних сборок давало ложное «есть»
  (строки `commit`/`deleted` находятся только в free-страницах
  контрпримера). Переписано на цепочку по `+ 31 + alloc` с пропуском
  свободных страниц.
- P2: разжатый контент — UTF-8 с BOM (разметка, модули); utf-16 —
  только имена файлов в дескрипторах. Поиск ведётся по обеим
  кодировкам.
- P2: проверка `len(entries) != count` была мёртвой (список строится из
  счётчика), обрыв контейнера падал `struct.error`; заменена на
  границы чтения и eof-проверку deflate с диагностикой.
- P2: reference был единственным сиротой репо (44/45 references связаны
  из SKILL.md) — ссылка добавлена в этот же тикет; ссылка из Т2
  (шаблоны проектов) путь к references/ не чинит.
- P3: «хеш-ID» в дескрипторе — метки времени (две одинаковые пары
  dword), не хеш; поиск маркеров ограничен содержимым блоков с
  оговоркой про utf-16 имена в дескрипторах.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: файл `skills/1c-project-layout/references/epf-binary.md`
   существует; греп «Ошибка формата потока» и «hex8-триплеты» находит
   разделы. На базовом дереве файла нет — падает.
2. Артефакт: рецепт (скопированный из reference как есть, подставлены
   PATH и имена маркеров из исходника Form.xml) на валидном `.epf`
   печатает «TOC: N записей», где N = размер TOC-страницы / 12, и
   «есть» по реальным маркерам при «нет» по подставному маркеру;
   негатив-контроль на контейнере со свободными страницами: строки,
   живущие только в free-страницах, дают «нет»; на обрезанном
   контейнере — диагностика, не мусор. На базовом дереве копировать
   нечего — падает.
3. Артефакт: греп ссылки `references/epf-binary.md` в
   `skills/1c-project-layout/SKILL.md`. На базе пусто, падает.
4. Инвариант: `lint_skill_frontmatter` 15/15 (reference без
   frontmatter-правок скиллов).
