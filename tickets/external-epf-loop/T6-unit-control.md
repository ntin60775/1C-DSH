Оценка: ~30 мин. Блокеры: Т1, Т2, Т3, Т4, Т5.

## Зачем

Финальный контроль юнита: спековский пункт «Готово» 6 — сводная вычитка
против первоисточников и полный набор проверок; решения юнита
фиксируются в ишью #62 (правило «последнее слово наше» и след для
читателей ишью). Спека:
[docs/plans/external-epf-loop.md](../../docs/plans/external-epf-loop.md).

## Что делается

- Сводная вычитка всех правленных носителей против первоисточников,
  по матрице «носитель × факт»:
  - `1c-testpilot` — транскрипт sess_8386e97e (чтение через
    `~/.zcode/cli/db/db.sqlite`, read-only) и TOOLS.md апстрима
    (`tc_app.get_current_error`, `set_file_dialog_result`,
    `answer_dialog`); тег клона `contrib/clones/1c-testpilot` сверить с
    пином скилла — при расхождении вычитка по diff TOOLS.md;
  - `src_epf.md` + reference — спека юники
    `references/specs/1c-epf-spec.md` (ChildItems — §6.3, отказ
    ссылочных колонок — примечание к таблице типов), `epf-init`/
    `erf-init` (файловая инициализация, `unica.run make`);
  - `1c-db-data` — память project-bp `1c-ibcmd-config-export.md`
    (`~/.zcode/cli/memories/projects/project-bp-8c992e49b7ba61d2/
    memory/`; те же факты покрывает транскрипт sess_8386e97e —
    семантика «каждый новый бинарник», 180-с зависание);
  - инвариант 1 — решения оператора 08.11 в спеке;
  - маршрут сборки — `1c-ibcmd-delivery` (раздел про `.epf`/`.erf`):
    формулировки согласованы, противоречий нет.
- Протокол вычитки — в тикете: каждый факт с отметкой «сходится» /
  «расхождение → правка внесена».
- `python3 scripts/lint_skill_frontmatter.py` — 15/15.
- Полный тест-набор: `for t in tests/test_*.py; do python3 "$t"; done`
  — 0 провалов (хуки гоняются процессами по канону репо).
- Гигиена имён: grep по паттерну `.forbidden-names.txt` (vendor
  исключён) — чисто.
- Сопровождение KB: `gitmark.py index`, `gitmark.py lint --strict`.
- Коммент-резюме в ишью #62 (`gh api repos/ntin60775/1c-zcode/issues/62/
  comments`): принятые решения (маршрут epf, сужение гейта, носитель
  v8-контейнера, правило issue вне рамок, приёмка вычиткой), носители,
  статус отгрузки.

## Демо-путь

Читатель ишью #62 видит коммент с решениями и носителями; протокол
вычитки в тикете показывает «сходится» по всем строкам матрицы.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: протокол вычитки в тикете — матрица заполнена, расхождений
   не осталось (или правки внесены и перечитаны). На базовом дереве
   протокола нет — падает.
2. Артефакт: вывод lint — 15/15 (инвариант).
3. Артефакт: вывод полного тест-набора — 0 провалов (инвариант).
4. Артефакт: вывод гигиены имён — «чисто» (инвариант).
5. Артефакт: коммент в #62 с решениями юнита — существует
   (`gh api …/issues/62/comments` возвращает его). На базовом дереве
   (до ship Т6) коммента нет — падает.
