# Т2 «Канон сборки в src_epf.md»

Оценка: ~40 мин. Блокеры: Т3 (секция «Проверка собранного» ведёт на
reference `references/epf-binary.md` из Т3).

## Зачем

Всегда-загружаемый контекст каталога `src/epf` — шаблон
`templates/agents/src_epf.md` — состоит из восьми строк: «правятся только
через Unica», и всё. Агент в каталоге исходников внешней обработки не
видит ни канона разметки (`<ChildItems>`, разные UUID, примитивные
колонки), ни маршрута работы (каркас — `epf-init`/`erf-init`, правка
узлов — `unica.apply`, сборка/разбор — скрипты контура), ни контроля
собранного. Сессия 08.11 переоткрыла весь этот канон, часть которого уже
документирована в спеке юники. Та же противоречащая канону строка
«правятся только через Unica» живёт и в существующем шаблоне
`src_erf.md` (scaffold разворачивает его в AGENTS каталога `src/erf`) —
после сужения гейта она станет прямым запретом канонного пути. Спека:
[docs/plans/external-epf-loop.md](../../docs/plans/external-epf-loop.md).

## Что делается

Правка `skills/1c-project-layout/templates/agents/src_epf.md` (шаблон
развёртывается скэфолдом в AGENTS каталога `src/epf`):

- канон разметки: секция элементов формы называется `<ChildItems>`
  (порядок верхнего уровня AutoCommandBar → ChildItems → Attributes →
  Commands); `<Items>` конфигуратор грузит «мягко» — молча выкидывает
  дерево, форма открывается пустым окном; UUID корневого XML и
  `Forms/Форма.xml` — разные; колонки ValueTable-реквизита формы —
  только примитивные типы, `cfg:CatalogRef.*` не резолвятся (ссылка
  заменяется строкой-ключом + `ПРЕДСТАВЛЕНИЕ()` в запросе);
- маршрут работы: каркас — файлами по `epf-init`/`erf-init` (спека
  внешней обработки юники — источник канона разметки); правка
  существующих узлов — `unica.apply` (поверхность на внешних
  source-set'ах — по тексту epf-init, живьём не проверена); сборка и
  разбор — `epf-load.sh`/`epf-dump.sh` из `1c-ibcmd-delivery`;
  `unica.run op=make` — альтернатива той же сборки через раннер;
- секция «Проверка собранного» — компактная, со ссылкой на
  `references/epf-binary.md` (детальный рецепт разбора v8-контейнера
  живёт там, always-загрузка остаётся короткой);
- строка «Исходники правятся только через Unica (`unica.apply`), не
  руками» заменяется маршрутом (каркас — файлами по epf-init/erf-init,
  правка существующих узлов — unica.apply): без удаления строки канон
  и старое правило противоречат друг другу;
- `templates/agents/src_erf.md` — существующий шаблон каталога `src/erf`
  приводится к тому же канону минимальным diff'ом (маршрут + ссылка на
  reference; новый шаблон не заводится);
- упоминание внешних отчётов: маршрут и канон одинаковы для `.erf`.

Текст по нормам канона: happy path, класс явления (epf/erf), без истории
сессии; кодовые фрагменты разметки допустимы, минимально.

## Демо-путь

Скэфолд в песочнице разворачивает AGENTS каталога `src/epf` с каноном и
маршрутом; агент, правящий внешнюю обработку, видит маршрут и контроль
собранного без открытия скиллов.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: греп `ChildItems` в
   `skills/1c-project-layout/templates/agents/src_epf.md`. Ожидание:
   канон разметки с порядком секций. На базе пусто, падает.
2. Артефакт: греп `epf-load` в том же файле. Ожидание: маршрут сборки/
   разбора со ссылкой на 1c-ibcmd-delivery. На базе пусто, падает.
3. Артефакт: греп `epf-binary` — ссылка на reference в src_epf.md.
   На базе пусто, падает.
4. Артефакт: греп «только через Unica» в `src_epf.md` и `src_erf.md` —
   пусто (противоречащая канону строка удалена из обоих). На базе
   возвращает строку, падает.
5. Инвариант: тесты скэфолда 1c-project-layout зелёные — оба шаблона
   разворачиваются без повреждений; `lint_skill_frontmatter` 15/15.
