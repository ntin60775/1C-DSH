# Т4 «Семантика доверия в 1c-db-data»

Оценка: ~20 мин. Блокеры: Т1 (кросс-ссылка ведёт в раздел «каталог
окон платформы», который создаёт Т1).

## Зачем

Раздел «Обновление обработки (epf): ручные шаги оператора на каждой
базе» в `1c-db-data` знает диалог безопасности по факту замены файла
(«любой новый контент — обновление донора») и немоту канала, но не
называет семантику «каждый новый бинарник» и симптом 180-с зависания
execute-каналов, который на живом стенде выглядит как флап базы. Оба
факта собраны в сессии 08.11 (project-bp) и живут только в её памяти.
Спека:
[docs/plans/external-epf-loop.md](../../docs/plans/external-epf-loop.md).

## Что делается

Правка `skills/1c-db-data/SKILL.md`, раздел «Обновление обработки (epf)»:

- семантика доверия уточняется: диалог «Предупреждение безопасности:
  Разрешить открывать данный файл?» привязан к контенту — поднимается
  на каждый новый бинарник epf, пересборка = новый диалог; путь вторичен;
- симптом недоставленного подтверждения: execute-каналы висят до 180 с
  — выглядит как флап стенда, диагностический признак — диалог не отвечен;
- машинный путь подтверждения: клик по Button0 тест-клиентом (реестр
  операций — `1c-testpilot`), ручной — оператор на видимом дисплее;
- кросс-ссылка на скилл `1c-testpilot` (каталог окон платформы).

Тексты по нормам канона: happy path, без истории сессии.

## Демо-путь

Агент при «флапе» execute-каналов после пересборки epf находит в
разделе причину (диалог не отвечен) и путь подтверждения, вместо
диагностики сети.

## Критерии приёмки (падают на базовом коммите)

1. Артефакт: греп «каждый новый бинарник» в `skills/1c-db-data/SKILL.md`.
   Ожидание: уточнённая семантика доверия. На базе пусто, падает.
2. Артефакт: греп «180 с» в разделе обновления обработки. Ожидание:
   симптом зависания execute-каналов. На базе пусто, падает.
3. Артефакт: греп «1c-testpilot» по диапазону раздела «Обновление
   обработки (epf)» (от заголовка раздела до следующего `##`).
   Ожидание: кросс-ссылка. Вне раздела «1c-testpilot» в файле уже
   встречается — греп по файлу целиком на базе не упадёт, проверять
   по диапазону.
4. Инвариант: `lint_skill_frontmatter` без замечаний.
